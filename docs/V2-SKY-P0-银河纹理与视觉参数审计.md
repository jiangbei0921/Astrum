## 1. 结论摘要

| 结论 | 判定 |
|---|---|
| P0-1 纹理来源、RGB565 解码、字节序、通道顺序 | **正确** |
| P0-1 赤经/赤纬方向、RA 0/24 环绕、银极、银道面、时间/地点依赖 | **正确** |
| P0-1 鱼眼逆投影与正向投影几何 | **正确**（369 个采样点误差 0 px） |
| **P0-1 天空纹理方位索引与栅格取样方位基准** | **存在问题：相差 180°**（根因已定位到 1 行） |
| P0-2 最近邻/双线性采样 | **有问题但非主因**（差值仅 1.0 灰阶） |
| **P0-2 亮度/对比度/混合链** | **存在问题**：均匀 alpha 0.55 抬高地平线、压低高光，暗尘埃带被压缩 |

**一句话根因**：`computeRaster` 用 `u = 0.5 + az/2π` 取样天空纹理，而天空纹理是按 `x ↔ az/360` 构建的，两者相差 180° 方位角。于是**整幅银河背景被绕天顶旋转了 180°**：真实位于低空的亮带被画到了高空（正是用户看到的「上半部分灰褐色云雾」），银心亮区被移出应有位置。再叠加均匀 alpha 0.55 的合成，结构层次被进一步压平。

## 2. 真实渲染调用链（逐层核实）

```
app.js drawSky(canvas, p)
 └─ SkyVM.build(jd, lat, lon, {width,height,yaw,pitch,fov,layers,...})
      ├─ A.altAz(ra, dec, jd, lat, lon)          // 恒星/银河带/DSO 的地平坐标
      └─ projector(): fwd/right/up 基向量 + 等距鱼眼 proj(az, alt)
 └─ SkyRender.draw(canvas, p, vm) → paint()
      ├─ skyBackground(g, vm)                    // 静态 4 段深蓝渐变（夜空底色）
      ├─ if layers.milkyWay:
      │    SkyBackground.draw(g, vm)
      │      ├─ load(): atob → Uint8Array → RGB565(512×256)
      │      ├─ ensureSky(jd, lat, lon):
      │      │    for y in 128, x in 256:
      │      │       alt = 90 - (y+0.5)/128*180
      │      │       az  = (x+0.5)/256*360        // ← 天空纹理 x ↔ az/360
      │      │       eq  = SkyVM.altAzToEq(alt, az, jd, lat, lon)
      │      │       rgb = sampleTex(eq.ra, eq.dec)   // 最近邻
      │      ├─ ensureRaster(vm):
      │      │    for py in 160, px in 160:
      │      │       dir = fwd*cos(rho·half) + (right·rx + up·ry)*sin(rho·half)
      │      │       alt = asin(vz), az = atan2(vx, vy)
      │      │       u = (0.5 + az/2π) % 1       // ← 偏差 180°
      │      │       v = 0.5 - alt/π
      │      │       rgb = sampleSky(u, v)       // 最近邻
      │      └─ drawImage(raster, cx-rmax, cy-rmax, 2rmax, 2rmax), globalAlpha=0.55
      ├─ (!realBg) milkyWay() + starField()      // fallback
      ├─ stars / deepSky / constellations / bodies / horizon / labels
      └─ return {hits, bodies, meta}
```

命中区仍由 `SkyRender` 唯一创建，背景不参与 hit；`stars` 图层归属未迁移。

## 3. P0-1 纹理来源与解码审计

### 3.1 运行时确实使用 NASA 纹理，无 fallback

| 检查 | 实测 |
|---|---|
| `SkyBackground.ready()` | `true`，`mode: "auto"`，`lastError: null` |
| `stats().texture` | `{w:512, h:256, bytes:262144}` |
| `stats().fallbacks` | `0`（浏览器运行、性能补测、答案卡直测均为 0） |
| `draws` | 启动后 2 次（主界面 + 预热） |
| `source` 元数据 | `milkyway_2020_4k_print.jpg`、`page: svs.gsfc.nasa.gov/4851`、`license: public domain`、`sha256` 齐全 |
| 源图 | 1024×512，71,247 B，SHA-256 `1ebe9580…ee2df0` |

结论：**使用真实资源，未降级**。

### 3.2 RGB565 字节序与通道顺序（与 Python 直读源图交叉验证）

| 方向 | 运行时解码 RGB（512×256，最近邻，单像素窗口） | Python 直读 512×256（13×13 窗口） |
|---|---|---|
| 银心 GC | `[179, 144, 121]` | `[145.3, 113.7, 92.4]` |
| 银北极 NGP | `[8, 9, 8]` | `[11.1, 11.1, 11.1]` |
| 全图通道均值 | `[35.1, 35.2, 31.6]` | `[37.8, 36.4, 34.4]` |

- 两者通道排序一致（R > G > B，银心为暖色），若发生 R/B 交换会得到 `[121,144,179]`，未出现；
- 若高低字节颠倒，解码值会完全离散，NGP 不可能稳定落在 8–11；
- 亮度差异来自统计窗口不同（运行时是单像素邻域，Python 是 13×13 平均），不是解码错误。

结论：**RGB565 little-endian + R 高位，正确**。

### 3.3 方向与坐标审计（全部用数值验证）

| 检查项 | 证据 | 判定 |
|---|---|---|

| Dec 方向 | 最亮区 Dec −28.48°，接近银心 −28.94° | 正确 |
| 银道面 | 沿 b=0 平均亮度 **72.51**，b=±40° 平均 **18.47**，比值 **3.93** | 正确 |
| 银心 / 反银心 | 银心 148.06 vs 反银心 55.24（比值 2.68）；全局最亮区距银心 **4.72°** | 正确 |
| 银北极 / 银南极 | NGP 8.31、SGP 9.12，均远暗于银道面 | 正确 |
| RA 0/24 环绕 | `eqToUv` 取模；离线下 R2.9 通过；最亮区跨越 u 边界无断裂 | 正确 |
| 不同时间 | 同一地点：11-05 21:00 银心 alt **−17.9°**（在地平线下）；06-01 21:30 银心 alt **+2.9°**（刚升起） | 正确 |

> 结论：**坐标链本身没有错**。背景与恒星在几何上完全对齐，问题不在 `altAzToEq`、`eqToUv`、`galToEq`、`A.altAz` 或鱼眼投影。

### 3.4 已定位缺陷：天空纹理方位索引与栅格取样基准相差 180°

| 环节 | 代码 | 方位映射 |
|---|---|---|
| 天空纹理构建 | `buildSky`：`az = (x + 0.5) / SKY_W * 360` | `x = az/360 · 256`（az 自北向东，0°=北） |
| 天空纹理取样 | `sampleSky(u,v)`：`x = floor(u * SKY_W)` | `u = az/360` |
| 栅格取样 | `computeRaster`：`u = (0.5 + az/(2π)) % 1` | `u = 0.5 + az/360` → **多出 0.5 圈** |

**直接实测（2026-06-01 21:30 北京，银心 az=132.4°、alt=+2.9°）**：

| 取值方式 | 读出亮度 | 实际读到的是哪个方位 |
|---|---:|---|
| 按 `buildSky` 索引（az/360） | **96.7** | az = 132.4°（正确位置） |
| 按 `computeRaster` 索引（0.5+az/360） | **46.3** | az = **312.4°**（偏 180°） |

**以银心为中心的 70° 视场，整盘对比**：

| 指标 | 值 |
|---|---:|
| 银心像素当前亮度 | 46.3 |
| 银心像素修正后亮度 | **96.7** |
| 整盘平均绝对差 | **32.27 灰阶** |
| 整盘最大绝对差 | **185.7 灰阶** |

### 3.5 这如何解释用户看到的现象

默认视角（南向、fov 145°、pitch 32°，2026-11-05 21:00 北京）：

| 指标 | 当前（有缺陷） | 修正后 |
|---|---:|---:|
| 地平线以上平均亮度 | 36.22 | 27.12 |
| 最亮像素所在高度角 | **+40.6°**（高空） | **+7.9°**（低空） |
| 最亮像素所在方位 | 97.3°（东） | 253.8°（西南） |
| 高空（>45°）区「亮像素」占比 | **58.9%** | 28.1% |

- 真实银河亮带此时应在低空西南方向（银心在地平线下、亮带贴地平线），但当前被画到**高空东侧**，形成「天空上半部分灰褐色云雾」；
- 银心附近的亮度集中被搬到不相关方位，因此「银心缺少明显亮度集中」；
- 由于 180° 绕天顶旋转仍是等距变换，亮带形状还在，所以像「云层」而不是完全乱码——与用户描述完全吻合。

**这是 P0-1 唯一的功能性缺陷，根因是一行取样基准不一致，不涉及任何天文算法。**

## 5. P0-2 亮度、对比度与混合模式审计

### 5.1 各级亮度统计（实测）

| 层级 | mean | p10 | p50 | p90 | p99 | max |
|---|---:|---:|---:|---:|---:|---:|
| 运行时纹理（512×256，抽样 1/4） | **33.97** | 9.3 | 26 | 67 | 118.7 | 230.7 |
| 天空纹理对应可见区 | 34.51（银道面）/ 11.35（面外） | — | — | — | — | — |
| 屏幕栅格（160×160，圆内 20,108 texel） | 29.89 | 9.3 | 24.7 | 59 | 90 | 125.3 |

关键事实：

- 纹理 **36% 的像素亮度 < 20，54% < 30** —— 大面积接近黑，但并非纯黑（有微弱弥漫底噪）。
- 纹理通道均值 `R 35.1 / G 35.2 / B 31.6`，银心 `[179,144,121]` —— **偏暖/偏褐**，这是 NASA print 版本的固有色，不是解码错误。

### 5.2 合成链（唯一一次 alpha，无重复叠加）

```
最终 = 0.55 × 背景栅格 + 0.45 × 夜空渐变
渐变：顶部 (3,5,10)=6.0 → 0.45 处 (7,16,32) → 0.72 处 (18,32,54) → 底部 (26,42,66)=44.7
```

| 指标 | 值 | 含义 |
|---|---:|---|
| 顶部合成后平均亮度 | **19.1** | 全天空中位亮度被抬到 19，天空不再是深黑 |
| 顶部合成后 p10 | 7.8 | 暗尘埃带最低只到 8 |
| 顶部合成后 p90 | 35.2 | 亮带主体只有 35 |
| 合成后对比跨度（p90−p10） | **27.4** | 结构层次弱 |
| 合成后理论上限（栅格 max 125.3） | **71.6** | 即使纹理最亮 230，画面上也只到 ~72 |
| 底部（近地平线）合成后平均 | 36.6 | 蓝灰渐变进一步稀释暖色带 |

### 5.3 混合模式

| 项 | 现状 | 影响 |
|---|---|---|
| 混合模式 | `source-over` + `globalAlpha 0.55` | 相当于「整幅背景乘 0.55」叠加，无高光增益 |
| 是否会遮盖恒星 | 否，恒星/DSO/星座/行星均在背景之后绘制 | 正确 |
| 是否让整片天空变灰 | **是**，平均抬到 19、p90 仅 35 | 问题 |
| 暗尘埃带是否保留 | 弱，最低只到 8，且被 RGB565 暗部量化压成 1–2 档 | 问题 |
| 亮区是否有层次 | 否，上限被 alpha 与渐变封在 ~72 | 问题 |
| 是否干扰星座线/标签/DSO | 否，绘制顺序在后 | 正确 |

### 5.4 暗部量化

RGB565：R/B 5 bit（步长 8.2 灰阶）、G 6 bit（步长 4.05 灰阶）。纹理亮度 <20 的 36% 像素只落在 2–3 个离散档位，没有抖动（dithering），再经 sRGB 下 55% alpha 混合，尘埃带的细节层次基本被抹平。

## 6. 问题清单与根因

| 编号 | 问题 | 根因 | 证据 | 严重度 |
|---|---|---|---|---|
| P0-1-A | 背景绕天顶旋转 180°，亮带位置错 | `computeRaster` 的 `u = 0.5 + az/2π` 与 `buildSky` 的 `x = az/360` 基准不一致 | 银心像素 46.3 vs 96.7；整盘平均差 32.3、最大 185.7；默认视角最亮像素从 +7.9° 被移到 +40.6° | **严重** |
| P0-2-A | 全天空泛灰褐、缺乏层次 | 均匀 alpha 0.55 + 无色调映射；纹理中位 26、36% <20 | 合成后平均 19.1、p90 仅 35.2、跨度 27.4 | **严重** |
| P0-2-B | 高光被封顶，银心不亮 | alpha 0.55 线性缩放，无高光增益 | 栅格 max 125.3 → 画面 71.6 | 中 |
| P0-2-C | 近地平线暖色被蓝灰渐变稀释 | 渐变底部亮度 44.7，占比 45% | 近地平线合成均值 36.6 | 中 |
| P0-1-B | 两级最近邻降采样，结构偏软 | 512→256→160 均为最近邻 | 双线性仅改善 1.0 灰阶，故列为次要 | 低 |
| P0-1-C | 天空纹理 1.406°/px 是结构上限 | 256×128 alt/az 网格 | 银道面/面外比值 3.04，细节在 1.4° 以下被丢弃 | 低（不在本次范围） |

> 未发现的问题（明确排除）：坐标算法、恒星目录、星座线、DSO 数据、行星渲染、hit 检测、缓存键语义、去抖逻辑。

## 7. 最小修改方案（待批准，尚未实施）

### 7.1 修改 1：修正方位基准（1 行，`core/sky-background.js`）

```js
// 现状（computeRaster 内）
var u = (0.5 + az / (2 * Math.PI)) % 1, vv = 0.5 - alt / Math.PI;

// 修正
var u = (az / (2 * Math.PI)) % 1, vv = 0.5 - alt / Math.PI;
if (u < 0) u += 1;   // az ∈ (-π, π]，直接取模可能为负
```

- 只改取样基准，不改 `buildSky`、不改 `sampleSky`、不改任何坐标算法；
- 修改后 `x ↔ az/360 ↔ u` 三者一致；
- 性能零变化（仍是两次取模与一次 floor）。

### 7.2 修改 2：纹理色调映射 + alpha（`core/sky-background.js`）

在 `buildSky` 采样得到 RGB 后，增加一张 256 项 LUT（构建一次，全局复用），按**亮度保比**方式压暗底噪、拉开高光，不改变色相比例：

```
Y  = 0.299R + 0.587G + 0.114B
Y' = 255 × ((max(0, Y − F) / (255 − F))^G)
k  = Y > 0 ? Y'/Y : 0
R' = min(255, R·k), G' = min(255, G·k), B' = min(255, B·k)
```

候选参数（由实测分位数校准）：

| 参数组 | 纹理 p50(26) → | p90(67) → | p99(118.7) → | max(230.7) → | 合成(α=0.8, 顶部) 底噪/中位/高光 |
|---|---:|---:|---:|---:|---|
| 现状（无 LUT，α0.55） | 26 | 67 | 118.7 | 230.7 | 19.1 / 24.7 / 51.7 |
| **F=10, G=1.45, α=0.80** | 4.9 | 30.8 | 78.5 | 219 | **3.2 / 5.1 / ~66** |
| F=8, G=1.30, α=0.80 | 8.5 | 39.6 | 89.9 | 223 | 6.0 / 7.9 / ~73 |
| F=12, G=1.60, α=0.85 | 2.7 | 23.6 | 68.4 | 215 | 3.2 / 3.4 / ~59 |

推荐起点 **F=10、G=1.45、alpha 0.80**：底噪从 19 降到约 3，高光从 52 提到约 66，中位保持在低位——是「拉开对比」而不是「整体提亮」，平均值不会上升。

### 7.3 明确不做的事

- 不改 `sky-renderer.js` 的夜空渐变（保持底色与恒星对比的既有语义；渐变仍负责近地平线的空气感）；
- 不改混合模式（保持 `source-over`，避免 `lighter` 造成整片发光）；
- 不加双线性（收益仅 1 灰阶，不值得引入采样成本）；
- 不改纹理分辨率、不换数据源、不动 `sky-viewmodel.js` / `astro.js` / `app.js`。

### 7.4 预计影响文件

| 文件 | 修改 | 行数量级 |
|---|---|---|
| `core/sky-background.js` | `computeRaster` 的 u 基准；`buildSky` 增加 LUT 与色调映射；`draw` 的 alpha；版本号 1.0.0 → 1.1.0 | 约 15–20 行 |
| `core/sky-renderer.js` | **不改**（背景仍通过 `SkyBackground.draw` 接入） | 0 |
| 其他文件 | **不改** | 0 |

### 7.5 回退方式

- 参数集中在 `core/sky-background.js` 顶部常量（`ALPHA`、`TONE_FLOOR`、`TONE_GAMMA`、`TONE_ENABLE`）；
- 保留基线值注释，改回常量即可完整回退；
- 方位修正单独一行，可独立回退。

## 8. 风险分析

| 风险 | 影响 | 缓解 |
|---|---|---|
