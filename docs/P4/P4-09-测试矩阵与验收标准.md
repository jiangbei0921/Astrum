# P4-09 测试矩阵与验收标准

## 1. 测试原则

1. 新增测试文件，不复用旧文件降低断言。
2. 旧测试预期值不得修改；如因契约冲突必须调整语义，单独列出并需用户批准。
3. 所有测试必须能通过 `node tools/<file>.js` 独立运行，末尾输出 `RESULT n/n`。
4. 浏览器刷新恢复必须用真实 Chrome 跑，不以 Node 模拟代替。
5. 未执行的测试不得标记为通过。

## 2. 现有基线

- `selftest.js` 153/156，3 项既有环境失败。

## 4. 详细矩阵

### 4.1 IndexedDB

| # | 用例 | 期望 |
| --- | --- | --- |
| 1 | 首次初始化 | 建 `tasks/events/checkpoints/meta` |
| 2 | 重复初始化 | 不重复建 store，版本不变 |
| 3 | v1→v2 升级 | 旧任务记录保留 |
| 4 | 升级失败注入 | 旧库仍可读，报 `DB_UPGRADE_FAILED` |
| 5 | 事务成功 | 任务+事件+检查点同时可见 |
| 6 | 事务失败 | 三者均不可见，内存状态不变 |
| 7 | 读取不存在数据 | 返回 null，不抛错 |
| 8 | 写入异常 | 返回错误码，不静默 |
| 9 | 配额不足 | `QUOTA_EXCEEDED`，不删除数据 |
| 10 | 关闭后读写 | 自动重连或明确报错 |

### 4.2 TaskState

| # | 用例 | 期望 |
| --- | --- | --- |
| 1 | 保存/读取 | 往返一致 |
| 2 | 更新 | `revision` 递增 |

| 4 | 删除 | 级联删除事件/检查点 |
| 5 | 跨用户读取 | null + 审计 |
| 6 | 跨项目读取 | null |
| 7 | 版本不兼容 | `SCHEMA_INCOMPATIBLE` |
| 8 | 损坏状态 | `stale`，恢复拒绝 |
| 9 | 多任务隔离 | 互不覆盖 |
| 10 | 陈旧写 | `STALE_WRITE` |

## 5. 验收标准

### 5.1 阶段 B 每批

- B1 存储：`p4-store-test` 全绿后才进入 B2。
- B2 TaskState：保存/读取/删除/隔离全绿。
- B3 Event：事务一致性全绿。
- B4 Checkpoint：完整性拒绝路径全绿。
- B5 Recovery：三策略与 17 项校验全绿。
- B6 故障：配额/多标签页/损坏全绿。
- B7 UI：`p4-ui-test` 与浏览器用例通过。
- B8 全量：既有套件全绿 + 新增套件全绿。

### 5.2 最终验收（对应任务书 §13）

1. TaskState 可靠持久化。
2. Event 可靠持久化。
3. Checkpoint 正确生成与读取。
4. 恢复前重新验证身份/权限。
5. 三策略与契约一致。
6. 恢复最多一次（或用户批准的分档）。
7. 已完成的可复用步骤不重复执行。
8. 恢复失败保留原因。
9. 数据库升级可靠。
10. 多用户/多项目隔离有效。
11. 无 Event Bus。
12. 无 Optimizer 自改写。
13. 无新依赖。
14. 不改 P0—P3 冻结契约（除用户批准项）。
15. 原有测试全部通过。
16. 新增测试全部通过。
17. Chrome 刷新恢复实测通过。
18. “不后台执行”文案明确。
19. 无已知严重数据丢失或越权问题。
20. 新模块接口清晰。
