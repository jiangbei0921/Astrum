# P4-08 模块映射与接口设计

## 1. 复用优先原则

P4 不新建第二套任务系统。现有模块承担主职责，P4 只补以下能力：

- 持久化存储版本与事务；
- 事件/检查点派生索引；
- 恢复前校验与三策略执行；
- 保留/清理与故障分类；
- UI 可恢复任务信息增强。

## 2. 现有模块映射

| 能力 | 现有模块 | P4 动作 |
| --- | --- | --- |
| TaskState 契约 | `core/task.js` | 仅必要时新增可选字段；不改 `schemaVersion` |
| 任务存储 | `core/task-store.js` | 升级 v2、加事务/事件/检查点/配额/revision |
| 消息存储 | `core/store.js` | 不改 |
| 课题与归属 | `core/research-store.js` | 复用 `getProject` |
| 身份与权限 | `core/security.js` + `core/profile.js` | 复用，不新增身份源 |
| 调度与执行 | `core/orchestrator.js` | 增加 critical 步后保存钩子，不改调度语义 |
| 控制与恢复 | `core/control.js` | 扩展 `resume` 校验与三策略；`pause` 写检查点 |
| Skill 发布 | `core/skill-store.js` | 恢复前查询 `getPublished` |
| Tool 声明 | `core/registry.js` | 复用 `idempotent/ttlMs/retry` |
| 审计 | `core/audit-log.js` | 增加 pause/resume/prune 记录 |
| UI | `core/app.js` | 增强可恢复卡片，不重做工作台 |
| 桥接 | `core/control-bridge.js` | 透传恢复结果与错误原因 |

## 3. 建议新增职责（不机械建文件）

| 职责 | 建议放置 |
| --- | --- |
| Recovery Validator（17 项校验） | `core/recovery.js`（新，纯函数） |
| Recovery Coordinator（策略执行） | `core/control.js` 内部或 `core/recovery.js` |
| Integrity Checker | `core/recovery.js` + `core/task.js` |
| Retention Manager | `core/task-store.js` 内部 |
| Migration Manager | `core/task-store.js` 内部 |

若新增文件超过 2 个，需先说明理由。建议仅新增 `core/recovery.js`，其余内聚到现有模块。

## 4. 接口契约

### 4.1 AstroTaskStore

```js
create({projectId, ownerProfileId}) -> store
store.init()
store.save(state) -> Promise<{id, revision}>
store.get(id) -> Promise<TaskState|null>
store.getRecord(id) -> Promise<Record|null>
store.list({limit}) -> Promise<TaskSummary[]>
store.listByProject(pid, {limit, raw}) -> Promise<TaskSummary[]>
store.listResumable({limit}) -> Promise<TaskSummary[]>
store.loadLatestCheckpoint(taskId) -> Promise<Checkpoint|null>
store.listEvents(taskId, {afterSeq, limit}) -> Promise<EventRecord[]>
store.remove(id) -> Promise<boolean>
store.pruneCheckpoints(taskId, keep) -> Promise<number>
store.getHealth() -> {backend, dbVersion, lastError}
store.backend() / store.ownerProfileId() / store.dbName()
```

错误码：`PERSIST_TX_FAILED`、`QUOTA_EXCEEDED`、`STALE_WRITE`、`DB_UPGRADE_FAILED`、`CHECKPOINT_INVALID`、`PROFILE_MISMATCH`、`PROJECT_MISMATCH`。

### 4.2 AstroRecovery（建议新模块）

```js
Recovery.validate({ state, record, principal, project, registry, skillLookup, limit })
  -> { ok, errors: [{code, detail}] }

Recovery.plan({ state, checkpoint, registry })
  -> { steps: [{ id, strategy: 'reuse'|'rerun'|'validate_then_reuse'|'block', reason }],
       reusable: string[], rerun: string[], blocked: string[] }

Recovery.apply({ state, checkpoint, registry, now })
  -> { state, applied: {...} }   // 纯内存变更，不写盘
```

约束：不读写 IndexedDB，不调 LLM，不执行工具。

### 4.3 AstroControl.resume

返回结构扩展（向后兼容）：

```js
{
  state, answer, runner, delivery, verdict, resumable,
  resumed: true,
  recovery: { attempt, limit, strategies: {reuse:[], rerun:[], blocked:[]} },
  error: string|null
}
```

### 4.4 AstroControl.pause

```js
pause(taskId, {store, principal})
  -> {state, verdict:'PAUSED'|'VIEW_ONLY'|'DENIED', paused, already?, error?}
```

P4 追加：pause 成功后写检查点（与状态同一保存流程）。

## 5. 调用链（恢复）

```text
app.offerResumeTask
  -> TaskStore.listResumable
  -> 用户点击
  -> ControlBridge.resume
  -> Control.resume
       -> TaskStore.getRecord/get
       -> TaskStore.loadLatestCheckpoint
       -> Recovery.validate (17 项)
       -> Recovery.plan/apply
       -> TaskStore.save (事务)
       -> Orchestrator.runPlan
       -> PROGRESS/JUDGE/COMPOSE
  -> renderAnswer
```

## 6. 依赖方向

```text
app.js -> control-bridge -> control -> { task, task-store, orchestrator, recovery }
orchestrator -> { task, registry, skill-* }
task-store -> { task, profile, audit-log }
recovery -> { task, registry, security }
```

禁止：`task-store` 反向依赖 `control`；`recovery` 直接开数据库；UI 直接调用 `recovery`。

## 7. 兼容约束

1. `schemaVersion` 保持 1。
2. 新增 store 不影响旧版本读取。
3. `listResumable/loadLatestCheckpoint/listEvents` 均为新增接口，不改变旧方法签名。
4. 旧任务（无 revision、无派生索引）可读、可恢复，但按“保守策略”处理：
   - 无检查点 → 不自动恢复；
   - 无 `idempotent` 声明 → 视为非幂等。
