## 3. 关键行为验证

1. **持久化**：任务、事件、检查点、meta 同事务写入；事务失败三者均不可见。
2. **升级**：v1 库只新增 store，旧记录保留；升级失败降级 localStorage 并报 `DB_UPGRADE_FAILED`。
3. **事件**：内嵌事件为权威，派生索引可重建；历史 seq 内容变化报 `EVENT_CONFLICT`。
4. **检查点**：`snapshot` 可复算 `stateHash`；完成/待办节点、依赖、计划版本、Tool/Skill 均校验；单任务保留 20 个。
5. **恢复**：17 项校验失败返回具体错误码；幂等步骤复用、非幂等重跑、TTL 过期重跑；恢复次数 ≤1。
6. **并发**：两个标签页同 revision 写入，后写方 `STALE_WRITE`。
7. **UI**：刷新后出现用户主动的“继续任务”入口；失败原因按错误码展示。
8. **真实浏览器**：刷新后恢复同一 `taskId`，幂等步骤 `attempt` 保持 0，待办步骤执行，最终进入 PARTIAL/DONE。

## 4. 兼容与偏差说明

- **无检查点历史任务**：仍允许恢复（P4-08 §7 与 `v1-1-e2e` E5.2 冲突时优先保持既有验收），有检查点则必须通过完整性校验。
- **未知幂等声明**：若成功步骤 `inputHash` 未变且存在 `result/outputHash`，保守复用而非阻断，避免重放未知副作用。
- **`save` 返回值**：保持旧接口返回任务 id（未改为 `{id, revision}`），兼容 `v1c-test C2.1`；revision 通过 `getRecord` 读取。
- **检查点自动清理**：保存后自动保留最近 20 个派生记录；`pruneCheckpoints` 仍可显式收紧。
- 未修改 `docs/architecture/15`，未新增依赖、后端、Service Worker、Event Bus 或 Optimizer。
