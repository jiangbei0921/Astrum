| 编号 | 风险 | 等级 | 触发条件 | 影响 | 缓解 |
| --- | --- | --- | --- | --- | --- |
| R-1 | 恢复次数上限与契约冲突 | 高 | L3/L4 任务多次刷新 | 重复执行副作用 | 用户裁定后统一实现（D-1） |

| R-4 | 数据库升级失败损坏数据 | 高 | 升级中断/多标签页 | 任务不可读 | 只增 store、保留 v1、失败回退 |
| R-5 | 多标签页并发写 | 高 | 两个页面同时恢复 | 状态互相覆盖 | `revision` + `STALE_WRITE` |
| R-6 | 配额不足静默失败 | 高 | 历史任务过多 | 进度丢失无提示 | `QUOTA_EXCEEDED` + 提示清理 |

| R-10 | 事件索引越界成为第二状态源 | 中 | 误用 events 重建状态 | 架构漂移 | 明确派生定位、无写入口 |
| R-11 | TaskState 被 UI 回写 | 中 | 直接暴露 state | 双状态源 | UI 只读视图 |
| R-12 | 浏览器关闭被误表述为后台执行 | 低 | 文案不当 | 用户误解 | 固定文案 |
| R-13 | 检查点裁剪误删最终检查点 | 中 | 清理逻辑错误 | 无法恢复 | 保留最终 + 事务 |
| R-14 | 删除任务未级联 | 中 | 只删 tasks | 孤儿数据/隐私残留 | 同事务级联 |
| R-15 | 恢复耗时过长 | 低 | 检索重跑 | 用户等待 | 进度事件 + 可取消 |

## 2. 需用户确认的事项

### D-1 恢复次数上限（阻塞阶段 B）

- 契约：`15` §4.2 同一任务 ≤1。
- 现状：P3 `BUDGET_LIMITS` 为 L2=1、L3/L4=3。
- 选项：
  - **A（推荐）** 全局统一 ≤1：修改 `BUDGET_LIMITS.recoveries` 为 L1=0、L2/L3/L4=1。
  - B 保留分档：需同步修订 `15` §4.2，并接受 L3/L4 多次恢复风险。
- 未确认前不得进入阶段 B。

### D-2 非幂等步骤恢复语义（阻塞阶段 B）

- 契约：检索类必须 rerun；P3 现有实现会复用 `ok` 结果。
- 选项：
  - **A（推荐）** 按契约：幂等 reuse、非幂等 rerun、TTL 半幂等 validate_then_reuse；同步修正 `v1-1-e2e` E5.3 的语义断言。
  - B 保持 P3 行为：所有 `ok + inputHash 未变` 复用；需修订 `15` 并接受旧检索结果风险。
- 未确认前不得进入阶段 B。

### D-3 Event 存储形态

- 选项：
  - **A（推荐）** 内嵌为权威 + 新增 `events` 派生索引，同事务写入，不引入总线。
  - B 仅内嵌，不新增 store；事件查询能力受限，但改动最小。
- 不影响安全，只影响查询与审计能力。

### D-4 Event ID

- 选项：
  - **A（推荐）** 使用 `taskId:seq` 作为稳定 ID，不新增必填字段。
  - B 新增 `eventId` 字段，需要兼容旧事件。

### D-5 数据保留默认值
