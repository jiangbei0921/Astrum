# P4-06 身份隔离与数据安全设计

## 1. 现有安全边界（核验结论）

| 边界 | 实现 | 证据 |
| --- | --- | --- |
| Principal 生成 | `Security.makePrincipal` / `Profile.currentId()` | `core/security.js`、`core/profile.js` |
| 能力矩阵 | `CAPABILITIES` + `ROLE_POLICY` + `USER_POLICY` | `core/security.js` |
| 资源 owner 校验 | `authorize` 比较 `ownerProfileId` | `p0-security-test` P0-AUTH-007 |
| 会话绑定 | `ensureSession` 比较 profile/session | `p0-security-test` P0-ASYNC-001 |
| 任务库隔离 | 按 Profile 命名空间分库 | `core/task-store.js:31-39` |
| 项目隔离 | `projectId` 字段 + `listByProject` | `core/task-store.js:344-374` |
| 审计 | `AuditLog.record` | `core/audit-log.js` |

## 2. P4 新增存储的强制规则

1. **身份只来自可信上下文**：`ownerProfileId` 由 `Profile.currentId()` 或 `principal.profileId` 生成；调用方传入的 owner 在浏览器必须被忽略。
2. **每条记录都带作用域**：`tasks/events/checkpoints` 均写 `ownerProfileId` 与 `projectId`。
3. **读取双校验**：先校验 owner，再校验 project（如请求带 projectId）。
4. **禁止按 taskId 直接读**：必须先 `getRecord` 并 `owned()`，再读状态/事件/检查点。
5. **UI 不接触原始存储**：UI 只调用 `AstroTaskStore`/`AstroControl`，不直接开 IndexedDB。
6. **恢复重新授权**：每次 `resume` 重新执行 17 项校验，不沿用历史决定。
7. **审计不可省**：拒绝、恢复、清理均写 `AuditLog`。

## 3. 会话作用域

- 任务记录新增元数据 `sessionScope`（可选，仅存储层）：保存时的 `principal.sessionId` 或 `Security` 会话标识。
- 恢复时若当前会话与记录会话不同：
  - 同 profile 且无并发写 → 允许，但记 `SESSION_CHANGED_ACCEPTED`；
  - 不同 profile → 拒绝 `PROFILE_MISMATCH`。
- 会话标识属于敏感元数据，不写入 `TaskState`，不展示给用户。

## 4. 敏感信息审查

禁止持久化：

- API Key、Token、Cookie、密码；
- 完整 Authorization 头；
- 临时 OAuth 凭据；
- 用户附件原始二进制（现有附件走独立通道，P4 不新增保存）。

允许持久化：问题文本、计划、步骤参数（不含凭据）、证据引用、摘要、哈希、事件 payload（白名单内）。

恢复需要凭据时，走现有设置/Provider 重新授权，不从检查点恢复。

## 5. 越权路径与防护

| 攻击/误用 | 防护 | 测试 |
| --- | --- | --- |
| 传别人 profileId | 浏览器忽略传参，使用 `Profile.currentId()` | 双 Profile |
| 猜 taskId | `owned()` 校验，失败返回 null 并审计 | 跨 Profile 读取 |
| 直接改 IndexedDB | 无法防本机用户；但读取仍校验 owner，且 `stateHash` 可发现篡改 | 篡改样本 |
| 用其他项目 principal 恢复 | projectId 校验 | `p1-resume-test` P1-RSM-015 |
| 绕过 Skill 审批执行 | 恢复前校验 published 版本 | Skill 撤销用例 |
| UI 回写状态 | 不给 UI 存储句柄；只传只读视图 | UI 测试 |

## 6. 数据删除边界

- 用户主动删除任务：需确认；级联删除任务、事件索引、检查点。
- 删除失败：保留记录并报错，不允许“删一半”。
- 不提供批量清空全部历史的默认按钮。
- 不自动删除失败任务，除非用户配置保留期并确认。

## 7. 审计事件

| 动作 | decision | reason |
| --- | --- | --- |
| task.read | allow/deny | ALLOW / PROFILE_MISMATCH |
| task.resume | allow/deny | ALLOW / CHECKPOINT_INVALID / RECOVERY_LIMIT ... |
| task.pause | allow/deny | ALLOW |
| task.delete | allow/deny | ALLOW / PROFILE_MISMATCH |
| task.prune | allow/deny | ALLOW / RETENTION_DENIED |

## 8. 结论

现有 P0 安全机制足以承载 P4；P4 只需把同样的 owner/project 校验扩展到新增 store 与恢复流程，不新建身份源、不降低校验强度。
