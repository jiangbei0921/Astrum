# P4-07 数据库版本迁移与数据生命周期设计

## 1. 当前版本

| 数据库 | 版本 | 位置 |
| --- | --- | --- |
| `astrum.tasks.v1`（按 Profile 命名空间） | 1 | `core/task-store.js:18-19` |
| `astrum.tasks.quarantine.v1` | 1 | `core/task-store.js:24-25` |
| `astrum`（消息历史） | 1 | `core/store.js:21-22` |
| 审计库 | 1 | `core/audit-log.js` |
| 科研课题库 | 见 `research-store.js` | — |
| Skill 库 | 见 `skill-store.js` | — |

P4 只升级 **任务库**，其他库不动。

## 2. P4 目标版本

| 项 | 值 |
| --- | --- |
| v1 | 现状：仅 `tasks` store |
| v2 | 新增 `events`、`checkpoints`、`meta`；`tasks` 记录增加 `revision` |
| 升级方式 | `onupgradeneeded` 中按 `oldVersion` 分支创建缺失 store 与索引 |
| 数据保留 | 不重建 `tasks`，不重写已有记录；`revision` 缺失按 0 读取 |
| 降级 | 不支持 v2→v1；旧代码打开 v2 会触发 `onblocked`/版本错误，必须提示升级刷新 |

## 3. 迁移步骤

```text
open(dbName, 2)
onupgradeneeded(oldVersion):
  if oldVersion < 2:
    createStore('events', {keyPath:['taskId','seq']})
      .createIndex('byTask','taskId')
    createStore('checkpoints', {keyPath:'checkpointId'})
      .createIndex('byTask','taskId')
      .createIndex('byTaskAt',['taskId','at'])
    createStore('meta', {keyPath:'key'})
    meta.put({key:'schemaVersion', value:2, updatedAt: now})
  (tasks 保持不变)
```

迁移完成后启动时执行一次派生索引补齐（可中断、可重复）：

1. 读取 `tasks` 全部记录；
2. 对每条 `state.events` 写缺失的 `events`；
3. 对每条 `state.checkpoints` 写缺失的 `checkpoints`；
4. 写 `meta.lastMigration`。

该步骤失败不回滚已建 store；下次启动重试，幂等。

## 4. 迁移失败与中断

| 情况 | 处理 |
| --- | --- |
| `onupgradeneeded` 抛错 | 事务 abort；旧库保持 v1；应用提示“存储升级失败，请刷新或清理站点数据” |
| `onblocked`（其他标签页占用） | 提示关闭其他标签页后重试；不覆盖数据 |
| 迁移中关闭浏览器 | 已建 store 保留，数据补齐下次继续；不标记完成前不启用事件索引读取 |
| 重复初始化 | `meta.schemaVersion===2` 时跳过升级 |
| 派生补齐失败 | 任务记录仍可读；事件/检查点读取回退到内嵌数据 |

## 5. 数据生命周期

| 数据 | 保留策略 | 默认 |
| --- | --- | --- |
| 进行中任务 | 永久直到完成/用户删除 | 保留 |
| 已完成任务 | 用户可删除；不自动清理 | 保留 |
| 失败任务 | 保留原因，供诊断 | 保留 |
| 事件 | 随任务保留 | 保留 |
| 检查点 | 每任务最近 20 个 + 最终检查点 | 自动裁剪，可配置 |
| 隔离区旧任务 | 永久，直到用户处理 | 保留 |
| 审计日志 | 独立库，按现有策略 | 保留 |

### 5.1 清理规则

1. 检查点裁剪只删“非最终、超过 20 个”的旧检查点。
2. 删除任务必须级联删除事件与检查点；事务失败则整体失败。
3. 不允许单独删除检查点而保留可恢复记录。
4. 配额不足时优先提示用户删除已完成任务；禁止静默删除。

### 5.2 配额不足

- 监听 `QuotaExceededError`。
- 返回 `QUOTA_EXCEEDED`，保留内存状态，提示：
  “本地存储空间不足，任务进度可能无法保存。请删除不再需要的历史任务后重试。”
- 不自动清理、不降级为“假装保存成功”。

## 6. 多标签页

- `tasks.revision` 递增；写入前比较记录 revision，落后则 `STALE_WRITE`。
- 两个标签页同时恢复同一任务：先写者成功，后写者收到 `STALE_WRITE`，提示“任务已在其他标签页继续”。
- 不实现跨标签页实时同步；以存储层冲突检测为准。

## 7. 测试

- `p4-migration-test`：v1→v2 建 store、记录保留、重复初始化不重复迁移、升级异常保留 v1、派生补齐幂等。
- `p4-lifecycle-test`：检查点裁剪、级联删除、配额不足、陈旧写、隔离区保留。
