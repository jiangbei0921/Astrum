## 3. 统一请求入口设计

### 3.1 实际调用链（V1.1 后）

```
用户输入
  └─ app.js ask()
       ├─ 归一化 / 城市 / 附件 / 用户气泡
       ├─ AstroRequest.classify(query, ctx, cfg)   ← 只执行一次 Router
       │    ├─ LEGACY / L1 → 旧 buildAnswer + 旧检索/云模型流程
       │    └─ L2-L4 → AstroControlBridge.runWithRoute
       │         └─ AstroControl.run（带 routeData）
       │              ├─ Planner → Scheduler → Runner → Registry
       │              ├─ Compose Adapter → answer.research
       │              └─ TaskStore.save
       └─ renderAnswer(answer)
            └─ AstroResearchUI.render(answer.research)（仅研究任务）
```

### 3.2 分流规则

- L1 / `unknown` / `smalltalk`：旧链路，不创建 Plan。
- L2-L4：`AstroRequest.classify` 判定 `control=true` 后交给 Control。
- Control 复用 `routeData`（intent/targets/route），不再执行 `resolveTargets/detectIntent/route`。
- 接管条件（保守边界）：
  - 本地来源（`src.type === 'local'`）；
  - 无附件；
  - 非「对比模式」。
  这样旧 web/云端/附件/对比流程保持原样，避免新链路丢失旧能力。
- 失败/取消：渲染明确的 boundary，不把失败包装成研究报告；也不回退成看起来成功的旧答案。

### 3.3 涉及文件

| 文件 | 作用 |
|---|---|
| `core/request.js`（新增） | `classify` / `handle`，一次 Router + routeData |
| `core/control-bridge.js`（新增） | 把分流结果交给 Control，统一返回 `{mode,answer,research,control}` |
| `core/control.js`（修改） | `prepare` 接受 `opts.routeData`，避免重复路由 |
| `core/app.js`（修改） | ask 中接入 Bridge、取消按钮、恢复提示、Research UI 挂载 |
| `core/research-ui.js`（新增） | 研究报告渲染与安全转义 |
| `core/planner.js`（修改） | 研究类问题优先 T-E/T-F（V1 已实现，V1.1 保持） |
| `core/i18n.js` | 新增 UI 词条 |
| `assets/app.css` | 研究报告卡片样式 |

## 4. Research UI 实现

- 位置：`answer.research` 存在时，`renderAnswer` 在 sections 之后追加 `details.research-panel`。
- 结构（8 个区块）：
  1. 研究概览（问题/主题/检索时间/覆盖度）
  2. 核心研究结论（等级/规则/evidenceRefs）
  3. 天体基础参数
  4. 相关论文（标题/作者/DOI/日期/摘要/链接/abstractOnly）
  5. 观测数据（FITS 文件/HDU/统计/警告）
  6. 证据验证（Evidence/来源类型/可信度）
  7. 冲突与不确定性
  8. 研究局限（缺口/不确定性/免责声明）
- 交互：`details` 展开/折叠；论文与证据链接 `target="_blank" rel="noopener noreferrer"`。
- 安全：
  - 外部标题/摘要/URL 全部 `esc()`；
  - URL 只允许 `http(s)`，`javascript:` 不生成链接；
  - 不把 JSON 直接输出到页面。
- 兼容：旧 L1 答案没有 `answer.research`，完全不走该分支；旧 sections 不改。

## 7. 科学证据机制边界检查

### 7.1 冲突阈值

- 当前 `Reducer.conflictsOf` 使用固定 5% 相对差阈值。
- 已按单位分组（`entity|unit`），因此不同单位不会互相比较。
- **未考虑**：测量不确定性、观测时期、参考系、物理量类型差异。
- 结论：这是保守的“数值分歧提示”，不是科学显著性检验；V1.1 不重写，登记为 V1-L20。
- 未做代码修改，避免改变既有 Judge/测试基线。

### 7.2 不确定性

- FITS Claim 的 uncertainty 为 `std/sqrt(n)`，记录为 `measurement`。
- 该值只是**样本均值标准误近似**，不代表仪器误差、系统误差或模型误差；报告与遗留清单已明确。
- 未把单一统计量包装成“完整科学不确定性”。

### 7.3 证据独立性

- 同 DOI（含镜像 URL）只保留一条，`duplicates` 记录被丢弃项；
- 独立来源按 `sourceId` 计数；
- 同一论文不同摘要页不会计为多个独立证据。
