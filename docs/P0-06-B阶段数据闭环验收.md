# P0-06 B 阶段数据闭环验收（B8）

> 范围：Plan → Scheduler → Runner → Registry → StepResult → Compose Adapter → answer
> 依据：P0-05 定向验收发现的 P1（Plan 结果未进入最终 answer）
> 批准范围：计算类模板（T-A/T-C）；T-B/T-D/T-E/T-F 的不可复用路径明确回退并标记
> 状态：B8 计算类数据闭环通过；全模板数据闭环未完成

---

## 1. 原有数据流（B8 前）

```text
Plan step
  → Runner.executeOne
      → Registry.get(tool)
      → spec.run(args, ctx, spec, cfg)
      → step.result = 工具原始返回
  → state.steps[].result
  → compose 步骤 args = {query, intent, from:[stepId]}
  → Registry.runCompose(args, ctx, spec, cfg)
  → Adapter.compose(args, ctx, cfg)
  → buildAnswer(args.query, ctx, cfg)
  → answer
```

问题：

- `from` 只是 stepId 列表，没有对应结果；
- Adapter 只读 `args.query`；
- 最终 answer 与 Plan 结果没有数据依赖；
- Registry 星历与 `composeTarget` 的 `ephemFor` 等价计算重复。

## 2. 修改后的数据流

```text
Plan step (t1 kb.lookup)
  → Runner 执行 → step.result {targets,names}
Plan step (t2 kepler.ephemeris)
  → Runner 执行 → step.result {records:[{target,ra,dec,ephem,alt,az}]}

compose step (t3)
  → Runner 收集 deps 中 status=ok 的 StepResult
  → Registry.runCompose(args,ctx,spec,cfg,depResults)
  → Adapter.compose(args,ctx,cfg,depResults)
      → buildPreloaded(depResults, args.from)
          targets ← kb StepResult
          ephem[target] ← kepler StepResult.records[].ephem

          targets = preloaded.targets（跳过重复 resolveTargets）
          composeTarget/composePhoto 命中 preloaded.ephem（跳过重复 ephemFor）
      → {ok, answer, delivery}
  → step.result.delivery
  → runner.answer
  → Control.answer
```

## 3. StepResult 传递路径与字段映射

| 步骤 | StepResult 关键字段 | 传给谁 | 被消费方式 |
|---|---|---|---|
| `kb.lookup` | `{ok, targets:[{item,match}], names}` | Adapter `buildPreloaded` | 作为 `preloaded.targets`，替代 `resolveTargets` |
| `kepler.ephemeris` | `{records:[{target,ra,dec,ephem,alt,az,jd}]}` | Adapter `buildPreloaded` | `preloaded.ephem[target]`，供 compose 复用 |
| `compose.target/domain/simple` | `{ok, answer, delivery}` | Runner → Control | `answer` 成为最终 answer，`delivery` 进入返回元数据 |
| 失败/缺失步骤 | 不进入 `depResults` | — | 不进入 preloaded；走旧计算 |
| `compare.curate` | `{ok,items}` | Adapter（仅标记） | 当前旧接口不消费，`fallback=true` |
| `evidence.search/paper.search` | `{ok,items:[],deferred:true}` | Adapter（无可用字段） | 当前不消费，`fallback=true` |

`delivery` 形状：

```js
{
  usedStepIds: ['t1','t2'],
  ephemTargets: ['猎户座大星云'],
  targetsFromSteps: true,
  fallback: false,
  missing: [],
  dependencyIds: ['t1','t2']
}
```

只由 `AstroControl.run()` 返回，不写入 answer。

## 4. Adapter 如何使用结果

- `args.from` 指明依赖 stepId；
- `depResults` 只包含 `status='ok'` 的 StepResult；
- `buildPreloaded` 识别：
  - `targets` → `preloaded.targets`
  - `records[].ephem` → `preloaded.ephem[target]`
- `buildAnswer` 第 4 参数接收 preloaded；
- `composeTarget/composePhoto` 通过 `ephemForPreloaded(name,ra,dec,ctx)` 命中缓存，否则调用原 `ephemFor`；
- 旧 `ask()` 不传 preloaded，`ACTIVE_PRELOADED` 为 null，行为完全不变。

## 5. 重复计算处理

| 计算 | B8 前 | B8 后 |
|---|---|---|
| `resolveTargets` | Runner kb 一次 + buildAnswer 一次 | preloaded.targets 命中，buildAnswer 跳过 |
| `ephemFor`（T-A/T-C） | Registry 一次 + compose 一次 | Registry 一次，compose 复用 |
| `ephemFor`（T-B 无显式目标） | 未覆盖 | 保持旧路径（visibility targets 为空） |
| `compare.curate` / evidence | 无旧消费接口 | 保持旧路径，`fallback=true` |

测试 3 通过 `Astro.track` 计数证明 T-A 单目标执行时仅 1 次星历计算，而不是 2 次。
