## 2. 当前部署架构

```
源码（index.html + core/ + data/ + assets/）
  ├─ 本地 file://            → 直接打开
  ├─ 本地 HTTP               → 静态服务器
  ├─ standalone              → tools/build-standalone.js 内联 CSS/JS
  └─ GitHub Pages（计划）
        ├─ 现状：README 指引 Deploy from a branch → main / (root)
        ├─ 风险：tools/、docs/、dev/ 会随分支公开
        └─ V1.4 方案：显式白名单暂存目录 `_site/` + 官方 Pages Actions
```

- 纯静态、无后端、无强制数据库；API Key 仅存用户 localStorage。
- 运行时不引用 `worker/`；CORS 代理是用户可选配置，不是部署依赖。
- 所有页面资源使用相对路径，未使用 `<base>`、绝对路径或动态 `import()`。
- `index.html` 的 CSP 是 `meta` 策略；GitHub Pages 不注入 CSP 响应头，因此该策略是线上唯一策略。
- 外部请求端点已列入 `connect-src`（OpenAlex、Semantic Scholar、SIMBAD、arXiv、NASA、天气/地理等）。

## 5. 资源加载机制

| 类型 | 方式 | 子路径兼容性 |
|---|---|---|
| CSS | `href="assets/app.css"` | 相对，兼容 `/Astrum/` |

| core | `<script src="core/*.js">` | 相对，兼容 |
| 图片 | 无外部图片，favicon 为 data URI | 兼容 |

| FITS | 用户本地文件（FileReader） | 不涉及网络路径 |

| 外部 API | `fetch` 到白名单主机 | 依赖 CORS/CSP，不依赖站点路径 |
| 动态脚本 | 无 `import()`/动态 `<script>` | 兼容 |
