## 2. P3 状态增补（最小、向后兼容）

### 2.1 新增 step 状态

| 状态 | 语义 | 加入位置 |
|---|---|---|
| `waiting_approval` | 等待用户确认（高风险/超预算追加/重规划） | `STEP_STATUS`、`validate` |
| `paused` | 用户暂停时正在运行或待运行 | `STEP_STATUS`、`validate` |

- 二者均为**可选状态**，旧任务不含它们仍合法；
- `isSettled` 不把 `paused` 视为终态（可恢复），把 `waiting_approval` 视为可继续；
- `blockedSteps` 的 `bad` 列表不含 `paused`（暂停不触发下游 blocked）。

### 2.2 TaskState 增补

| 字段 | 类型 | 说明 |
|---|---|---|
| `goal` | `ResearchGoal|null` | 必须加入 `create()` 白名单 |
| `pausedAt` | `string|null` | 暂停时间 |
| `recoveries` | `number` | 已恢复次数（预算项） |
| `planHistory` | `array` | 计划版本索引（可选；现有 `replans` 已可承载） |

**关键：** `TaskState.create()` 是字段白名单，未加入的字段在 `fromJSON` 时会被丢弃。P3 必须同步修改 `create()`，否则「刷新后恢复」会丢失 goal。

### 2.3 状态机（step 级）

```
pending ──ready──► running ──► ok
   │                 ├──► failed ──retry──► running
   │                 ├──► blocked（依赖失败传播）
   │                 ├──► aborted（取消/会话变化）
   │                 ├──► paused（用户暂停） ──resume──► pending
   │                 └──► waiting_approval ──approve──► pending
   └──skipped（预算不足/optional 跳过）
```

规则：

1. 只有 `pending` 才可被调度（现状）；
2. `paused` 不可被调度；
3. `waiting_approval` 不可被调度，需用户动作；
4. `failed` 只有显式重试才回到 `running`；
5. `ok` 不可回退；`aborted` 不可复活（与任务级一致）。

## 3. 任务调度

### 3.1 调度循环（复用现状）

```
while guard++ < 200:
    blocked = blockedSteps()            // 失败依赖 → blocked
    if criticalFailed() → 返回 criticalFailed
    if allSettled() → break
    batch = nextBatch(limitParallel)    // compose 串行；parallel ≤ 4
    ensureSession()                     // 每批重校验
    results = runBatch(batch)           // 并行/串行
    if any aborted → cancelledRun()
```

证据：[runPlan](file:///D:/Projects/Astrum/core/orchestrator.js#L487-L573)。

### 3.2 P3 增量

1. **并行副作用过滤**：`nextBatch` 生成候选后，按 `P3-03 §7.1` 的等级剔除冲突项，必要时降为串行；
2. **批前预算预检**：`sum(cost(batch)) ≤ remaining`，不足则整批降级为单步；
3. **暂停检查点**：每批开始前检查 `state.pausedAt`，存在则返回 `paused` 结果而不调度；
4. **审批检查**：存在 `waiting_approval` 步骤且未批准 → 返回 `waiting_approval`。

### 3.3 就绪/阻塞判定（保持语义）

- 依赖全 `ok` → 就绪；
- 依赖 `optional === true` 且已 settled 且非 ok → 放行；
- 依赖 failed/blocked/aborted/skipped 且非 optional → blocked；
- 依赖缺失 → 不就绪（同时应被 DAG 校验提前拒绝）。

## 5. 失败传播

### 5.1 分类

| 类别 | 来源 | 可重试 | 下游 |
|---|---|---|---|
| `timeout` | 超时 | 是（幂等） | critical → 阻断 |
| `network` / `rate_limit` | 外部 | 是（幂等） | 同上 |
| `tool_missing` / `deps_missing` | 能力缺失 | 否 | 阻断 |
| `args_invalid` | 参数 | 否 | 阻断 |
| `permission` | 授权 | 否 | 阻断 + 审计 |
| `budget` | 预算 | 否 | skipped，不阻断可选 |
| `cancelled` | 取消 | 否 | 全部 aborted |
| `contract` | 输出不符 | 否 | 阻断 |

### 5.2 传播规则

1. **critical 失败** → `criticalFailed === true` → 停止调度 → 进入一次（或多次，受 `replans`）重规划；
2. **optional 失败** → 不阻断下游（`readySteps` 已放行）；
3. **非 critical 非 optional 失败** → 下游 blocked；
4. 失败步骤**永不**被判定为成功；
5. 重规划后仍失败 → `PROGRESS → JUDGE → COMPOSE` 走 `PARTIAL`，报告如实列出失败。

### 5.3 现有重规划路径

[control.js](file:///D:/Projects/Astrum/core/control.js#L320-L369)：`criticalFailed && replans < limit` → `Planner.replan` → 新增步骤 → 再跑。P3 保持，只补「记录 planVersion」。

## 6. 重试

| 项 | 规则 |
|---|---|
| 允许条件 | `idempotent === true` 且 `retry.allowed !== false` |
| 最大次数 | 1（`Math.min(1, max)`） |
| 可重试类别 | `timeout` / `network` / `rate_limit` |
| 不重试 | 权限、参数、工具缺失、合同不符、取消 |
| 预算 | 每次尝试都 `spend(cost)`（现状在 `withTimeout` 后统一记账，P3 需确保失败尝试也扣减） |
| 记录 | `step.attempt` 递增，`step.retry` 事件 |

**注意：** 当前实现中 `spend` 在每次 `withTimeout` 之后执行，即使失败也扣减，符合「尝试即消耗」。P3 保持不改为「成功才扣」。

## 7. 取消

### 7.1 机制

`AbortController.signal` → `runPlan` 入口/每批前/工具调用内检查；`withTimeout` 监听 `abort` 返回 `cancelled`。

### 7.2 语义

- 未开始步骤 → `aborted`；
- 在飞请求 → 返回 `{ok:false, reason:'cancelled', pendingAbort:true}`，步骤 `aborted`；
- 任务级 → `T.transition('ABORTED')`，事件 `task.cancelled`；
- **不产出伪结论**：UI 明确提示「已完成步骤不会作为结论使用」（[app.js](file:///D:/Projects/Astrum/core/app.js#L3873)）。

## 8. 暂停

### 8.1 现状

**未实现。** `task.pause` 能力为 `false`；只有取消（不可恢复）。

### 8.2 设计（阶段 B 实现）

```
pause(taskId, principal):
  1. authorize(task.pause) + ensureSession
  2. 校验任务属于当前 Profile/Project 且 phase === 'EXECUTE'
  3. state.pausedAt = now; 追加事件 task.paused
  4. 不中断在飞请求（浏览器无法安全杀死 fetch），但不再启动新批次
  5. 在飞请求完成后：其步骤按真实结果记为 ok/failed，不标记为成功
  6. 保存状态 + 检查点（phase=EXECUTE, pausedAt）
```

### 8.3 与取消的区别

| 维度 | 暂停 | 取消 |
|---|---|---|
| 阶段 | 保持 `EXECUTE` | 进入 `ABORTED` |
| 已运行步骤 | 保留结果 | 保留结果但整体作废 |
| 能否继续 | 能（resume） | 不能 |
| 新任务 | 不启动 | 不启动 |

### 8.4 安全中断声明

浏览器无法强制终止已发出的网络请求。暂停只保证「不再发起新批次」；在飞请求完成后落库真实结果。报告与 UI 必须如实标注「暂停时仍有 N 个请求在飞」。

## 9. 并发控制

| 控制点 | 规则 |
|---|---|
| 批大小 | `min(4, budget.limit.parallel)` |
| compose | 强制串行 |
| 写共享证据 | 禁止同批 |
| Skill 步骤 | 默认串行 |
| 全局任务 | 同一 Profile 同时只允许 1 个执行中的 P3 任务（UI 层约束） |
| 存储写 | 同一任务串行保存；`save` 拒绝陈旧写 |
