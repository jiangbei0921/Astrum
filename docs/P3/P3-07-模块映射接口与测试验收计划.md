## 3. 接口契约

### 3.1 Goal Adapter

```js
AstroResearchGoal.fromRoute(routeData, opts) →
  { ok: true, goal } | { ok: false, reason, missingInfo: [] }

AstroResearchGoal.validate(goal) → { ok, errors: [{path, reason}] }
```

约束：`goal.projectId` 必须等于 `opts.projectId`（若提供）；不访问存储。

### 3.2 DAG Validator

```js
AstroDagValidator.validate(plan, opts) →
  { ok, errors:[{path, code, reason}], order: string[], levels: string[][] }

AstroDagValidator.parallelConflicts(batch, registry) → [{a, b, reason}]
```

约束：纯函数；不读 I/O；Skill 存在性通过 `opts.skillLookup` 注入，便于测试。

### 3.3 Capability Resolver

```js
AstroCapabilityResolver.resolve(step, ctx) →
  { ok: true, kind:'tool'|'skill', toolId?, skillId?, versionId?, agentId }
  | { ok: false, code:'capability_missing', capability }
```

约束：只读 registry / skillStore；不创建、不发布。

### 3.4 Task Executor（门面）

```js
AstroTaskExecutor.execute(step, state, opts) → StepResult
```

`StepResult` 与现有 `executeOne` 返回一致，字段为 `ok / result / reason / critical / aborted / budget`（均为可选）。

### 3.5 Progress Evaluator

```js
AstroEvaluator.decide({ state, plan, goal, research, opts }) →
  { action:'continue'|'append'|'replan'|'pause'|'complete'|'stop',
    reason, gaps, details, counts, dimensions? }
```

向后兼容：不传 `goal` 时行为与现状一致。

### 3.6 Reporter

```js
AstroReport.buildExecution({ state, goal, plan, executions, budget, verdict }) →
  { summary, planSummary, executed, completed, failed, skills, tools, findings,
    evidence, gaps, openQuestions, budgetUsage, changes, status, nextSteps }
```

只产出数据，不直接渲染；由现有 compose 输出接入。

### 3.7 存储

- 不新增 store；
- 目标/计划/检查点随 `TaskState` 持久化；
- 所有保存继续经 `AstroTaskStore.save`（含 Profile/Project 校验）。

## 6. 验收标准

### 6.1 功能

- 识别目标并关联正确项目；
- 生成 ≤8 步 DAG 并通过校验；
- 正确分配工具/Skill/Agent；
- 受控执行、失败分类、暂停/恢复/取消/重试；
- 检查点可恢复且不重复非幂等操作；
- 预算可阻止超限；
- 缺口检测与阶段报告与真实状态一致。

### 6.2 安全

- 无网关绕过；
- 无未发布 Skill 执行；
- 无跨 Profile/Project 读取；
- 无 `eval`/动态代码；
- 无未授权外部副作用；
- 会话/项目切换立即阻断。

### 6.3 稳定性

- 全部回归通过；
- 无未解释失败；
- 无状态不一致；
- 无无限循环（guard/上限）。

### 6.4 兼容

- 简单问答、比较、科研检索、天文计算不受影响；
- Agent 名册不变；
- `answer.sections/trace/meta` 契约不变；
- 静态部署方式不变。

## 8. 回滚方案

| 层级 | 方式 |
|---|---|
| 代码 | `git revert` P3 提交（阶段 B 单个或分组提交，便于回滚） |
| 数据 | 新增字段全部可选；旧任务无需迁移；如异常，读取时忽略新字段 |
| 功能 | 通过开关式入口（`opts.p3 !== false`）保守接入；默认路径保持旧行为 |
| UI | 新面板/按钮独立挂载，异常不阻断启动（沿用 P2 做法） |
| 部署 | 静态资源回滚到上一 commit，无数据库迁移 |

**禁止：** 删除任务、清空 IndexedDB、批量迁移历史数据作为回滚手段。
