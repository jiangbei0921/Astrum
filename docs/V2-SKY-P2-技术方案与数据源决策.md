# ASTRUM V2-SKY P2：技术方案与数据源决策

- 日期：2026-11-14
- 决策状态：**PARTIAL**；沿用已接入HEASARC BSC5P，不引入新外部星表；算法接入需以回归全绿为前提。

## 1. 数据源

### 正式生产数据

继续使用现有NASA HEASARC修订版Bright Star Catalogue 5th Rev. Ed. (BSC5P)，共9,096条。生成数据记载的许可为美国政府作品/公有领域，官方记录为[Data.gov HEASARC BSC5P记录](https://catalog.data.gov/harvest_record/0675b2e3-9533-4105-9e5a-a13cefd3765c/raw)，政府作品说明为[USA.gov](https://www.usa.gov/government-works)。许可结论严格限于HEASARC所分发的这一版本，不推论Yale出版物或其他镜像的授权。

Gaia DR3、Hipparcos、Hipparcos-2、Tycho-2等不作为本次生产数据源；此前记录有CC BY-NC 3.0 IGO相关限制，本次未发现可替代已打包生产数据的许可证明。UCAC4未重新验证完整许可链，标记`LICENSE_UNVERIFIED`，不导入。无需引入测试星伪装生产记录。

### 数据字段决策

- 当前数据坐标为J2000 RA/Dec度，星等为V波段，B-V为实测表字段的量化值（缺失为null），谱型仅现有字节编码首字母。
- 当前数据未施加自行；视差/自行在现有文件缺失，保持null，不计算或伪造。
- 压缩量化误差必须随数据元信息披露；当前坐标精度不应描述为高精度测量值。
- 新增规范读取接口`recordAt(index)`为字段附带来源/历元/单位描述；来源ID仅能来自真实记录元数据，否则为null。不得以数组索引伪造源ID。
- 正式构建必须显式传入批准的官方许可记录URL，使用不覆盖现存文件的新输出路径；必须有原始TDAT文件和零静默异常才能生成正式表。当前原始TDAT缺失，本轮不重建、不覆盖`data/sky-stars-l1.js`。

## 2. 视觉算法方案

- 保持L0 `CAT.stars`及其点击、标签、Agent业务逻辑不变。
- L1继续作为独立视觉数据。**用户已确认：保留既有带名L1亮星（V≤5.0）点击**，沿用原`l1:index`键、原命中半径与详情字段；其他视觉星仅绘制，不自动新增业务身份、不进入Agent搜索。不拆分公共详情接口。
- 星等通量可由`F ∝ 10^(-0.4m)`导出，屏幕亮度使用有界压缩映射；亮星保留、暗星按FOV降采样，不能更改原始数据。
- B-V→颜色仅作显示近似，不称为真实肉眼颜色/精确有效温度；缺失B-V时仅以可识别的谱型字母降级，其余中性。
- LOD显示上限按性能测试确定；保留最亮星优先，不以排序改变旧记录索引语义。关闭stars图层时停止L1投影/绘制。
- 球面方向网格适合无依赖静态数据；查询必须采用保守视场边界（含RA环绕、极区）避免漏星。已实现为 36×18（10°×10°）网格 + 视场球冠选格，并用 `tools/visual-stars-test.js` 对照暴力遍历验证 6 组视角（常规/RA=0/RA≈360/近天顶/近地平极广角/窄视场）结果完全一致。

## 3. 文件和回归计划

允许范围：`core/sky-viewmodel.js`、`core/sky-renderer.js`、`core/sky-star-data.js`、`tools/build-star-data.js`及新增隔离测试、三份P2报告。禁止改`data/catalog.js`、`core/astro.js`、`core/app.js`无关逻辑、`core/solarsystem.js`、背景纹理/资源和旧测试断言。`index.html`及standalone如需改动应先确认依赖，避免增加CSP/独立文件兼容风险。

回归执行：2B/阶段1离线与Chrome、2C离线与Chrome、P0/P1离线与Chrome、CSP；自检、Pages子路径及standalone构建仅在确认其固定输出不存在/可覆盖且不含用户数据后执行。浏览器性能报告使用真实墙钟采样与场景分层，Node微基准单独标识，不冒充帧率。

## 4. 当前决策门槛和待办

1. 不扩展许可范围、不导入额外数据，无需许可审批。
2. 业务命中语义已决策：保留既有带名L1点击；后续若要求“L1完全不产生业务hit”需另立批准变更。
3. 本轮已从元数据记载的官方原URL取得`heasarc_bsc5p.tdat.gz`，实算SHA-256与生产`inputSha256`一致（`122628cd…93931`）。原始数据14条缺V星等记录对应官方说明的14个获HR编号非恒星对象（HR 92/95/182/1057/1841/2472/2496/3515/3671/6309/6515/7189/7539/8296）。**用户已批准显式排除政策**：构建器仅在“HR在官方清单内且V星等缺失”时将其归入独立`EXCLUDED_ROWS`计数，不混入拒绝项、不静默删除；若清单内HR反而带星等，则硬失败并要求人工审查。官方输入`--check`已通过（9,096接受 / 0拒绝 / 14排除）。
4. 生产星表已按批准流程替换，采用`--no-records`模式保持体积同量级：新文件182,156B（+1.3%）、9,096颗、1,630名称、`data`逐字节一致；旧文件留存临时备份可回滚。
5. 旧回归 N3.4 与浏览器 B4.2 在未修改断言前提下于历史复测通过；本轮仅收紧相应测试标题/注释，断言与执行次序未变。
6. 数据源与许可结论仍仅限HEASARC分发版本；`--license-evidence`仅作来源声明字符串门禁，不等同联网核验。
