## 4. 真实调用链

### 4.1 论文 PDF 附件

```
用户上传 .pdf
  → Attachments.kindOf = paper
  → Attachments.process（≤12 MB）
  → AstroPaperAttachment.parseBytes
      → AstroPdfText.parse（零依赖）
      → AstroPaperFulltext.buildChunks / buildEvidence
  → item.paper（页数/章节/分块/pageStart）
  → AstroAttachmentEvidence.fromAttachments
  → AstroControlBridge.canControl（allSupported）
  → AstroControl.run（attachmentsEvidence 注入 compose.sections）
  → Compose Adapter → Reducer → Report → Research UI
```

- 仅本机解析，不上传服务器。
- 解析失败/扫描件无文本：`pdf_no_text` / `pdf_parse_error`，不生成 fulltext Evidence。
- 页码未知时保持 `null`，不伪造。

### 4.2 云端模型表述

```
app.js
  → AstroControlBridge.modelGenerate
      → Sources.generate（统一超时/外部 AbortSignal）
      → 成功/限流/超时/鉴权/取消分类
  → 研究答案：追加“表述”段；科学结论仍来自 Evidence/Claims/Report
  → 失败时保留研究结论并明确标注，不伪装成功
```

- L1/对比旧路径的模型调用也统一经过 `modelGenerate`。
- 没有密钥、没有真实 provider 调用时不会伪造模型输出。

## 5. NOT_REQUIRED 依据

### 5.1 Agent Registry

原始设计明确为 **Tool-Centric + 固定 13 Agent 角色**：

- `docs/architecture/02-现有架构问题诊断.md` 指出 13 Agent 是角色包装，不应为了“更像 Agent”引入无价值 LLM 调用；
- `docs/architecture/04-Agent职责与协作规范.md` 保留 13 Agent 职责与协作，不做动态 Agent 市场；
- `V1-00` 明确 Registry 管理 12 个 Tool，Agent 名册不变。

因此不新增第二套 Agent 注册表、不改变 13 Agent，符合原架构。Tool Registry 已支持注册、查找、Schema、依赖、能力、超时、重试。

### 5.2 独立 Memory 模块

原设计的三层 Memory 已由现有模块承担：

- Conversation Memory：`agents.js` 的 `MEMORY` / `resolveByMemory`；
- 会话与历史：`thread.js`、`store.js`；
- 任务与证据：`TaskStore`、`Evidence`、`TaskState`。

再建独立 Memory 会与 TaskStore/Evidence 职责重复，原文档明确要求避免重复。因此不新增模块。

### 5.3 MAST

`V1-00 §5` 明确记录：

> MAST `mast.stsci.edu`：invoke 500（空请求预期），**仅记录，不依赖下载**。

`09/16` 也把 MAST 列为 P3 可放弃项，并要求先做 CORS 可行性验证；且 Registry 的 12 工具基线不可扩张。因此本轮不新增 `mast.*` 工具，保留该数据源为后续独立版本的可选任务，不使用 Mock 冒充接入。
