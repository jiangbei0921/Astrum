## 5. 真实执行链路

```
用户提问 (app.js)
  → Router.route → intent/mode/level
  → Control.run (control.js:206+)
      → Planner.plan → TaskState.steps
      → Orchestrator.runPlan (orchestrator.js:415+)
          → executeOne (236+)
              → Registry 工具
              → 有 principal 时走 ToolGateway.invoke (321-337)
                  → Security.authorize('tool.call')
      → Evaluator / Judge
      → Report.build → answer
  → app 渲染 + recordSkill(ans)（仅统计，不执行）
```

- **Skill 进入点**：无。现有链路中没有 Skill 加载/执行阶段。
- **权限校验点**：`Control.authorized`（task.*）与 `ToolGateway`（tool.*）。
- **Skill 输出能否改变 Task 状态**：现有 Skill 不参与，不能。
- **外部副作用**：搜索/外部 API 经 ToolGateway；无任意代码执行。

## 8. 风险与前置条件

### 8.1 需用户确认（详见 P2-07）

- **Q1**：确认当前 P2 正式定义为「科研 Skill 自我成长」，旧 Planner/Reducer P2 不再作为本轮范围。

- **Q3**：新系统命名 `ResearchSkill`，旧 `state.skills` 保留且不改语义。

### 8.2 已识别高风险

1. 术语碰撞导致开发者误把旧统计当 Skill 注册表。
2. 若无强约束，模型生成 workflow 可能试图写入 `allowedTools` 扩大权限。
3. 验证环境若使用真实工具会产生外部副作用。
4. 版本指针与审批绑定不严会导致「旧审批发布新内容」。
5. 递归提议可能造成候选爆炸。

### 8.3 前置条件

- P0 安全能力保持不变，`p0-security-test` 32/32。
- P1 已实施，P2 只读引用 ResearchMemory/Evidence。
- 不引入新依赖、后端、云端、向量库。
- 阶段 A 不修改任何业务/测试代码（本次遵守）。
