## 3. 阻断条件

出现以下任一情况必须停止阶段 B 并报告：

1. 发现 P0 权限门可被 Skill 绕过。
2. 需要引入任意代码执行/沙箱才能继续。
3. 必须修改 Evidence/Claims 权威契约。
4. 必须引入后端、云库、向量库或新依赖。
5. 验证需要真实外部副作用才能通过。
6. 旧测试无法在不改预期的情况下通过。

## 4. P0 / P1 依赖风险

- **P0**：身份与权限稳定；`skill.*` 能力已在字典中占位，扩展风险可控。
- **P1**：已实施；P2 仅只读引用 `research-store` 与 `research-context`，不修改其结构。
- 若用户后续回退 P1：P2 的 proposal 来源可退化为仅 Task + Evidence，仍可运行（PARTIAL）。

---

## 5. 数据风险

- 新库 `astrum.skills.v1` 与验证库分离，首次创建无迁移。
- 旧数据不迁移、不删除。
- 回滚：停用新模块即可恢复旧行为；新库可保留为审计冷数据。
- 未执行任何不可逆数据操作。

---

## 6. 执行安全风险

- 无 `eval/Function/动态脚本`；workflow 仅引用 Registry 工具。
- 外部工具在验证中禁用；执行时全部经 ToolGateway。
- 超时/重试/预算上限在 runtime 内硬编码并可由 Skill 收紧、不可放宽超过全局上限。

---

- 阶段 A 仅交付 `docs/P2/` 8 份文档；未改代码、测试、配置、数据；未执行 Git 写操作。
- 阶段 B 仅在用户明确批准本方案后开始，且只实施 P2-03 列明的文件。
- 超出清单的修改必须先报告并获批。
