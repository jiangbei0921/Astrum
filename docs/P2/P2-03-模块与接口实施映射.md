## 2. 新增模块接口

### 2.1 `skill-contract.js`

```js
AstroSkillContract = {
  STATUS, VERSION_STATUS, CAPABILITY_MAP,
  makeProposal(input), makeDraft(input), makeSkill(input), makeVersion(input),
  validateProposal(p), validateDraft(d), validateSkill(s), validateVersion(v),
  canTransition(entity, to), transition(entity, to, ctx),
  normalizeContent(content), contentHash(content),
  diffDraft(baseVersion, draft), verifySnapshot(approval, version),
  semver: { parse, compare, classify(base, next) }
}
```

### 2.2 `skill-store.js`

```js
AstroSkillStore.create(options) -> {
  init(),
  // 提议
  createProposal(input, principal), getProposal(id, principal), listProposals(principal, opts),
  // 草稿
  createDraft(input, principal), updateDraft(id, patch, principal), getDraft(id, principal),
  // 验证/评估
  saveValidation(record, principal), saveEvaluation(record, principal),
  // 生命周期
  transitionSkill(skillId, to, principal, {versionId, reason, approvalId}),
  requestApproval(skillId, versionId, principal, snapshot),
  decideApproval(approvalId, decision, principal, {reason, conditions}),
  publish(skillId, versionId, approvalId, principal),
  deprecate(skillId, principal), archive(skillId, principal),
  rollback(skillId, targetVersionId, principal, reason),
  // 读取
  getSkill(id, principal), listSkills(principal, opts),
  getVersion(id, principal), listVersions(skillId, principal),
  getPublished(skillId, principal),
  // 执行记录
  recordExecution(record, principal), listExecutions(skillId, principal, opts),
  recordFeedback(record, principal), stats(skillId, principal),
  backend(), ownerProfileId(), dbName()
}
```

### 2.3 `skill-proposal.js`

```js
AstroSkillProposal = {
  scan(store, researchStore, principal, opts) -> {proposals, skipped, reasons},
  signatureOfSteps(steps), similarity(a, b),
  dedupe(candidates, existingSkills, existingProposals),
  draftFromProposal(proposal, taskSamples, opts) -> SkillDraft,
  limits: { minRuns, minSuccessRate, similarityThreshold, maxOpenProposals }
}
```

### 2.4 `skill-validator.js`

```js
AstroSkillValidator = {
  validate(draft, ctx) -> Validation,      // ctx: {registry, principal, fixtures}
  evaluate(validation, ctx) -> Evaluation,
  layers: ['schema','static','functional','regression','security','stability'],
  blockingRules(validation) -> {blocked, reasons},
  verdictOf(validation, evaluation)
}
```

### 2.5 `skill-runtime.js`

```js
AstroSkillRuntime = {
  resolveScope(skill, version, principal) -> {ok, reason, tools},
  execute(skillId, input, opts) -> Execution,
  // opts: {store, principal, projectId, threadId, taskId, dryRun, fixtures}
  recordUsage(execution, store),
  failureCategoryOf(err)
}
```

执行流程：
1. 读取已发布版本；2. 校验 Profile/Project/Agent；3. 求交工具；4. 逐步 `ToolGateway.invoke`；5. 校验输出契约；6. 写 Execution 与 AuditLog。
无动态代码执行；步骤失败按 `retryPolicy` 最多重试 2 次，超时即终止。

### 2.6 `skill-ui.js`

`AstroSkillUI.mount()/refresh()`：侧栏「科研技能」区块，列表/详情/提议/草稿/验证/审批/版本/回滚；所有写操作走 store，不直接改数据。

## 3. 修改点

### 3.1 security.js

- `CAPABILITIES`：`skill.read/propose/create/test/evaluate/approve/publish/execute/rollback` 置 true。
- `ROLE_POLICY`：按 P2-02 §2.1 增补。
- `USER_POLICY`：加入全部 `skill.*`。
- `authorize`：对 `skill.approve/publish/rollback` 增加 `principalType==='user'` 判断（与 P1 记忆审核同构）。

### 3.2 orchestrator.js

- `executeOne` 前增加：`if (planStep.kind === 'skill')` → 调 `AstroSkillRuntime.execute`，结果结构包装为普通步骤结果。
- 不影响 `TOOL_AGENT` 与既有工具分支；无 Skill 时零行为变化。

### 3.3 app.js

- 启动时 `AstroSkillUI.mount()`（不存在则跳过）。
- 任务完成后（可选、默认关闭）调用 `AstroSkillProposal.scan`，只写提议，不自动生成/发布。
- 不改 `ask()/buildAnswer()/finalize()/criticReview()`。

### 3.4 index.html

在 `core/research-context.js` 之后、`core/app.js` 之前加载：
`skill-contract.js` → `skill-store.js` → `skill-proposal.js` → `skill-validator.js` → `skill-runtime.js` → `skill-ui.js`。

## 4. 依赖关系

```
skill-contract ← skill-store ← skill-proposal
                     ↑            ↓
                skill-validator ← skill-runtime
                     ↑
                  skill-ui

外部依赖（只读复用）：security, audit-log, registry, tool-gateway,
                      task-store, research-store, profile
```

禁止循环：`skill-*` 不得被 `control/orchestrator` 之外的 P0/P1 模块反向依赖。

## 6. 数据结构与迁移

- 新库 `astrum.skills.v1` 版本 1；首次打开即建 store，无迁移。
- 正式库与验证库分离；失败清理只影响 `validation` 库。
- 旧 `state.skills` 不迁移。
- 回滚方法：删除新库命名空间或忽略新模块；不修改 P0/P1 数据即可恢复旧行为。

## 7. 实施顺序（阶段 B）

1. contract + store（含 security 扩展）→ 单测。
2. proposal + draft → 单测。
3. validator + evaluation → 单测。
4. approval + publish + rollback → 单测。
5. runtime + orchestrator 分支 → 集成测试。
6. UI + app/index 挂载 → 浏览器冒烟。
7. 全量回归 + 最终报告。
