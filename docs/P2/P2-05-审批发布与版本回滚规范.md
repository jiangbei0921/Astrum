# P2-05 审批发布与版本回滚规范

> 原则：正式发布必须人工授权；旧版本永不覆盖；审批与内容哈希强绑定

---

## 1. 流程

```
提议(proposed) → 草稿(draft) → 验证(validating)
   → 通过(pending_approval) / 失败(validation_failed)
   → 人工审批(approved/rejected)
   → 发布(published)
   → 使用/监控 → 改进 → 新草稿（循环）
```

未通过验证、未获审批、审批已失效的版本均不得进入 `published`。

---

## 2. 审批角色

| 动作 | 角色/能力 | 说明 |
|---|---|---|
| 创建提议 | Agent(`skill.propose`) / user | Agent 只能 proposed |
| 生成草稿 | Agent(`skill.create`) / user | 不能改正式 Skill |
| 启动验证 | Agent(`skill.test`) / user | 隔离环境 |
| 评估写入 | critic/`skill.evaluate` | 模型评价只作参考 |
| 审批 | **user only** `skill.approve` | Agent 一律拒绝 |
| 发布/废弃/归档 | **user only** `skill.publish` | |
| 回滚 | **user only** `skill.rollback` | |
| 使用 | `skill.execute` | 需作用域匹配 |

不新增角色；复用现有 user + Agent 角色体系。

---

## 3. 审批数据

`Approval.snapshot` 必须包含：
- 名称、描述、适用场景、不适用场景。
- 输入/输出契约。
- 执行步骤与工具。
- 所需能力/权限。
- 验证结论与六层摘要。
- 安全发现。
- 与旧版本差异（输入/输出/步骤/权限/兼容性）。
- 已知风险。
- 来源（proposal/task/memory/evidence）。
- `contentHash`、`versionId`、`expiresAt`。

审批界面禁止只显示「是否同意」。

---

## 4. 审批规则

禁止发布：
- 验证 FAIL 或安全 FAIL。
- 权限范围未批准。
- 来源不明确。
- 高危风险未解决。
- 版本契约不完整。
- 必需测试缺失。
- 审批已过期或 `contentHash` 不一致。

`CONDITIONAL_PASS` 不自动等于批准；必须由审批者逐条接受条件并记录 `decision='conditional'`。

---

## 5. 发布校验顺序

1. principal 为 user 且具备 `skill.publish`。
2. Skill 存在且 `versionId===approval.versionId`。
3. `contentHash === approval.contentHash`。
4. `approval.decision ∈ {approved, conditional}` 且未过期。
5. 验证 `verdict !== FAIL` 且安全通过。
6. 作用域与目标 Profile/Project 匹配。
7. 旧 `currentVersionId` 存在 → 保留为历史版本（status=`superseded`）。
8. 更新 `skills.currentVersionId` 指针；写 `Publication` 与 `events`；写 AuditLog。
9. 返回 `{ok, publicationId, previousVersionId}`。

并发/重复发布：以 `versionId` 幂等；同一版本重复发布不产生第二个正式指针变更。

---

## 6. 版本规则

- SemVer：`MAJOR.MINOR.PATCH`。
- 版本记录独立（`versions` store），不覆盖文件。
- `contentHash` 为规范化内容的 SHA-256；用于审批绑定、重复检测、审计。
- `parentVersionId` 形成版本链。
- 权限变化（allowedTools/requiredCapabilities 增加）→ 必须 MAJOR 且重新审批。
- 输入/输出契约变化 → MAJOR。
- 新增非权限步骤 → MINOR。
- 文案/超时/重试调整 → PATCH。

### 6.1 版本对比

`compareVersions(v1, v2)` 输出：
`inputsChanged/outputsChanged/stepsAdded/stepsRemoved/toolsAdded/toolsRemoved/permissionsExpanded/compatible`。
`permissionsExpanded=true` 时禁止沿用旧审批。

---

## 7. 回滚

前置：
1. `targetVersionId` 属于同一 `skillId` 且曾 `published`。
2. 目标版本当前安全策略下仍通过（至少 Schema + 静态安全 + 安全层）。
3. 若目标版本存在已知漏洞（`securityKnownIssues` 非空）→ 拒绝或要求额外审批。
4. principal 为 user 且 `skill.rollback`。

执行：
- 不删除新版本；记录 `rolled_back`。
- 更新 `currentVersionId` 指向目标版本。
- 写 `Publication{action:'rollback',previousVersionId}` 与审计。
- 保留全部 Execution/Feedback 记录，不改历史任务。
- 多次回滚允许；每次独立记录。

失败：目标不存在/不属于该 Skill/安全检查失败/权限不足 → 返回结构化错误，指针不变。

---

## 8. 审计

必须记录：
`skill.approve`（含 decision、条件）、`skill.publish`、`skill.rollback`、`skill.deprecate`、`skill.archive`。
字段：principal、skillId、versionId、approvalId/publicationId、reason、timestamp、traceId。
不记录 Skill 正文与敏感输入；快照只存哈希与结构化摘要。

---

## 9. 不允许

- 模型/Agent 直接改 `skills.currentVersionId`。
- 跳过 `Approval` 直接写 `Publication`。
- 用旧审批发布新哈希。
- 回滚删除或改写历史 Execution。
- 通过修改 `status` 字段绕过状态机（store 内必须校验）。
