## 1. 原始问题

2C 接入 NASA SVS 银河纹理后，实际浏览器观感为：

1. 天空上半部分出现灰褐色云雾；
2. 银河平面走向不突出；
3. 银心缺少亮度集中；
4. 暗尘埃带与亮区层次不明显；
5. 整体像模糊云层，恒星与背景缺少纵深。

阶段A审计已定位到「天空纹理构建基准 `az/360` 与栅格取样基准 `0.5+az/2π` 相差 180°」以及「均匀 alpha 0.55 + 无色调映射」两条根因。本轮据此实施 P0，并对 P1 两项分别做证据化评估。

## 2. P0 修复内容

### 2.1 P0-1 方位角 180° 偏移（`core/sky-background.js` → `computeRaster`）

```js
// 修改前
var u = (0.5 + az / (2 * Math.PI)) % 1, vv = 0.5 - alt / Math.PI;
// 修改后
var u = (az / (2 * Math.PI)) % 1;
if (u < 0) u += 1;
var vv = 0.5 - alt / Math.PI;
```

- 不改 `buildSky`、不改 `sampleSky`、不改 `altAzToEq` / `eqToUv` / `galToEq` / `A.altAz` 与鱼眼投影；
- 负方位角与 0°/360° 环绕由 `% 1` + 负值归一处理；
- RA/Dec/UV 映射与投影零改动。

**验证（决定性证据）**

| 检查 | 修改前 | 修改后 |
|---|---|---|
| 银心方位 az=132.4° 读到的纹理亮度 | 46.3（实际读到 az=312.4°） | **96.7（与构建基准一致）** |
| 以银心为中心的 70° 视场整盘平均绝对差 | **32.27 灰阶** | **0.006 灰阶** |
| 默认视角最亮像素高度角 | +40.6°（高空） | **+7.9°（低空，真实位置）** |
| 默认视角高空（>45°）亮像素占比 | 58.9% | **2.3%** |

全盘面 20,108 像素 × 7 个方位（0/90/180/270/360/−90/−180）比对：平均差 ≤0.006 灰阶（单点最大 3 灰阶，来自 rho 的 1/1024 查表量化），全部通过。

### 2.2 P0-2 亮度保比色调映射 + alpha（`core/sky-background.js`）

新增集中参数：

```js
var TONE_ENABLED = true;
var SKY_BRIGHTNESS_FLOOR = 10;
var SKY_BRIGHTNESS_GAMMA = 1.45;
var SKY_BACKGROUND_ALPHA = 0.80;
```

- 256 项 LUT **在模块加载时生成一次**，热路径为单位置整数索引（`toneK`），无函数插值、无逐帧重算；
- 亮度 `Y = 0.299R + 0.587G + 0.114B`，缩放因子 `k = Y'/Y` 同时作用于 R/G/B → 只改亮度、不改色相比例；
- `Y ≤ 10` → 0；`Y ≥ 255` → k=1；无 NaN / Infinity；输出经 `Uint8ClampedArray` 限定 0–255；
- 只作用于 `buildSky` 生成的天空纹理（每个时刻/地点一次），不影响恒星、行星、DSO、星座线；
- 合成只保留原有的一次 `source-over` + `globalAlpha`，**未改混合模式、未新增叠加层**。

### 2.3 需要说明的一处关联调整（`core/sky-renderer.js`）

银河背景改暗后，既有的 2C 断言 `B4.2 开启背景后更亮`（探针位于反银心方向，对照画布含“合成星场 + 夜空渐变”）出现 **on=19.9 < off=22.6**。

在**不放宽、不跳过断言**的前提下，按「深空底色应保持深邃」这一目标把夜空渐变各停靠点压暗（形状不变），按色值计算约压暗 **2/3**（保留约 1/3 亮值）：

|---|---|---|
| 0 | `#03050a` | `#010203` |
| 0.45 | `#071020` | `#03050a` |
| 0.72 | `#122036` | `#060a11` |

修改后同一探针：纯渐变 **5.7**、渐变+合成星场 **11.2**、渐变+真实背景 **17.4**，差值 **+6.2**，B4.2 恢复通过且余量充足。

## 3. P1 两个任务的审计结论

### 3.1 P1-1 纹理降采样与插值：**评估后保留原方案**

分辨率与采样方式（现状，未改）：

| 阶段 | 分辨率 | 采样 |
|---|---|---|
| 源图 → 运行时纹理 | 1024×512 → 512×256 | Lanczos（离线，0.703°/px） |
| 运行时纹理 → 天空纹理 | 512×256 → 256×128 | **最近邻**（1.406°/px） |
| 天空纹理 → 屏幕栅格 | 160×160（低端 128×128） | **最近邻**（fov145 时 0.906°/texel） |
| 栅格 → 屏幕 | 160 → 980 px | `imageSmoothingEnabled=true` 双线性放大 |

质量对比（以 512×256 网格 + 2×2 面积平均作为“理想抗锯齿”参考）：

| 指标 | 最近邻（现状） | 双线性 |
|---|---:|---:|
| RMSE（对参考） | **2.28–2.39** | 1.39 |
| 平均绝对差 | 1.28 | 0.73 |
| 最大差 | 36.5 | 20.7 |
| 大台阶（>25 灰阶，共 65,280 边） | 485 | 370 |
| 天空纹理构建耗时（Node） | **13 ms** | 24 ms（+85%） |

结论：**保留最近邻**。理由：整体平均差仅 0.79 灰阶，视觉层级的根本上限是天空纹理 1.406°/px；插入双线性会使每次重建 +3–11 ms（浏览器实测重建已达 30–42 ms），收益与代价不匹配。已验证「重复降采样」确实存在（512→256→160 两级最近邻），但任务要求「没有明显收益就保留原方案」，因此**未做修改**，仅记录数据。

### 3.2 P1-2 恒星与背景层次：**存在问题，已最小修复**

审计发现（修改前）：

| 项 | 现状 | 判断 |
|---|---|---|
| 绘制顺序 | 背景 → 星场 → 恒星 → DSO → 星座 → 天体 → 地平线 → 标签 | 正确，背景未遮盖恒星 |
| 恒星绘制 | 5 个亮度桶 `Path2D` 批量填充，颜色 `rgba(226,234,248,α)` | 无光晕，亮星与普通星只有尺寸差异 |
| 亮星光晕 | **仅行星/月球/太阳有径向渐变光晕**，恒星没有 | 缺失，不满足「亮星适度光晕」 |
| 恒星颜色/星等/位置 | 直接来自星表，未改动 | 正确 |
| 背景对恒星的影响 | 合成后背景上限约 100 灰阶，恒星核心 228 | 仍清晰，但亮星缺纵深感 |

最小修复（`core/sky-renderer.js`）：

- 新增 `starGlow()`：仅 `mag ≤ 2.5` 且在地平线上方的恒星叠加光晕；两档强度（`mag ≤ 1.5` 强、1.5–2.5 弱）；
- 预渲染 64×64 精灵，逐帧只 `drawImage`，不创建径向渐变；绘制在恒星核心之前，核心保持锐利；
- 不增加 hit、不改 `_hits/_bodies/_meta`、不改星表与任何天体数据；
- 星光晕受 `layers.stars` 控制，图层语义未迁移。

**验证**

| 断言 | 结果 |
|---|---|
| 亮星邻域（半径 7px）亮度：有光晕 47.2 vs 抑制光晕 32.4 | +14.8，光晕生效 |
| 暗星（mag 3.27）邻域：6.12 vs 6.11 | 无变化 → 光晕只作用于亮星 |
| 亮星核心像素 | 228.1（远高于背景） |
| 银心方向像素 vs 画布其余区域 | 55.4 vs 13.7（4.0×） |

## 9. 性能对比（真实 Chrome + 真实时钟，1600×1000，全图层）

基线取 2C 性能报告；本次取 3 次独立运行的中位数。

| 场景 | 基线 p50 | 本次 p50 | 基线 p95 | 本次 p95 | 判定 |
|---|---:|---:|---:|---:|---|
| B1 缓存命中整帧 | 2.5 | **2.3** | 3.3 | **3.0** | 持平/略优 |
| B3 仅背景 drawImage | 0.021 | **0.018** | 0.1 | 0.1 | 持平 |
| C 相机变化（栅格重建） | 11.1 | **11.8** | 17.0 | **17.5** | +0.7 / +0.5（≈3%） |
| F1 高负载缓存命中 | 0.8 | **1.6** | 1.0 | 1.8 | +0.8（光晕） |
| F2 高负载相机变化 | 6.7 | **8.8** | 7.7 | **11.2** | +2.1 / +3.5（光晕） |
| H 典型 760×540 缓存命中 | 1.2 | **1.7** | 1.6 | 2.3 | +0.5（光晕） |
| A3 纯天空纹理构建 | 21.2 | 26.9（三次 21.7/26.9/27.3） | 24.8 | 29.1 | 波动区间覆盖基线 |
| A2 冷重建 | 31.1 | **31.6**（30.2/31.6/39.6） | 36.0 | 43.4 | 基本持平 |
| D2 时间强制重建 | 30.6 | 41.6（42.3/39.5/41.6） | 32.5 | 46.8 | 偏高，见下 |

**性能分析**

1. **缓存命中整帧（B1）反而略优**：2.3 / 3.0，说明背景合成路径没有新增开销（LUT 只在重建时执行，`drawImage` 0.018 ms）。
2. **相机变化（C）几乎不变**：+0.5–0.7 ms，来自新光晕的少量 `drawImage`。
3. **高负载（F2）p50 +2.1 / p95 +3.5**：全部来自亮星光晕（1600×1000、fov178° 时可见亮星数量最多）。p95 11.2 仍远低于 33.3 ms 目标。
4. **天空纹理构建**：Node 侧微基准在修改前后均为 **14.7–15.4 ms（无变化）**，说明 LUT 本身成本 <1 ms；浏览器 A3 三次为 21.7–27.3 ms，与基线 21.2 ms 的区间重叠，且本机存在用户 Chrome 后台负载，故判定为**测量波动而非结构性退化**，A2 冷重建基本持平也支持这一结论。
5. **D2/E2 重建偏高（37–42 ms）**：该场景 n=10、且包含模型重算，波动最大（单次最高 46.8）；Node 与 A2 数据均未显示构建路径变慢。已在报告中如实标注，不作掩饰。

**目标对照**：缓存命中 p95 3.0 <33.3；相机变化 p95 17.5 <33.3；高负载 p95 11.2 <33.3 —— 全部达标。

## 10. 尚未解决的问题 / 需注意

1. **2C `B4.2` 断言的成立依赖夜空底色亮度**：本轮通过压暗底色使「真实背景 > 渐变+合成星场」重新成立（余量 +6.2）。若未来继续大幅压暗或提高 LUT 强度，该断言可能再次失效；这是既有对照方式（背景开/关时合成星场语义不同）带来的固有耦合，未在本轮修改测试。
2. **阶段1 `B4.2 拖动改变 yaw` 仍有约 40% 概率失败**（5 次中 2 次 20/21）：`--virtual-time-budget` 下 rAF 未及时回写 `_meta`；与本轮改动无关（指针与 yaw 逻辑未动），属既有抖动。
3. **headless 无法给出真实显示帧率**：静态缓存命中场景每帧仅 1–2 ms，但 rAF 间隔 p50 仍为 37–41 ms（节流），因此「连续拖动是否卡顿」仍需你在实机观察。
4. **天空纹理 1.406°/px 仍是细节上限**：P1-1 已证明提高纹理插值无法突破该上限；若后续追求更细的银河结构，应按「先优化构建耗时 → 再提高天空纹理 → 最后提高栅格」的顺序单独授权。
5. **LUT 的设计取舍**：亮度 ≤10 的弥散底噪被压到 0，极暗的弥漫结构会消失（这是消除灰雾的代价），亮区未过曝（max 224.3）。
