### 1.2 绘制数据流

正向（恒星/行星/银河带几何）：

```
Astro.altAz(ra, dec, jd, lat, lon)
  → SkyVM.model()      // 按 (jd, lat, lon) 缓存一次
  → SkyVM.build()      // 等距鱼眼投影 + 视觉参数 → 视图模型 vm
  → SkyRender.draw()   // 画布绘制 + 命中区
```

银河背景（真实纹理，反向采样）：

```
屏幕像素
  → computeRaster() 鱼眼逆投影 → (alt, az)
  → SkyVM.altAzToEq(alt, az, jd, lat, lon) → (ra, dec)
  → SkyVM.eqToUv(ra, dec) → 赤道纹理 UV
  → sampleTex() RGB565 解码 → [r,g,b]
  → 亮度保比 LUT 压暗 → 天空纹理 256×128
  → 屏幕栅格 160×160 → drawImage 双线性放大
```

对应关键实现位置：

| 环节 | 文件 / 函数 | 关键事实 |
|---|---|---|
| 天空纹理构建 | `core/sky-background.js` `buildSky()` | `SKY_W=256, SKY_H=128`；az 采样点 `(x+0.5)/256*360`，alt `90-(y+0.5)/128*180`；逐像素 `altAzToEq` + `sampleTex` + `toneK` |
| 屏幕栅格采样 | 同上 `computeRaster()` | 方位基准 `u=(az/2π)%1`（负值 +1），`vv=0.5-alt/π`；与 `buildSky` 同基准，这是 P0-1 的修复点 |
| 栅格尺寸 | 同上 | `RASTER_HI=160`（画布 ≥1200×700）/ `RASTER_LO=128`；非 192 |
| 时间/地点缓存 | 同上 `skyKey()` / `ensureSky()` | 键 = `floor(jd*1440)`（分钟粒度）+ 纬度 4 位 + 经度 4 位；150ms 去抖（`THROTTLE_MS`） |
| 相机缓存 | 同上 `rasterKey()` | 键含 `yaw / pitch / fov / w / h / SKY.key` → **相机或视场变化一定重建栅格** |
| 亮度参数 | 同上 | `TONE_ENABLED=true`、`FLOOR=10`、`GAMMA=1.45`、`ALPHA=0.80`；256 项 `Float64Array` LUT，整数索引 `toneK()` |
| 背景合成 | 同上 `draw()` | 一次 `source-over` + `globalAlpha=0.80` + `imageSmoothingEnabled=true`，绘制到 `[cx-rmax, cy-rmax, 2*rmax, 2*rmax]` 的正方形 |
| 夜空渐变 | `core/sky-renderer.js` `skyBackground()` | `#010203 / #03050a / #060a11 / #080d14`（P1-2 压暗，用于维持 B4.2） |
| 恒星光晕 | 同上 `glowSprite()` / `starGlow()` | 64×64 预渲染精灵；`mag<=2.5 && alt>0`；`mag<=1.5` → `r=size*5.4, alpha=0.55`，否则 `r=size*3.6, alpha=0.28` |
| 恒星本体 | 同上 `stars()` | 5 桶 Path2D，alpha `[1,0.9,0.68,0.42,0.2]`；命中条件仍为 `alt>0 && size>1.9*k`（与 P1 前一致） |
| 绘制顺序 | 同上 `paint()` | 夜空渐变 → 银河背景（或降级银河带）→ 星场 → **光晕** → 恒星 → 深空 → 星座线 → 行星 → 地平 → 标注 |
| 投影 | `core/sky-viewmodel.js` `projector()` | 等距鱼眼；`pitch ∈ [-6, 78]`，`fov ∈ [30, 178]`，`Rmax = min(W,H)*0.49` |
| 纹理资源 | `data/milkyway-bg.js` + `assets/sky/milkyway/metadata.json` | 512×256 RGB565 小端 base64；源 NASA SVS 1024×512，公有领域 |

**注**：`core/sky-background.js` 文件头注释第 9 行写「屏幕栅格 192×192（低端 128×128）」，与实现常量 `RASTER_HI=160` 不一致。这是注释陈旧，不影响运行行为，已在交付报告中登记为文档性问题（P3），本阶段不修改。

## 2. 测试环境与启动方式

### 2.1 推荐环境

| 项 | 要求 |
|---|---|
| 浏览器 | 真实 Chrome 或 Edge，**非 Headless**，关闭「精简/节能」模式 |
| 窗口 | 建议 ≥1440×900，最大化以免星图被压到小尺寸 |
| 缩放 | 系统缩放 100%（DPR=1）作为主测；另用常用 DPR（如 1.25 / 1.5 / 2）复测至少 1 轮 |
| 网络 | 地点搜索、IP 定位需要联网；**手动坐标与星图渲染完全离线可测** |
| 控制台 | 允许打开 DevTools（只读观测用，见 §7） |
| 音频/其他 | 无关 |

### 2.2 三种启动方式

1. **直接打开（file://）**：双击 `D:\Projects\Astrum\index.html`。银河纹理由 base64 内联解码，不涉及跨源图片，`file://` 可用。
2. **单文件版**：运行 `node tools/build-standalone.js` 生成 `astrum-standalone.html`，再双击打开。
   - **注意**：`astrum-standalone.html` 是构建产物（gitignored）。若你的副本生成于 P0/P1 最终调整之前，其中的 LUT 整数索引版本可能不是最新。验收前请重新构建一次，或改用方式 1 / 方式 3。
3. **本地 HTTP**：在项目根目录执行 `python -m http.server 8080`，访问 `http://127.0.0.1:8080/index.html`。适合模拟 Pages 子路径与缓存行为。

### 2.3 打开后的定位步骤

1. 顶栏点击「观测台」(`#btnObs`) 打开右侧观测台面板。
2. 观测台「观测上下文」卡片确认日期(`#ctxDate`)、时刻(`#ctxTime`)、地点(`#ctxPlace`)。
3. 点击星图小窗右上角「全屏查看星图」(`#skyExpand`)，或直接点击小星图，打开「星空全图」(`#viewer`)。
4. 全屏视图中：拖动环顾、滚轮缩放、`#vwVal` 显示当前视场角、`⟲`(`#vwReset`) 复位、`Esc` 关闭。

## 4. 测试矩阵

统一说明：
- 「预期」来自当前实现与冻结基线，不是历史报告数值的直接复述。
- 「异常判据」按 §8 的 P0/P1/P2 分级。
- 每组都应至少留 1 张截图（§5）。

### A. 视场角测试

固定条件：地点 = 北半球中纬度（推荐 39.9042, 116.4074，UTC+8），日期 = 2026-06-01，时刻 = 21:30（该组合下银心位于东南方低空，便于观察主体方向）。

操作步骤：
1. 打开全屏星图，`#vwReset` 复位到 fov≈145。
2. 用快捷档位（30/50/70/100/140/170）直接跳档，并读 `#vwVal` 确认实际值；也可用滚轮微调。
3. 每个视场：先保持 yaw 朝向银心，再左右拖动 ±60° 扫过银道面。
4. 对照 `#bodyRail` 中的行星/恒星位置判断方位是否合理（如夏季银河应从东南向天顶延伸）。

| 编号 | 目标视场 | 操作要点 | 预期现象 | 异常判据 |
|---|---|---|---|---|
| A-1 | 30° | 点快捷档位「30°」 | 银心结构放大、纹理明显柔和但不出现方向错误 | 方向反转 = P0；仅模糊 = P2 |
| A-2 | 50° | 滚轮放大至 `#vwVal` ≈50 | 银心亮集中可见，暗尘埃带可辨 | 主体错位 = P0；突变跳变 = P1 |
| A-3 | 70°（基线核心对照） | 读 `#vwVal` 记录实际值（约 73.5 或 74） | 银河主体方向与恒星方位一致，层次最接近交付观感 | 主体方向 180° 反转 = P0 |
| A-4 | 100° | 缩小到 ≈100 | 银道面贯穿画面，边缘轻微拉伸但连续 | 断层/突然消失 = P1 |
| A-5 | 140° | 缩小到 ≈140 | 可见更大范围银河，模糊增加但不断裂 | 明显拼缝 = P1；像素块 = P2 |
| A-6 | 170° | 缩到接近上限（≤178） | 允许明显模糊，银道面仍应连续、方位正确 | 反转/错位 = P0；大面积块状 = P2 |

每组同时记录：银心方向是否正确、边缘拉伸、模糊程度、连续性、切换视场时是否跳变、恒星与银河相对关系。

### B. 观测地点测试

用 `#btnManualCoord` 精确输入，避免依赖城市库。

| 编号 | 纬度 | 经度 | UTC | 说明 |
|---|---|---|---|---|
| B-1 | 39.9042 | 116.4074 | +8 | 北半球中纬度（北京） |
| B-2 | 0.0000 | 0.0000 | 0 | 赤道附近（几内亚湾） |
| B-3 | -33.8688 | 151.2093 | +10 | 南半球中纬度（悉尼） |

操作步骤：
1. 打开「坐标」面板，输入纬度/经度/UTC 偏移，点「使用该坐标」。
2. 固定日期 2026-06-01、时刻 21:30（三地都用当地时 21:30，注意这会对应不同 UTC，属预期差异）。
3. 复位视角后，先朝南看（yaw≈180），再朝北看（yaw≈0），各拖动扫过银道面。
4. 对比同一天体（如织女星、心宿二）与银河的相对位置。

观察与判据：
- 银心在南半球应显著更高、在北半球偏低；若三地银心高度几乎相同 → 疑 P0。
- 银道面与地平线的夹角应随纬度改变；不变 → 疑 P0。
- 地平线遮挡：地平线以下不应出现明显银河亮块（地面覆盖）→ 出现 = P1。
- 方向反转或整体偏移 180° → P0。

### C. 观测时间测试

| 编号 | 场景 | 操作 |
|---|---|---|
| C-1 | 同地不同时 | 固定地点/FOV，时刻依次 20:00 → 22:00 → 24:00（每次修改后等待 ≥1 秒） |
| C-2 | 同地不同日期 | 固定时刻 21:30，日期 2026-06-01 → 2026-07-01 → 2026-09-01 |
| C-3 | 时间连续推进 | 用 `#ctxTime` 分钟级逐步增加（如每步 +10 分钟），观察是否平滑 |
| C-4 | 快速调整后恢复 | 连续快速改 5 次时刻，再回到原值，观察是否回到同一画面 |

观察与判据：
- 银河应随天球顺时针（北半球）缓慢旋转约 15°/小时，与恒星同步；若银河转、恒星不转或反向 → P0。
- 恒星与银河的相对关系（如某亮星在银道面某侧）在时间变化过程中不应改变 → 改变 = P0。
- 界面在改动后 ≤150ms 内可能沿用旧纹理再刷新（`THROTTLE_MS`），属**预期去抖**；但若持续 2 秒以上不更新或反复闪烁 → P1。
- 快速调整后回到原值，画面应完全复原（缓存命中）→ 不复原 = P1。
- 民用时间 ≠ 屏幕固定旋转：不得用「屏幕转了 N 度」直接推断坐标错误，必须结合恒星位置判断。

### D. 亮度与视觉层次

观察项与判据（全部只能「背景开启」单侧观察）：

| 编号 | 观察项 | 预期 | 异常判据 |
|---|---|---|---|
| D-1 | 深空底色 | 圆盘外四角与暗区应近黑，不发灰发白 | 明显灰雾 = P1 |
| D-2 | 银河主体 | 亮带清晰可辨，与底色对比明显 | 与底色几乎同亮度 = P1 |
| D-3 | 银心亮度集中 | 银心区域应是全画布最亮结构之一 | 银心不比旋臂亮 = P1（结合方位） |
| D-4 | 高亮结构过曝 | 亮区应有细节，不是纯白块 | 大面积纯白/无色阶 = P1 |
| D-5 | 亮星光晕 | 1 等以上亮星有柔和外晕，不遮挡本体 | 光晕过大糊成团 = P2 |
| D-6 | 暗星可辨 | 4–6 等星仍可见细点 | 暗星被背景吞没 = P1 |
| D-7 | 银河 vs 恒星 | 恒星应「压过」背景，亮星明显更亮 | 银河亮带盖过亮星 = P1 |
| D-8 | 不同 FOV 层次稳定性 | 30–170 各档层次关系一致 | 某档明显发灰/发白 = P1 |

**红线**：不得为改善观感修改夜空底色、ALPHA、F/G、LUT、光晕参数或 B4.2 断言。发现问题只记录现象与复现条件。

### E. 纹理质量

| 编号 | 观察项 | 预期（512×256 上限内） | 异常判据 |
|---|---|---|---|
| E-1 | 主体模糊 | 大视场有柔和模糊，小视场可辨结构 | 任何视场都糊成一片 = P2 |
| E-2 | 像素块 | 170° 附近允许轻微块状（最近邻） | 明显马赛克影响观感 = P2 |
| E-3 | 拼接缝 | 赤道纹理 RA 0h/24h 接缝与 UV 边界处不应有明显竖线 | 出现硬竖线/错位 = P1 |
| E-4 | 颜色断层 | 银道面颜色应连续过渡 | 出现色带断裂 = P2 |
| E-5 | 亮度边界 | 不应有直线型亮度跳变（除地平线） | 直线型边界 = P1 |
| E-6 | 不同 FOV 细节变化 | 细节随视场缩放平滑变化 | 同一区域在两档间突然变样 = P1 |
| E-7 | 银心/银道面结构 | 银心应有亮核与暗带结构 | 银心无结构、纯平色块 = P2 |

所有超出现有分辨率上限的细节问题先记录，不现场调参、不升纹理。

### F. 性能

| 编号 | 场景 | 操作 | 记录 |
|---|---|---|---|
| F-1 | 初次打开 | 冷启动打开页面 → 打开全屏星图 | 从点击到画面出现的主观等待；首帧是否缺背景后补 |
| F-2 | 改变 FOV | 连续滚轮 10 次 | 是否卡顿、是否掉帧、`#vwVal` 是否跟手 |
| F-3 | 改变地点 | 切换 3 个坐标 | 应用后到画面更新的延迟 |
| F-4 | 改变时间 | 连续改 5 次时刻 | 是否有明显停顿/闪烁 |
| F-5 | 连续拖动 | 环顾一整圈 | 拖动是否跟手、是否有明显滞后 |
| F-6 | 高频率改视场 | 1 秒内快速缩放 10 次 | 是否堆叠卡顿 |
| F-7 | 高负载 | 同时开多个标签页/其他应用后再操作 | 是否明显掉帧 |
| F-8 | 长时间运行 | 连续 20 分钟操作（见 G） | 是否越来越卡 |

**性能事实（用于解释预期，不作为验收结论）**：
- 相机/视场变化会重建屏幕栅格，但已有 **4 条 LRU 缓存**：回到刚看过的视角（复位、切档位往返）直接命中，不再重算。
- **拖动中**（`interactive`）栅格降到 **128×128**，松手后自动回到 **160×160**；两者共用同一投影，方位不变，只影响拖动时的背景锐度。
- 稳态静止时栅格命中缓存，`draw()` 只做一次 `drawImage`。
- 时间/地点变化触发 256×128 天空纹理重建（此前测量约 **20–30ms**），并有 150ms 去抖。
- 因此「拖动中背景略软、松手变清晰」属于**预期行为**，不是缺陷；判据是「是否影响可用」。

**禁止**：不得用 Headless 的 `performance.now()` 结果推断真实显示帧率；不得把 `perf().sky.last`（JS 调用耗时）说成屏幕帧率。

### G. 长时间稳定性

| 编号 | 项目 | 方法 | 判据 |
|---|---|---|---|
| G-1 | 内存 | DevTools → Task Manager（Shift+Esc）或 Memory 面板，记录 0/10/20 分钟 JS 堆 | 单调持续大幅增长 = P2；小幅波动属正常 |
| G-2 | 背景重建频率 | 控制台读 `SkyBackground.stats().skyBuilds`，静止不动 5 分钟后应几乎不增长 | 静止也持续重建 = P1 |
| G-3 | 拖动后卡顿 | 连续拖动 2 分钟后停下，再拖 | 停下后仍卡 = P1 |
| G-4 | 光晕异常 | 观察亮星周围是否出现方块/残留 | 出现 = P2 |
| G-5 | 时间缓存 | 反复改时间再回原值 | 应命中缓存、画面一致 |
| G-6 | 视觉漂移 | 20 分钟后与初始截图对比 | 明显变灰/变亮 = P1 |

若无法取得内存读数（无 DevTools 权限等），标记 `BLOCKED`，不得书写数值。

## 6. 问题分级与判定标准

### 6.1 分级

| 级别 | 定义 |
|---|---|
| P0 | 天球方向、坐标映射或科学正确性错误（如银河整体反转、银心出现在相反方位、银河与恒星反向运动） |
| P1 | 明显影响真实星空观感（如大面积发灰、银河压过恒星、明显接缝、卡顿影响可用） |
| P2 | 细节质量、纹理、性能优化类（如高 FOV 块状、轻微掉帧、光晕偏大） |
| P3 | 非必要视觉增强（如更细腻的尘埃带、额外的银河 HDR 处理） |

**未实际观察到的问题不得登记为缺陷。**

### 6.2 结论

| 结论 | 条件 |
|---|---|
| PASS | 无 P0；无影响观感的 P1；P2 少量且不影响主要使用；视场/地点/时间变化正常；长时间运行无明显异常 |
| CONDITIONAL PASS | 无 P0；有少量 P1 且有明确限制条件或可接受临时处理；不影响天球方向正确性；遗留问题已登记 |
| FAIL | 出现任一：天球方向错误、坐标映射错误、银河主体明显反转/错位、银河与恒星不合理相对运动、多个 P1 严重影响观感或可用性、长时间运行明显异常 |

标记为 `BLOCKED` / `NOT TESTED` 的项目**不得计入 PASS 依据**。

## 7. 性能与客观观测方法（只读，不改任何文件）

### 7.1 应用自带只读读数（DevTools 控制台粘贴）

```js
// 1) 背景模块统计：纹理规格、重建次数、上次耗时、栅格尺寸
window.SkyBackground.stats();
```

关注字段：
- `texture` 应为 `{w:512, h:256, bytes:262144}`
- `rasterW/rasterH` 应为 160（大画布）或 128
- `skyBuilds` 随改时间/地点增长；静止时应稳定
- `rasterBuilds` 随相机/视场变化增长
- `lastSkyMs / lastRasterMs / lastDrawMs`：**这是 JS 侧耗时，不是帧率**

```js
// 2) 应用自身性能计数
window.__astrum.perf();
```

关注 `sky.calls / last / avg`（`drawSky` 整体 JS 耗时）、`model.key` 与 `model.built`（是否在重复构建模型）。

```js
// 3) 模块版本（冻结基线核对）
window.__astrum.skyModules();
```

应返回 `viewModel: '1.1.0'`、`renderer: '1.2.0'`、`layers: '1.0.0'`。

### 7.2 银心方向与亮度的客观读数（可选，只读）

在固定测试场景下（例：39.9042, 116.4074, UTC+8, 2026-06-01 21:30），打开全屏星图后粘贴：

```js
(function () {
  var A = window.Astro, S = window.SkyVM;
  var cv = document.getElementById('viewerCanvas');
  var m = cv._meta || {};                      // 上次绘制的 yaw/pitch/fov
  var lat = 39.9042, lon = 116.4074, tz = 8;   // 修改地点时同步改这里
  var jd = A.fromLocal(2026, 6, 1, 21, 30, tz);
  var GC = { ra: 17.7610, dec: -28.9362 };     // 银心 J2000
  var aa = A.altAz(GC.ra, GC.dec, jd, lat, lon);
  var vm = S.build(jd, lat, lon, {
    width: cv.width, height: cv.height,
    yaw: m.yaw, pitch: m.pitch, fov: m.fov
  });
  var q = vm.project(aa.az, aa.alt);
  if (!q) { console.log('银心不在视野内 alt=' + aa.alt.toFixed(1), 'az=' + aa.az.toFixed(1)); return; }
  var g = cv.getContext('2d');
  var box = g.getImageData(Math.max(0, q.x - 10), Math.max(0, q.y - 10), 21, 21).data;
  var sum = 0, n = 0;
  for (var i = 0; i < box.length; i += 4) { sum += 0.299 * box[i] + 0.587 * box[i + 1] + 0.114 * box[i + 2]; n++; }
  console.log('银心 alt=' + aa.alt.toFixed(1) + '° az=' + aa.az.toFixed(1) +
    '° 屏幕(' + Math.round(q.x) + ',' + Math.round(q.y) + ') 邻域平均亮度=' + (sum / n).toFixed(1));
})();
```

用途：
- 验证「银心出现在其真实方位对应的屏幕位置」，而不是只看「屏幕中央有亮斑」；
- 给出可比较的亮度数值（邻域平均），用于跨视场/跨地点横向对比。

用法约束：
- 只读：不写文件、不改参数、不写 Canvas 以外的状态；
- 会调用 `SkyVM.build`，与主界面同参数时为缓存命中；若参数不同会替换模块内模型缓存（**只影响下一次重绘 20–30ms，不改变画面**）；
- 结果只能作为**辅助证据**，最终判定仍以人眼观察为准。

### 7.3 帧率与内存

- 帧率：DevTools → Command Menu（Ctrl+Shift+P）→ 输入 `frame` → 打开 **Frame Rendering Stats**（浏览器自带 FPS 计），或 Performance 面板录制 10 秒滚动。
- 内存：`Shift+Esc` Task Manager 观察该标签页内存列；或 Memory 面板取 0/10/20 分钟三次快照对比。
- 以上均为浏览器/系统读数，**不是应用自证**，允许记录为客观参考。
