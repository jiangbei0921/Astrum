## 1. 设计目标

1. 原有 12 套件与 V1-V1.3 测试全部进入 CI，不静默跳过。
2. 静态、离线、网络、构建分层，失败能直接定位。
3. 网络测试独立，外部限流/超时不被当作代码失败，也不使用 Mock 冒充 REAL。
4. 发布 CI 不依赖网络，测试通过后才允许 Pages 部署。
5. 旧测试断言不改、标准不降。

## 2. Workflow 结构

### 2.1 `test.yml`（发布门禁）

| Job | 运行环境 | 内容 |
|---|---|---|
| `static` | ubuntu-latest / Node 22 | 全 JS 语法检查、CSP hash、standalone、`_site`、daily、部署静态检查、csptest、i18n、Workflow 配置检查、构建产物一致性 |
| `offline-core` | ubuntu-latest / Node 22 | research、task、p0-03、control、b8、v1b、v1c、v1d(offline)、v1-e2e(offline)、V1.1 routing/compat/e2e(offline)、V1.2 五套件 + simbad(offline)、V1.3 五套件 |
| `offline-browser` | ubuntu-latest / Node 22 + Chrome | selftest(file://)、store、skill、consistency、a11y、rail、settings、ctx-isolation、v1-1-browser、v1-4-pages-test |

触发：`push main`、`pull_request`、`workflow_dispatch`。并发按分支取消旧运行。

### 2.2 `network.yml`（真实网络，独立）

触发：每周一 UTC 03:00（北京 11:00）+ 手动。**不参与 push/PR 门禁**。

运行 `tools/v1-4-network-ci.js`，逐套件判断：

| 结果 | 条件 | 退出码 |
|---|---|---|
| PASS | 套件退出码 0 | 0 |
| NETWORK_UNAVAILABLE | 套件失败，且其**全部**依赖主机探测不可达/非 2xx/3xx | 0 |
| FAIL | 套件失败，但至少一个依赖主机可达（部分不可达会写入原因） | 1 |

主机探测覆盖：arXiv、export.arxiv.org、OpenAlex、Semantic Scholar、SIMBAD、raw.githubusercontent.com、Wikipedia。探测只决定分类，不替代套件断言。

覆盖套件：

- `v1-2-simbad-test.js`（SIMBAD REAL）
- `v1d-test.js`（SIMBAD / FITS / 论文检索 REAL）
- `v1-e2e-test.js`（V1 端到端 REAL）
- `v1-1-e2e-test.js`（V1.1 端到端 REAL）
- `v1-3-paper-fulltext-test.js`（arXiv PDF REAL）
- `v1-3-paper-e2e-test.js`（论文全链路 REAL）
- `research-test.js --online`（在线检索 REAL）

### 2.3 `pages.yml`（发布）

- `workflow_run` 监听 `test` 成功，仅 `main`；也支持手动 `workflow_dispatch`。
- checkout 到 `test` 对应的 `head_sha`。
- `node tools/build-pages.js` 生成 `_site`。
- `actions/configure-pages@v5`（`enablement: true`）+ `upload-pages-artifact@v3` + `deploy-pages@v4`。
- 权限：`contents: read`、`pages: write`、`id-token: write`。
- 无 Git 写操作。

## 4. 环境一致性

| 项 | 本地 | CI |
|---|---|---|
| Node | 24.19.0 | 22 |
| OS | Windows 11 10.0.26300 | ubuntu-latest |
| Chrome | 156.0.8078.79 | Runner 预装（步骤先确认） |
| 时区 | Asia/Shanghai | UTC |
| 路径大小写 | 不敏感 | 敏感 |

针对性措施：

- `build-pages.js` 逐段精确大小写比对；
- 所有引用文件名为小写；
- 不使用 Windows 专用路径；浏览器查找包含 Linux 候选；
- `selftest` 已兼容 Linux `file://` 路径；
- 测试临时目录统一用 `os.tmpdir()`；
- `v1-4-network-ci.js` 使用 Node 内置 `https`，不依赖代理工具；
- 零 npm 安装。

**本地 Node 24 与 CI Node 22 的差异仍存在**，未在 Node 22 容器内实跑；由远端 CI 最终确认（DEFERRED）。

## 7. 失败排查指引

| 失败位置 | 先看 |
|---|---|
| `static` | 语法输出、CSP hash、`git status`（构建产物是否未提交） |
| `offline-core` | 套件名即层级；p0-03 的 `RESULT` 与 `diffBytes` |
| `offline-browser` | Chrome 是否可执行；driver 日志；`--no-sandbox` |
| `network` | 汇总表：NETWORK_UNAVAILABLE 看主机探测；FAIL 看断言 |
| `pages` | `configure-pages` 权限、Pages Source 是否 GitHub Actions、`_site` 构建日志 |
