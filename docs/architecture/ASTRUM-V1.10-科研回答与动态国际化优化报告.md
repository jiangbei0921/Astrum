## 3. 科研回答整合机制

流程：

1. 任务执行结果进入 `AstroComposeAdapter`，生成 Report/Claims/Evidence。
2. `AstroAnswerComposer.finalize` 统一整理：
   - 去重：重复 verdict、重复 evidence item、重复 followup；
   - 合并：多个 evidence 章节按 label+value 合并为一节；
   - 排序：verdict → analysis → evidence → conclusions → conflicts → limitations → sources；
   - 生成 analysis：核心结论、论文来源、关键证据、差异、限制；
   - 质量检查：Claim→Evidence 引用、无来源数字、无证据确定性措辞、限制声明。
3. 前端只负责渲染整理后的章节；不再把各 Agent 输出直接平铺。
4. 云端模型表述进入 `analysis` 首段，作为“组织与解释”，不进入 Evidence。

模型表述与证据分离：

- 模型只接收 facts + 本轮 evidence + para；不得新增数字/名称/年代/结论。
- `meta.cloudExpression` 记录模型调用状态；失败保留证据链结论。
- 模型文本不写回 Evidence、Claim 或 evidenceRefs。

## 4. Muse 优化前后对比

| 维度 | V1.9 | V1.10 |
|---|---|---|
| 最终回答 | 各 Agent sections 直接平铺，云端表述作为孤立 `model` 卡片 | 由 composer 统一组织为“结论 → 综合研判 → 证据 → 结论分级 → 差异 → 限制 → 来源” |
| 回答结构 | 基本固定 | A 事实 / B 原理 / C 数据 / D 多论文对比 / E 综合科研，按问题复杂度选择 |
| 重复信息 | 同一证据/结论可能多处出现 | 按内容归一去重；重复 verdict 只保留一个 |
| 逻辑衔接 | 段落可能跳跃 | analysis 段落使用“在此基础上 / 与此相关 / 需要注意的是 / 综合来看”等显式关系 |
| 证据不足 | 可能只写“没有依据” | 明确“系统内置知识未命中，尚未完成外部核验”，并列出缺口/限制 |
| 模型表述 | 无法自动检查数字与引用 | 模型文本进入质量检查；无来源数字与确定性措辞写入 `meta.quality` |
| Agent 细节 | 占据阅读区 | 保留在可折叠研究执行报告中；主阅读区先给结论与分析 |

## 5. 知识来源分类与路由规则

四类来源：

| 类型 | 判定 | 展示 |
|---|---|---|
| 用户资料 | 仅当本轮确实有用户上传附件 | “用户上传资料 · 已读取”；没有附件时显示“无用户资料”，不虚构 |
| 系统内置知识 | `data/knowledge.js`、星表、本地规则 | “系统内置知识 · 有命中/未命中” |
| 外部科研资料 | 真实调用 OpenAlex/arXiv/SIMBAD/Crossref 等 | 只按 `state.steps` 真实状态显示成功/部分失败/不可用/未调用 |
| 模型已有知识 | Provider 模型输出 | “模型已有知识 · 已使用/不可用”，并说明不构成新证据 |

路由：

| 问题类型 | 决策 |
|---|---|
| 基础概念（什么是光年/原理） | 允许模型解释 + 系统知识；不强制外部检索 |
| 特定天体参数（目标有内置条目） | 系统知识/行星参数优先，作为基础事实 |
| 特定天体参数（目标无内置条目） | 进入外部检索（Planner T-E，SIMBAD/论文） |
| 最新科研进展 | 必须外部检索，不因本地未命中直接返回“无依据” |
| 多论文比较 | 必须外部论文检索，再比较数据/方法/结论 |
| 用户上传资料分析 | 优先读取用户资料；没有上传就明确说明 |

工具真实性：

- 只读取 `state.steps` / `research` 的真实状态；未调用显示“未调用”。
- 失败工具显示 `tool + 失败原因`；不把失败写成成功。
- 没有实际调用的来源不会出现在“已调用”列表。

## 6. 本地知识库未命中后的处理

修复前：

> 本地没有这个问题的依据。

修复后：

> 系统内置知识中暂未找到相关内容，尚未完成外部科研资料核验。

同时：

- 需要外部检索的问题由 Router/Planner 进入 T-E/T-F，不落到旧兜底。
- 外部检索失败时显示“部分科研数据源暂时不可用，本次结果可能不完整”。
- 外部检索为空时显示“已查询当前可用的外部科研来源，但暂未获得足够的相关证据”。
- 只有模型解释时显示“模型基于已有知识提供的背景解释，尚未通过本次科研检索核验”。

P0-03 基线：20 问中仅第 15 问（unknown）文案按设计变化，其余 19 问 sections 逐字节不变。

## 7. 动态论文翻译机制

- 入口：`AstroContentI18n`，所有论文卡片（每日前沿、研究论文列表、论文类 Evidence）共用。
- 语言：读取 `I18N.current()`；中文模式下翻译，英文模式直接原文。
- 翻译：`Sources.generate({task:'translate', text, kind, maxChars})`，使用现有 Provider/Control 路径，不新增翻译 Agent。
- 缓存键：`版本 + 目标语言 + 类型 + 原文内容哈希 + 原文长度`。
- 缓存位置：`localStorage`，最多 240 条；失败短时冷却 60 秒，失败不写缓存。
- 按需：研究执行报告折叠时只翻译可见论文；展开后再补译；每日前沿仅在用户打开面板时渲染。
- 回退：Provider 不可用/超时/空响应/数值丢失时保留英文原文，不显示空白。
- 数值校验：带单位的测量值与小数必须保留；M13/NGC/arXiv 等标识编号允许按语言习惯省略。

## 10. 翻译失败回退

| 场景 | 行为 |
|---|---|
| 无 Provider / 无密钥 | 返回 `provider_unavailable`，显示英文原文 |
| HTTP 失败/超时 | 返回 `translate_failed`，短时冷却，显示英文原文 |
| 空译文 | 视为失败，不显示空白 |
| 数值丢失 | `number_mismatch`，拒绝该译文，保留原文 |
| 语言切换 | 不重新执行科研任务、不重新检索；仅展示层切换 |
| Provider 恢复 | 下一次可见内容按需重试；成功结果写入缓存 |
