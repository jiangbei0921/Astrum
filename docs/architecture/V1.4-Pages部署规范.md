## 3. Pages 设置前提

仓库 **Settings → Pages**：

- Source 必须为 **GitHub Actions**。
- 若组织策略禁止 Actions 发布，需要管理员先启用。
- `pages.yml` 中的 `actions/configure-pages@v5` 带 `enablement: true`，可尝试自动启用；但无法绕过组织级策略。

未满足该前提时，`deploy-pages` 会失败。当前因无 GitHub 授权，未能确认远端 Pages Source，登记 DEFERRED。

## 4. 资源路径规则

| 类型 | 规则 |
|---|---|
| CSS | `assets/app.css` |
| data | `data/*.js` |
| core | `core/*.js` |
| 图片 | 无外部图片；favicon 为 data URI |
| 字体 | 系统字体 |
| 外部 API | 使用绝对 https URL，列入 CSP `connect-src` |
| 内部链接 | `./`、`privacy.html`、`assets/...` |

禁止：

- 以 `/` 开头的站点绝对路径；
- 盘符或 `file:///`；
- 在运行时拼接 `location.origin`；
- 动态 `import()`；
- 新增后端或代理依赖。

本地 `v1-4-pages-test.js` 以 `/Astrum/` 前缀挂载 `_site/`，验证 52 个资源均 200，`tools/docs/dev` 均 404，根路径 `/` 不冒充站点。

## 5. CSP 与 CORS

- GitHub Pages 不注入 CSP 响应头；`index.html` 的 `meta` CSP 是唯一策略。
- 未放宽 CSP：无 `unsafe-eval`，无 `*`，`object-src 'none'`。
- 外部数据源按需列入 `connect-src`：OpenAlex、Semantic Scholar、SIMBAD（含 Harvard 镜像）、arXiv（含 export）、NASA、天气/地理等。
- PDF 下载依赖 arXiv 的 `access-control-allow-origin: *`；出版社反爬仍按失败记录。
- 站点子路径不改变 CORS：请求的是外部绝对 URL，与部署域无关。

---

## 6. 缓存与版本核对

- GitHub Pages 可能缓存旧资源；部署后用 `version.json` 核对：
  - `commit` 是否等于目标提交；
  - `buildTime` 是否为新一次构建；
  - `deployEnv` 是否为 `github-actions`。
- 本地测试服务器对 `_site` 使用 `Cache-Control: no-store`，避免测试命中旧内容。
- 页面自身不使用 service worker，不做离线缓存。

## 7. 发布流程

```
push main
  → test.yml（static / offline-core / offline-browser）
      → 成功
          → pages.yml（workflow_run）
              → checkout head_sha
              → build-pages.js
              → configure-pages
              → upload-pages-artifact
              → deploy-pages
                  → https://jiangbei0921.github.io/Astrum/
```

手动重发：

- Actions → `pages` → Run workflow（选择 main）。
- 仍需 Pages Source = GitHub Actions。

## 8. 失败处理

| 失败 | 现象 | 处理 |
|---|---|---|
| 构建失败 | `build-pages.js` 退出 1，常见于引用缺失/大小写/密钥扫描 | 本地复现后修复源码，不用手工改 `_site` |
| 测试失败 | `pages` 不触发（workflow_run 条件不满足） | 先修 `test.yml` 失败项 |
| `configure-pages` 失败 | 权限或 Pages 未启用 | 检查 Settings → Pages 与组织策略 |
| `deploy-pages` 失败 | artifact 缺失/权限不足 | 重跑 build job；核对 `_site` 路径 |
| 资源 404 | 子路径或引用错误 | 本地跑 `v1-4-pages-test.js` |
| 外部 API 失败 | 页面提示 CSP/CORS/超时 | 不是部署错误；按网络 workflow 记录 |
| 旧版本残留 | `version.json` commit 不符 | 触发 pages 重新部署，核对 CDN 缓存 |

## 9. 回滚

优先使用 GitHub 原生能力，不自建发布服务器：

1. **重新部署旧提交**：Actions → `pages` → 手动运行并 checkout 旧 SHA（需 workflow 支持输入或临时改 ref；当前实现取 `github.sha`，建议用 `git revert` 后再触发）。
2. **回滚提交**：在授权后对目标提交执行 `git revert`，push 到 main；`test` 通过后自动部署回滚版本。
3. **紧急下线**：Settings → Pages → 取消发布（需仓库管理员权限）。

回滚同样需要 Push 授权；未授权时不能执行。

## 10. 安全

- 发布产物不含任何真实 API Key；`sources.js` 只包含用户配置入口。
- 用户 API Key 仅存浏览器 localStorage，不进入构建。
- 构建器扫描 `sk-`、`ghp_`、`github_pat_`、`AIza`、`AKIA`、Slack、私钥块、Bearer 长凭据；命中即停止并只打印掩码。
- 发布产物不含 `docs/tools/dev/worker`，避免测试脚本与本地路径公开。
- 外链渲染仍只保留 `http(s)` 且 `rel="noopener noreferrer"`（V1.3 已实现）。
