# ASTRUM V1.6 可选优化评估报告

> 日期：2026-11-01
> 依据：原始 V1.4—V1.6 工程计划（用户提供的执行计划）§六
> 结论：**V1.6 不启动（NOT STARTED）**；原计划 gate 未满足，未新增 V1.6 代码。

---

## 1. 原计划对 V1.6 的定义

V1.6 不是必须新增的功能版本，而是根据 V1.4 / V1.5 的真实结果，决定是否解决剩余问题。

正式启动必须同时满足：

1. V1.4 已完成线上验收；
2. V1.5 已完成稳定性验收；
3. 存在明确的实际问题；
4. 有具体改进目标；
5. 有可验证的验收指标。

两个候选方向：

- P1：云模型表达统一（输出协议、校验、Evidence 引用、降级）；
- P2：复杂 PDF（双栏、公式、表格、图注、扫描件、OCR、参考文献）。

---

## 2. 当前 gate 状态

| 条件 | 实际 | 是否满足 |
|---|---|---|
| V1.4 线上验收 | Pages 仍为 legacy branch，V1.4 未部署；线上旧版 | **否** |
| V1.5 稳定性验收 | 1m 冒烟通过；30m/1h/3h 未跑 | **否（长时未完成）** |
| 明确实际问题 | 无生产性能数据；复杂 PDF 仅有已知限制 | **否** |
| 具体改进目标 | 未定义 OCR/公式/表格指标 | **否** |
| 可验证验收指标 | 未建立 | **否** |

因此不能按原计划启动 V1.6。

---

## 3. P1 云模型表达统一评估

现有基础：

- V1.5 已将 app 的模型调用统一到 `AstroControlBridge.modelGenerate`；
- `Sources` 支持外部 AbortSignal/超时；
- 研究答案保留 Evidence/Claims/Report，模型只追加表述；
- 失败/取消不伪造成成功；
- 已有 429/超时/鉴权/取消分类测试。

尚未完成（且不应在本轮擅自扩大）：

- 统一 JSON 输出协议；
- 结构化输出校验器；
- 真实 provider 密钥验证；
- 多模型协作/路由；
- 输出质量评分。

这些属于 V1.6 P1 的正式范围；在 gate 未满足前不实现。当前 bridge 已能作为后续基础，不在本轮重写。

---

## 4. P2 复杂 PDF 评估

现有能力：

- 零依赖 `pdf-text`：Flate 流、对象流、页面树/内容流、Tj/TJ、章节、分块；
- 本机 PDF 附件：页数/章节/分块/fulltext Evidence；
- 明确失败：`not_pdf / pdf_too_large / pdf_no_text / pdf_parse_error / timeout / cancelled`；
- 页码不可靠时 `null`，不伪造。

已知限制：

- 扫描件无文本；
- CID 字体缺 ToUnicode；
- 双栏顺序、公式、表格、图注、复杂参考文献有限；
- 不含 OCR。

原计划要求先分析真实错误案例，再决定是否引入外部解析服务/依赖；不得破坏纯静态、file://、Pages。当前没有真实错误样本集和可验证指标，因此不引入 OCR/第三方服务，不宣称完全解析。

---

## 5. 结论

- **V1.6：NOT STARTED**（原计划 gate 未满足）；
- 已完成的 V1.5 云模型 Bridge 与 PDF 附件链路作为 V1.6 的现有基础，不重复开发；
- 后续启动顺序：先完成 V1.4 线上验收 + V1.5 30m/1h/3h 长时 + 收集真实问题/指标，再决定 P1/P2；
- 本轮未新增 V1.6 功能，未修改架构边界。

状态：**DEFERRED（可选版本，非本轮必需）**。
