# ASTRUM V1.4 架构更新

> 日期：2026-11-01
> 主题：运行架构不变，新增“可审计的静态发布层”
> 结论：V1-V1.3 的 Router / Planner / Control / Evidence 链路未改动；V1.4 只增加构建、CI 与 Pages 发布外围。

---

## 1. 边界

V1.4 **没有**修改：

- `ask()` / `buildAnswer()` / `compose*` / `toSections()` / `detectIntent()`；
- 七种任务模板、13 个 Agent、TRACE_ORDER、Critic 五项、Qty；
- Evidence / Claims / Reducer / Report 的字段与判定；
- 运行时资源加载方式（仍为相对路径的 `<script src>`、无动态 import、无后端）。

V1.4 **新增**：

- 发布目录构建器 `tools/build-pages.js`；
- 本地 Pages 等价测试 `tools/v1-4-pages-test.js`；
- 网络套件分类运行器 `tools/v1-4-network-ci.js`；
- CI 配置检查 `tools/v1-4-ci-test.js`；
- 三个 workflow：`test.yml`（三层 CI）、`network.yml`（真实网络）、`pages.yml`（Pages 发布）；
- `_site/version.json` 版本元数据。

---

## 2. 部署拓扑

```
源码（唯一事实来源）
  index.html / privacy.html / assets/ / core/ / data/
        │
        ├─ tools/build-standalone.js ──→ astrum-standalone.html（单文件，gitignore）
        │
        └─ tools/build-pages.js
              ├─ 白名单复制
              ├─ 计算资源引用 / 大小写校验
              ├─ 密钥与绝对路径扫描
              ├─ 写入 version.json
              └─→ _site/（gitignore）
                    │
                    ├─ 本地 HTTP 子路径测试（tools/v1-4-pages-test.js）
                    └─ GitHub Actions artifact → GitHub Pages
```

`_site/` 是唯一允许发布的目录；仓库根目录、`tools/`、`docs/`、`dev/`、`worker/` 不进入站点。

---

## 3. 发布目录契约

顶层白名单：

```
.nojekyll
assets/
core/
data/
index.html
privacy.html
version.json
```

校验规则：

1. `index.html` 中每个 `<script src>` 必须匹配 `core/*.js` 或 `data/*.js`；
2. 样式必须匹配 `assets/*.css`；
3. 不允许 `../`、盘符、`http(s):`、`data:` 资源引用；
4. 逐段用 `readdir` 原始文件名比对，防止 Windows 大小写不敏感掩盖 Linux 失败；
5. 发布目录不允许符号链接；
6. 扫描真实密钥形态（`sk-`、`ghp_`、`github_pat_`、`AIza`、`AKIA`、Slack token、私钥块、Bearer 长凭据）；
7. 扫描本地绝对路径（`C:\Users\`、`C:\Projects\`、`file:///C:`、`/home/`、`/Users/`）；
8. 发现命中即停止构建，只输出掩码片段，不在日志中展示完整密钥。

## 4. 版本元数据

`_site/version.json` 字段：

```json
{
  "app": "ASTRUM",
  "appVersion": "4.8",
  "releaseVersion": "V1.4",
  "featureVersion": "V1.3",
  "buildTime": "ISO-8601",
  "buildMode": "static-pages",
  "deployEnv": "github-actions | local",
  "repository": "owner/repo",
  "commit": "40/7 位",
  "dirty": true,
  "branch": "main",
  "runId": "GitHub Run ID | null",
  "features": ["V1", "V1.1", "V1.2", "V1.3", "V1.4"]
}
```

- `commit` 优先取 `BUILD_COMMIT` / `GITHUB_SHA`，本地回退 `git rev-parse HEAD`；
- `dirty` 取 `git status --porcelain`；本地未提交时如实标 `true`，不冒充正式版本；
- `version.json` 只存在于 `_site/`，不进入源码提交。

## 5. CI 分层

| 层 | Workflow / Job | 内容 | 网络 |
|---|---|---|---|
| 静态 | `test.yml / static` | 语法、CSP hash、standalone、Pages 构建、daily、部署静态检查、csptest、i18n、配置检查 | 否 |
| 离线核心 | `test.yml / offline-core` | 原有非浏览器套件 + V1-V1.3 全部离线套件 | 否 |
| 离线浏览器 | `test.yml / offline-browser` | Chrome + file://、IDB、布局、无障碍、V1.1 浏览器、Pages 子路径 | 否 |
| 真实网络 | `network.yml` | SIMBAD、arXiv、OpenAlex、FITS、论文全文、在线检索 | 是 |
| 发布 | `pages.yml` | 白名单构建 → artifact → Pages | 否 |

`pages.yml` 由 `test` 成功后的 `workflow_run` 触发，避免“测试未过就部署”。

## 6. 部署环境差异处理

| 差异 | 处理 |
|---|---|
| 仓库子路径 `/Astrum/` | 全部资源相对路径；本地 HTTP 测试按 `/Astrum/` 前缀挂载 |
| Linux 大小写 | 构建器逐段精确比对；测试文件均小写命名 |
| Pages 无 CSP 响应头 | 仍由 `index.html` 的 `meta` CSP 生效；未放宽策略 |
| `file://` 与 HTTP | 两套路径分别由 selftest / v1-4-pages-test 覆盖 |
| Chrome 沙箱 | 浏览器套件统一 `--no-sandbox`（CI 容器） |
| 外部 API 限流 | 网络 workflow 独立；运行器区分 NETWORK_UNAVAILABLE 与 FAIL |
| 缓存 | `_site/version.json` 作为部署核对依据；本地测试 `no-store` |

## 7. 兼容性

- 发布层只读取源码，不参与运行时分支；L1/L2-L4、Control、Evidence 链路不变。
- 旧 12 套件与 V1.1/V1.2/V1.3 测试断言未修改。
- `astrum-standalone.html` 构建仍由原脚本负责，`_site` 不复制它。
- 不引入 npm 依赖、PDF.js、Python/Node 后端、数据库、事件总线或第八种模板。
