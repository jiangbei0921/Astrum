## 7. 是否可以安全进行 rebase

**可以，但必须满足条件并获授权：**

1. 先获得明确 Git 写操作授权；
2. 先 `git fetch origin`，确认 `origin/main = 8e7e9`；
3. 先把本地 13 个修改 + 79 个新增提交为一个本地提交（或按需拆分）；
4. 再 `git rebase origin/main`；
5. rebase 后重新构建 `_site`/standalone，并重跑关键测试；
6. 最后 push。

理由：

- 远端是本地 HEAD 的直接子提交；
- 远端只改 `data/daily.js`；
- 本地 `data/daily.js` 未修改；
- 无重命名、删除或同文件改动。

不建议在 dirty 工作区直接 `git pull --rebase`；应先提交本地变更，避免 autostash 带来的额外风险。
