# ASTRUM V2-SKY · 阶段 2 任务清单

- 前置：`V2-SKY-阶段2-技术规格.md`、`V2-SKY-阶段2-数据来源与许可.md` 获批
- 执行原则：依赖顺序执行；同一文件不并行改；每完成一个任务先跑对应测试再进入下一个
- 阶段 2 只做恒星与银河，不触碰行星、地平线、DSO 符号、业务链路

## 里程碑

| 里程碑 | 内容 | 出口条件 |
| --- | --- | --- |
| M0 | 决策门与原始数据准备 | 许可/商用、图片方案、构建脚本改动、逆变换位置全部确认 |
| M1 | L1/L2 视觉星表与视图模型 | 数据测试 + 坐标一致性测试通过 |
| M2 | 恒星渲染升级 | 颜色/亮度/LOD/命中回归通过 |
| M3 | 银河背景升级 | 参考点对齐 + 降级链通过 |
| M4 | 构建、性能与全量回归 | standalone/Pages/file:// + 旧测试全绿 |

## 任务

### T2-00 决策门（阻塞）

- 目标：确认四个会改变实现路径的问题。
- 前置：无。
- 内容：
  1. 项目是否商用 → 决定 L2 是否可用 Gaia/Hipparcos/Tycho（均为 CC BY-NC 3.0 IGO）。
  2. 银河底图选 NASA SVS（公有领域，赤道/银道版）还是 ESO/S. Brunier（CC BY 4.0）。
  3. 是否允许修改 `tools/build-standalone.js` 以把底图内联为 data URI。
  4. 是否允许在 `core/sky-viewmodel.js` 新增 `altAzToEq()`（不改 `core/astro.js`）。
- 涉及文件：无（只产出决策记录）。
- 验收：四项均有明确“是/否”，写入交付文档。
- 风险：未确认就编码，可能返工或引入许可问题。

### T2-01 离线星表数据管线

- 目标：建立可重复的“原始星表 → 项目数据文件”脚本。
- 前置：T2-00。
- 涉及文件：新增 `tools/build-star-data.js`、`tools/fixtures/star-raw/README.md`（原始文件不进仓库）。
- 内容：
  - 读取本地原始 BSC5P（L1）与 Hipparcos-2/Tycho-2（L2）导出文件；
  - 校验必要字段、坐标范围、星等范围；
  - 去重、按 V 星等截断、生成 L0 匹配；
  - 量化打包为 base64，写出 `data/sky-stars-l1.js` / `l2.js` 与生成报告。
- 验收：脚本可重复运行，输出文件哈希稳定；生成报告包含总数/截断数/缺失 B-V 数/缺失光谱数/L0 匹配数。
- 测试：`node tools/build-star-data.js --check`（只校验，不写文件）。
- 风险：原始文件格式差异、字段单位不一致（尤其 pmRA 的 cosδ 约定）。

### T2-02 生成 L1/L2 数据文件

- 目标：产出可发布的静态数据。
- 前置：T2-01。
- 涉及文件：`data/sky-stars-l1.js`、`data/sky-stars-l2.js`（自动生成）。
- 验收：L1 ≈ 9,096 颗；L2 ≈ 20,000–25,000 颗；文件 ≤ 250 KB / 500 KB；`meta.license` 与真实来源一致。
- 测试：`node --check`；`tools/v2-sky-02-test.js` 的数据结构断言。
- 风险：文件过大影响首屏；截断阈值需实测调整。

### T2-03 星表适配模块

- 目标：加载、解码、标准化、索引，不接触绘制。
- 前置：T2-02。
- 涉及文件：新增 `core/sky-star-data.js`。
- 内容：实现技术规格 §5.2 接口；缺失字段保持 `null`；`l0Key` 映射；`loadL2()` 动态注入。
- 验收：`records('l1')` 返回只读标准化记录；`stats()` 数字与生成报告一致。
- 测试：字段完整率、id 唯一、缺失字段计数、L0 匹配率。
- 风险：解码耗时；需缓存解码结果，避免重复构造对象。

### T2-04 视图模型接入与逆变换

- 目标：把视觉星表接入 `SkyVM.model/build`，并新增银河所需的逆变换。
- 前置：T2-03。
- 涉及文件：`core/sky-viewmodel.js`。
- 内容：
  - `model()` 合并 L0 + L1（+L2），预存 `ux/uy/uz`；
  - 缓存键加入数据版本；
  - `altAzToEq(alt,az,jd,lat,lon)`；
  - 保持旧 `model()` 返回结构兼容（`stars` 数组仍含 L0 记录）。
- 验收：L0 132 条坐标与阶段 1 完全一致；新增恒星不修改 `CATALOG`；`altAzToEq` 往返 ≤ 1e-9。
- 测试：`tools/v2-sky-02-test.js` 的坐标/缓存/逆变换断言；阶段 1 `v2-sky-01-test.js` 全绿。
- 风险：模型对象增大；缓存键遗漏导致热更新后旧数据。

### T2-05 颜色、亮度与 LOD

- 目标：真实数据驱动的视觉参数。
- 前置：T2-04。
- 涉及文件：`core/sky-viewmodel.js`。
- 内容：`colorForBV` / `colorForSpectral` / 33 档色表；`f^(1/4)` 尺寸；alpha 分级；视场星等极限；锥裁剪；12,000 上限。
- 验收：无 B-V 的星 `colorSource` 正确；不生成 `bv` 字段；不同 fov 的可见数量符合 §3.3 表。
- 测试：颜色映射单元测试（已知 B-V → 色相范围）；LOD 数量断言；30° 视场 ≥ 300 颗。
- 风险：颜色偏紫/偏红；需按 33 档表校准并截图确认。

### T2-06 恒星渲染升级

- 目标：颜色分桶、亮星光晕、替换随机星场。
- 前置：T2-05。
- 涉及文件：`core/sky-renderer.js`。
- 内容：7×5 桶；`hit:true` 才写 `_hits`；L1/L2 不产生命中；`starField()` 在非降级模式下不再绘制随机点。
- 验收：绘制顺序不变；命中只含 L0；点击 L1 空白区域不弹详情。
- 测试：阶段 1 的 L6/L7/L8 断言（需按新桶调整但不得弱化语义）；浏览器 B1–B7。
- 风险：绘制调用增加导致掉帧；需性能任务兜底。

### T2-07 命中与详情的兼容回归

- 目标：确认 `_hits/_bodies/_meta` 语义未变。
- 前置：T2-06。
- 涉及文件：无（测试为主）。
- 验收：土星可检索；L0 恒星详情字段完整；`_meta` 键集合不变；深链 `target=参宿四` 可定位。
- 测试：`v2-sky-02-browser-test.js` + `v2-sky-01-browser-test.js`。
- 风险：L1 星误入命中导致详情空白。

### T2-08 银河底图离线处理

- 目标：把公有领域底图转成项目可用、可内联的低对比资源。
- 前置：T2-00。
- 涉及文件：新增 `tools/build-milkyway-bg.js`、`assets/milkyway-2020-2048.jpg`。
- 内容：EXR/大图 → 2048×1024 JPEG（质量 78–85）；记录来源、版本、坐标取向、处理步骤；可选生成 12k 密度点 JS。
- 验收：图像坐标取向经参考点核对；文件 ≤ 300 KB；来源与许可写入文档。
- 测试：脚本可重复；输出哈希稳定。
- 风险：EXR 解码需要离线工具；坐标取向若判断错误会导致整夜错位。

### T2-09 银河背景模块

- 目标：底图加载、反投影栅格、缓存与释放。
- 前置：T2-08、T2-04。
- 涉及文件：新增 `core/sky-background.js`。
- 内容：`load/draw/ready/dispose/stats`；逆鱼眼采样；缓存上限 2；80–120 ms 去抖；降级链。
- 验收：银心/反银心/银北极/银南极方向对齐 ≤ 0.02°；关闭全屏后缓存释放。
- 测试：参考点投影测试；缺失图片时返回 `false`；缓存命中/失效测试。
- 风险：每帧三角运算过慢；必须实测栅格重建耗时并调分辨率。

### T2-10 渲染器接入银河背景

- 目标：底图 + 密度点场绘制，保留程序化降级。
- 前置：T2-09。
- 涉及文件：`core/sky-renderer.js`。
- 内容：`milkyWayImage()`；`layers.milkyWay` 同时控制底图与点场；绘制顺序不变；亮度上限。
- 验收：银河不遮挡恒星/星座线/标签；关闭图层后完全不绘制；降级链可用。
- 测试：浏览器截图对比 + L7 图层门控。
- 风险：背景过亮压过恒星；需按 alpha/亮度阈值调参。

### T2-11 standalone 图片内联

- 目标：保证单文件版银河不缺图。
- 前置：T2-08。
- 涉及文件：`tools/build-standalone.js`、`astrum-standalone.html`（生成产物）。
- 内容：构建时把底图替换为 `data:` URI；保持 CSP `img-src 'self' data: blob:` 兼容；体积预算检查。
- 验收：standalone 打开后银河正常；文件体积 < 4 MB；`selftest` 通过。
- 测试：`node tools/build-standalone.js` + `selftest`。
- 风险：体积超预算；data URI 过长导致构建脚本或编辑器卡顿。

### T2-12 脚本顺序与按需加载

- 目标：确定加载顺序与 L2 策略。
- 前置：T2-03。
- 涉及文件：`index.html`、`core/sky-star-data.js`。
- 内容：L1 静态；L2 懒加载（首次全屏或 fov<60°）；失败只降级不报错。
- 验收：`build-pages` 引用全部 200；`file://` 下动态 script 可用；无 CSP 违规。
- 测试：`v1-4-pages-test`、新增浏览器测试。
- 风险：动态注入脚本在 file:// 受限；需在 Chrome 中实测。

### T2-13 新增离线测试 `tools/v2-sky-02-test.js`

- 目标：数据、坐标、颜色、LOD、银河映射。
- 前置：T2-06、T2-09。
- 断言清单：
  - 数据字段完整率、id 唯一、坐标/星等范围、缺失字段计数；
  - L0 132 条与阶段 1 一致；
  - 逆变换 1,000 组往返 ≤ 1e-9；
  - B-V → 颜色范围（O/B 偏蓝、M 偏红）；
  - 光谱型降级不写回 `bv`；
  - 视场 LOD 数量与上限；
  - 银河参考点 5 组；
  - 图片缺失 → 降级返回 false。
- 验收：全部 PASS，退出码 0。
- 风险：断言过严导致调参反复；参考点容差按 §4.4。

### T2-14 新增浏览器测试 `tools/v2-sky-02-browser-test.js`

- 目标：真实渲染、颜色、密度、银河、降级、命中。
- 前置：T2-12。
- 场景：
  - 小星图/全屏/答案内星图三处均无错误；
  - 30° 视场恒星数 ≥ 300；
  - 恒星颜色不是单一冷白（至少 3 个色相桶非空）；
  - 银河在银心方向出现亮度峰（像素采样对比反银心）；
  - 图层开关生效；
  - 移除底图后降级且无未捕获错误；
  - 命中只含 L0，点击详情正常；
  - `file://` 与 `/Astrum/` 子路径各跑一次。
- 验收：全绿，CSP 违规 0。
- 风险：颜色/亮度的像素断言不稳定；阈值需留余量。

### T2-15 性能调优与全量回归

- 目标：达到阶段 2 预算并证明无回归。
- 前置：T2-14。
- 内容：按同机同浏览器记录冷加载、解析、model、build、首帧、拖动 FPS、缩放 FPS、内存；必要时下调 L2 规模或栅格分辨率。
- 验收：拖动 ≥ 30 FPS（普通设备基线）；旧测试全绿；性能报告写入交付文档。
- 测试：CI 全部离线与浏览器套件 + 新增两套。
- 风险：为达标牺牲视觉质量；禁止用降低天文精度换性能。
