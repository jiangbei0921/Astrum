## 六、本次：语言层扩到整页

### 6.1 之前的误解

上一版只做了「界面外壳 + 设置面板」，答案区（依据 / 评审 / 步骤）、
观测台、器材名仍是中文——那不是英文模式，是半英文。

### 6.2 做法：渲染后统一翻译

本项目大量用 HTML 字符串拼 DOM，逐个改渲染点必然漏。所以加了一层：

```
core/i18n.en-extra.js   第二批词表（约 120 条）
core/i18n.js -> applyDom(root)   遍历文本节点，整段精确匹配替换
core/app.js  -> MutationObserver 监听 #thread / #settingsBody / #agentList /
                                  #obsPanel / #threadList / #heroSlot
```

三条约束保证它安全：

1. **只匹配「整段文本等于词条」**，所以知识正文（长句）不会被翻，也不会中英混排；
2. **跳过 `SCRIPT / STYLE / NOSCRIPT / TEXTAREA / CODE / PRE`**——
   这条是踩坑后加的：TreeWalker 会走到 `<script>` 的文本，
   改写它等于改 JS 源码，表现为页面正常但行为坏掉；
3. **幂等**：英文值不是中文键，重复执行不会叠加，所以观察器不会自激。

### 6.3 覆盖率（实测）

英文模式下打开并询问「猎户座大星云是什么」，统计仍含中文的文本节点：

| 阶段 | 残留条目 |
| --- | --- |
| 修改前 | **225** |
| 加词表 + applyDom + 观察器 | **165** |
| 补来源名 / 状态标签 / 检索过程片段 | **159** |

剩下 159 条里，**界面骨架已基本清零**，绝大多数是：

- 知识条目的 `summary` / `pro` / `pop` 长句；
- 计算结果里的中文（`约 1344 光年`、`东（90°） · 高度 -8°`）；
- 由数据拼出的句子（`按 北京（Bortle 7）计算`）。

### 6.4 没有翻的部分，以及为什么不假装翻完

知识库有 160 条条目，每条含 `summary` + 5 组 `facts` + `observe` + `pro` + `pop`，
合计约 4 万汉字。这批内容**不适合现在机翻塞进去**：

- 它们带来源与核验日期，是「可复算」承诺的载体；
- 逐条翻译必须同时核对术语（H II 区 / 视星等 / 秒差距 / 共识等级），
  机翻会把 `H II 区` 译成 `H II region` 之外的东西，读起来像另一份资料；
- 一次性产出 4 万字的译文无法在本轮内校验。

**正确做法（建议下一轮）**：给条目加可选 `en` 字段族
（`summaryEn` / `factsEn` / `proEn` / `popEn`），渲染时缺字段回退中文，
按主题分批填（深空 → 恒星 → 太阳系 → 宇宙学），每批跑一致性测试。

### 6.5 顺带修的

- `applyStatic()` 增加 `[data-i18n-aria]`：英文模式下 `aria-label` 不再念中文；
- 搜索框的可访问名跟着语言切换。
