# ASTRUM 运行时契约（v3.0）

三个契约是 A（观测决策）/ B（可复现研究）/ C（技能自演化）三条线并行开发的前提。
**任何一条线改动数据格式，必须先改这份文档并同步 `core/runtime.js`。**

代码实现：`core/runtime.js`（`window.AstroRuntime`）

---

## 契约一：四档应答（Tier）

### 判定依据是「答案怎么来的」，不是「问题是什么」

| 档位 | key | 含义 | 判定条件 |
|---|---|---|---|
| **可算** | `compute` | 由本地星历/几何计算得出，可复算 | `meta.computed === true` 且存在数值型依据 |
| **可查** | `fetch` | 来自外部真实数据源，附查询与出处 | 存在 `web` 或 `synthesis` 证据章节 |
| **可释** | `infer` | 基于本地知识库的解释性结论 | 只有 `evidence`，无外部数据、无本地计算 |
| **未知** | `unknown` | 无可靠依据 | 以上都不成立 |

### 每一档的输出义务

| 档位 | 必须包含 | 禁止 |
|---|---|---|
| 可算 | 数值 + 计算参数 + 模型版本 | 只给数值不给参数 |
| 可查 | 数值 + 查询语句/接口 + 命中数 | 把「查不到」说成「不存在」 |
| 可释 | 结论 + 出处 + 置信度 | 把知识库解释包装成测量结果 |
| 未知 | **缺什么 + 怎么才能得到** | 用「知识库未收录」当挡箭牌后堆检索结果 |

### 未知档的硬性要求

必须回答三件事，缺一不可：

1. **缺什么**：具体缺哪类数据（原始光变曲线 / 某巡天数据库 / 实时气象）
2. **去哪拿**：给可执行的获取路径（库名、查询语句、链接）
3. **能不能退而求其次**：有没有次优答案（相邻时段、相似天体、原理性解释）

> 反例（当前实现）：`这个问题不在我当前可确证的范围内` + 列出四个「我可以回答的方向」。
> 正例：`这里需要 XX 巡天的原始光变曲线，本地没有。你可以在 ZTF 归档按坐标 05h35m 查，查询语句：SELECT ...；如果不方便，我可以先按已知的周期范围给一个粗估。`

## 契约二：执行记录（Exec）

### 每个 agent 跑完必须回填

```js
{
  agent:  'ephemeris',        // 必填，取自 AGENTS 的 id
  action: '计算升落与中天',     // 必填，动宾短语，面向用户
  tool:   'local-ephemeris',  // 必填，实际用的工具标识
  params: { ra, dec, jd },    // 可选，关键入参（脱敏、可复算）
  result: '22:14 升起 / 04:38 落下',  // 可选，一句话结果
  ok:     true,               // 必填，本次执行是否成功
  check:  {                   // 可选，自检结果
    name:   '单位与量级',
    passed: true,
    detail: '高度 42.3° 在 [-90, 90] 内'
  },
  ms: 3                       // 可选，耗时
}
```

### 失败判据（必须能用代码判定，不靠主观）

| Agent | 失败条件 |
|---|---|
| Ephemeris | 与 JPL Horizons 抽查偏差 > 1′ |
| Catalog | 查询报错被当成「天体不存在」 |
| Literature | 引用了不存在的 DOI |
| Critic | 单位缺失 / 量级偏差 > 1 个数量级 / 跨源分歧未标注 |
| Narrator | 出现事实白名单之外的数字或名称 |

### 展示规则

- trace 面板展示的是**真实执行记录**，不是流程标签
- `ok: false` 必须显式标出，不允许静默降级
- `check.passed: false` 必须带 `detail` 说明缺陷

## 契约三：数值表示（Qty）

### 结构

```js
{
  v:     1344,          // 数值，不带单位
  u:     'ly',          // 单位代码（见下表）
  err:   20,            // 误差，可为 null
  src:   'local',       // 来源标记：local | simbad | gaia | ads | user
  basis: '视差 2.42±0.06 mas · Bailer-Jones 2021'
}
```

### 单位代码表

| 代码 | 显示 | 用于 |
|---|---|---|
| `ly` | 光年 | 距离（科普） |
| `pc` | 秒差距 | 距离（学术） |
| `au` | AU | 行星际距离 |
| `km` | km | 天体尺度 |
| `mag` | 等 | 视星等 |
| `deg` | ° | 角度 |
| `arcmin` / `arcsec` | ′ / ″ | 小角 |
| `h` / `min` / `s` | 时/分/秒 | 时刻 |
| `K` | K | 温度 |
| `%` | % | 比例 |

### 显示规则

1. **单位必须跟在数值后**，不允许裸数字
2. **有误差就显示**，格式 `1344 ± 20 光年`
3. **时间必须带时区**：`22:14 (UTC+8)`，不允许只写 `22:14`
4. **角度必须带坐标系/历元**：`RA 05h35m17.3s (J2000)`
5. **不可复算的值必须标来源**，`src` 为空视为违反契约

### 反例

| 错误 | 问题 |
|---|---|
| `距离 1344` | 缺单位 |
| `22:14` | 缺时区 |
| `RA 83.82°` | 缺历元，且未给小时角写法 |
| `1344 光年（约）` | 用「约」代替误差，无法做区间比较 |

## 与现有代码的衔接

| 契约 | 落地位置 | 状态 |
|---|---|---|
| 四档应答 | `runtime.js` `classify()` + `app.js` 答案头部徽标 | 本轮完成 |
| 执行记录 | `agents.js` `step()` 升级为可携带 `tool`/`ok`/`check` | 本轮完成 |
| 数值表示 | `runtime.js` `Qty()` 提供原语；**存量字符串数值暂不强制迁移** | 原语完成，迁移随 P1 器材计算一起做 |

> 存量代码里大量数值是预格式化字符串（`'约 1344 光年'`）。强制全量迁移风险高于收益，
> 因此 `Qty` 先作为**新代码必须使用的原语**，旧数据在触碰时逐步迁移。
