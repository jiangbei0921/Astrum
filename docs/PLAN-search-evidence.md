# ASTRUM 检索与答案链路优化方案（第二阶段：待确认）

版本 1.0 · 2026-10-23
前置文档：`docs/AUDIT-search-evidence.md`（第一阶段问题定位）

---

## 一、总体思路

**不推翻现有架构，只把断掉的链路接上。**

项目已有的可靠基础：
- 本地星历复算（`core/astro.js`）—— 数值可复算，保持不动
- 133 条带出处的知识库（`data/knowledge.js`）—— 事实底座，保持不动
- 端点健康度/熔断/缓存（`core/sources.js`）—— 复用，不重写
- `trace` / `TASKS` / `HEALTH` 日志机制 —— 扩展，不新建

需要新建的只有一件事：**检索规划与证据管理**（`core/research.js`）。

保持不变的原则：
- 纯静态、零依赖、可双击运行
- 不放宽 CSP（新增域名逐条白名单）
- 星历与本地事实仍以本地为准，检索只作补充与佐证

### 阶段 B · P1 检索质量

| 项 | 修改位置 | 内容 | 预期效果 |
| --- | --- | --- | --- |
| **B1** | `sources.js` 新增 `searchMany(queries, opts)` | 多端点并行（端点内串行防限流），返回全部来源结果而非首个成功 | 一次检索可同时拿到百科+论文+影像，具备交叉验证前提 |
| **B2** | `sources.js` 各端点 `parse` | 采集 `date_created`/`publication_date`/`year`/`authors`/`doi`/`center`/`photographer`；新增 `sourceType` 字段 | 证据可追溯时间与出处类型 |
| **B2b** | `sources.js:454` `shortText` | 展示用 180 字不变；证据用 `excerpt` 放宽到 600 字 | 关键证据不被截断 |
| **B3** | `research.js` | 三层去重（URL / DOI / 标题指纹）；结构化排序（源类型匹配度 → 时间 → 词项覆盖） | 去掉重复，把最合适的证据排前面 |
| **B3b** | `app.js:2386` `filterRelevant` | 收紧为「词项覆盖率 ≥ 阈值」，无命中时**不再全放行**，改为标注「未找到相关结果」 | 无关结果不再冒充证据 |

排序不采用「域名白名单打分」这种单一评分，而是由
`sourceType 是否匹配子问题类型` + `是否有明确时间` + `标题词项覆盖率` 三项共同决定，
并把这三项写进 `evidence.reliability` 供用户查看。

### 阶段 C · P1 规划与多轮检索

| 项 | 内容 |
| --- | --- |
| **C1** | `Research.plan(question, intent, targets)`：按问题类型生成搜索计划 |

问题类型 → 检索策略（**简单问题不强行多轮**）：

| 问题类型 | 判定来源 | 策略 |
| --- | --- | --- |
| 基础科普 / 机制原理 | `intent = cosmos / knowledge-target` | 百科打底 + 论文补机制，2 个子问题 |
| 具体天体 | `intro-target` | 百科 + 天体数据 + 影像，1~2 轮 |
| 最新发现 | `nova` | 论文按时间倒序，强调 `published` |
| 天象 | `event` | 百科 + 机构发布 |
| 观测/器材/星图/今晚看什么 | `tonight / observe-target / photo-target / gear / chart` | **不检索**，纯本地计算（省配额） |
| 无法归类 | `unknown` | 检索 1 轮；有结果则基于证据作答，无结果如实说不知道 |

复杂问题拆解示例（「为什么超新星爆发能产生那么大的能量」）：

```
q1 类型与形成条件   → "core-collapse supernova progenitor"
q2 观测证据         → "supernova neutrino observation SN1987A"
q3 物理机制         → "neutrino-driven explosion mechanism energy"
q4 替代解释         → "magnetar vs neutrino driven supernova"
```

| 项 | 内容 |
| --- | --- |
| **C2** | 多轮迭代：从首轮结果提取锚点（任务名、仪器名、作者、天体编号），生成更具体的第二轮检索词 |

停止条件（全部可配）：

| 条件 | 默认值 |
| --- | --- |
| 最大轮数 | 2 |
| 单轮最多检索词 | 4 |
| 总调用预算 | 6 次 |
| 总时间预算 | 12s |
| 连续两轮无新增去重结果 | 立即停止 |
| 所有子问题已有证据覆盖 | 立即停止 |

每次停止都记录 `stopReason`，并在日志中可见。

### 阶段 D · P2 证据与引用

| 项 | 内容 |
| --- | --- |
| **D1** | 证据编号 `E1…En`，每条记录 `subQuestion` / `endpoint` / `query` / `fetchedAt`；答案中引用的证据可回指 |
| **D2** | `Research.verifyCitations(answer, evidence)`：<br>① 引用是否存在于本轮证据或本地知识库<br>② 引用是否有明确出处（URL/DOI）<br>③ 不同来源对同一量的数值是否冲突 |
| **D2b** | 无法判定为充分支持的证据标记「待核验」，**不显示为已证实**；冲突时并列展示双方数值与出处，不擅自择一 |

冲突检测范围：同一子问题下、同一物理量（质量/距离/年龄/温度）的数值差异超过 10% 时提示。

## 四、影响评估

| 维度 | 评估 |
| --- | --- |
| 包体积 | `research.js` 约 700 行，单文件版预计 +25~35 KB（当前 793 KB） |
| 依赖 | **不新增任何依赖**，不新增域名（复用现有 5 个端点） |
| 兼容性 | `Sources.search()` 保留为兼容包装，旧的调用点不会立刻失效 |
| 离线可用性 | 检索失败时行为不变：回退本地索引并标注，不阻塞答案 |
| 调用成本 | 阶段 C 的预算控制把每次提问的检索次数上限限定为 6 次；观测类问题 0 次 |
| 破坏风险 | 主要风险在 `app.js` 的答案组装。缓解：证据作为**新增章节**插入，不改动既有 `verdict`/`evidence`/`observe` 章节的生成逻辑 |

## 五、测试计划

### 5.1 离线（mock，确定性，可长期跑）

`tools/research-test.js` 内置 fixture，不联网：

| 用例 | 断言 |
| --- | --- |
| 查询词传递 | 传入 `X`，端点收到的 query 必须为 `X`（**直接锁死 P0-1**） |
| 空查询防御 | `enQueryFor('')` 不得返回任何星名 |
| 简单科普不多轮 | 「今晚看什么」类问题 `searchCalls === 0` |
| 复杂问题拆解 | 机制类问题产出 ≥ 2 个子问题、≥ 2 个检索词 |
| 去重 | 同 URL / 同 DOI / 同标题只保留一条，且保留原始 `url` 与 `endpoint` |
| 来源冲突 | 两个源数值差 > 10% 时 `conflicts.length > 0` 且双方数值都保留 |
| 引用校验 | 伪造引用 → 判定不可验证；真实引用 → 通过 |
| 无结果不编造 | 全端点空 → 答案出现「未找到」边界声明，`meta.confidence` 不升高 |
| 超时处理 | mock 超时 → 走降级，`stopReason` 为 `timeout` |
| 时间字段不混淆 | `published`（论文发表）与 `fetchedAt`（抓取）分开，展示用前者 |
| 预算上限 | 构造 20 个子问题，实际调用不超过 6 次 |
| 问题类型 → 答案结构 | 科普 / 天体 / 前沿研究 / 最新发现 各产出一套结构 |

### 5.2 在线（真实联网，单独标记）

```bash
node tools/research-test.js --online
```

覆盖：真实端点可达性、真实检索词效果（「黑洞」应返回黑洞相关）、字段采集完整性。

**输出中会明确区分**「模拟数据通过」与「真实外部数据通过」，不混为一谈。

### 5.3 回归

`tools/selftest.js` 增加：
- `Sources.search` 传入 query 后请求 URL 含该 query
- 检索证据章节存在且条目数 > 0
- 引用校验章节存在

## 七、明确不做的事

| 事项 | 原因 |
| --- | --- |
| 引入向量检索 / embedding | 需要新依赖与索引构建，破坏零依赖定位 |
| 引入新的付费数据源 | 无密钥，且需用户承担成本 |
| 放宽 CSP | 安全边界不因功能妥协 |
| 让模型自由生成天文数值 | 与项目「可追溯」契约冲突；数值仍以本地星历为准 |
| 用单一「域名权威分」判断可信度 | 按你的要求，改为类型+时间+词项覆盖+多源佐证综合判断 |

## 八、已知能力缺口（不在本次范围，但需说明）

现有 5 个端点无法覆盖以下需求，**不假设项目已具备**：

| 缺口 | 影响 | 可行的接入方式 |
| --- | --- | --- |
| 彗星/小行星精确轨道 | 无法回答「某彗星当前亮度」 | MPC / JPL SBDB（需确认 CORS） |
| 系外行星参数 | 无法回答「某系外行星半径」 | NASA Exoplanet Archive TAP（需确认 CORS） |
| 预印本（arXiv） | 「最新发现」缺少最快来源 | arXiv API 不返回 CORS 头，需代理 |
| 实时云量 / 空间天气 | 无法给「今晚实际能否观测」 | 需气象与 NOAA SWPC 接口 |
| 天体专业数据库（SIMBAD/NED） | 参数查询精度有限 | 需确认 CORS 与限流 |

本次不接入，仅在文档与界面提示中如实标注，避免用户误以为已支持。
