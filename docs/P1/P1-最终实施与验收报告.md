## 3. 关键实现说明

### 3.1 双层校验

`ResearchStore 方法 → Security.ensureSession → Security.authorize → 记录 profileId/projectId 二次校验 → AuditLog`。
- 未绑定 projectId 的 principal 由存储层绑定到目标课题；已绑定且不匹配返回 `PROJECT_MISMATCH`。
- 跨档案统一返回「不存在或不属于当前档案」，不泄露存在性。
- `memory.approve` 仅用户可用；模型层与存储层各判一次 `APPROVER_NOT_USER`。

### 3.2 召回

`verified` 过滤 → 当前 Thread 排除 → 实体/类型/时间/来源可信加权 → fingerprint 与 claimIds 去重 → 条数与字符双预算（默认 6 条 / 2000 字、证据 8 条）→ 审计。
失败返回 `{ok:false, denied, memories:[]}`，不回退全库。UI 通过 `setPending` 登记召回 Promise，编排器执行 compose 前最多等待 3 秒，超时/异常均放行。

### 3.3 检查点与恢复

写入时机：PLAN 后、critical 步骤 ok 后、PROGRESS 后（含再次 PROGRESS/Research Loop 追加）。字段含 `checkpointId/at/phase/stepId/inputHash/stateHash/budgetUsed/projectId/taskStatus/version/memoryIds/evidenceIds/claimIds`。写入失败不阻断执行。
恢复前重校验：所有权、会话、`schemaVersion=1`、课题存在且非 archived/deleted；running 步骤重置为 pending；已 ok 步骤不重复执行。

### 3.4 导入导出

- 导出 `astrum.project/1`，含 project/memories/evidence/claims/memoryEvents/threads/checkpoints/manifest。
- 导入：尺寸（≤10MB）、schema、原型污染、关联引用预校验全部先于写入；ID 全量重映射（project/evidence/claims/memories），Claim.support/contradict 与记忆 source.refs 同步重映射；文件内 verified/archived/superseded 一律落为 proposed；写入异常按逆序清理本批记录。
