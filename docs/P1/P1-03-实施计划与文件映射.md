# ASTRUM P1 实施计划与文件映射

> 阶段：P1 阶段 A（设计，不实施）
> 审批范围：本文件列出的「新增 / 修改」清单即阶段 B 的授权边界；清单外的文件不得改动。
> 顺序依据：任务书 §11.2，P1-01 → P1-06 → 全量回归。

---

## 1. 总体策略

1. **只做加法**：新增 5 个模块，扩展 9 个既有模块；不重写 Orchestrator、Agent 架构、Kepler、Evidence/Claim 基础契约。
2. **不新增依赖、不引入后端、不引入向量库、不改构建**。
3. **存储分库不分版本**：新课题库独立；任务库/线程库不加版本号，靠可选字段兼容。
4. **权限先于功能**：每个模块先接 `Security.authorize` 与存储层 owner 校验，再接 UI。
5. **单模块可回滚**：新增模块不被 `index.html` 加载即完全回退；扩展字段全部可空。

## 3. 任务拆分与依赖顺序

### P1-01 建立 ResearchProject（依赖：P0）

| 步骤 | 文件 | 内容 |
|---|---|---|
| 1 | `project.js` | 模型、校验、状态机 |
| 2 | `research-store.js` | 建库、project CRUD、owner 校验、列表 |
| 3 | `thread.js` + `app.js` | 新建 Thread 时带 projectId |
| 4 | `control.js` + `task-store.js` | 任务带 projectId，按课题过滤 |
| 5 | `project-ui.js` | 创建/编辑/暂停/归档/删除确认 |
| 6 | `security.js` | `project.*` 置真 |

**验收**：同 Profile 多课题；跨 Profile 不可见；跨课题不可见；状态流转正确；刷新后仍在；归档/恢复；非法操作拒绝。

### P1-02 建立 ResearchMemory（依赖 P1-01）

| 步骤 | 文件 | 内容 |
|---|---|---|
| 1 | `memory.js` | 10 类记忆、状态机、校验、fingerprint |
| 2 | `research-store.js` | memory CRUD、状态转换、事件记录 |
| 3 | `research.js` | 从研究结果生成候选（只 draft/proposed） |
| 4 | `project-ui.js` | 候选列表、详情、审核（通过/拒绝/编辑） |
| 5 | `security.js` | `memory.propose/approve/update` |

**验收**：候选与正式分离；Agent 不能 verified；审核留痕；版本/取代；来源可追溯；证据缺失不得 verified。

### P1-03 Evidence / Claims 关联（依赖 P1-02）

| 步骤 | 文件 | 内容 |
|---|---|---|
| 1 | `memory.js` | 引用完整性校验 |
| 2 | `research-store.js` | `verifyProject`、关联查询 |
| 3 | `project-ui.js` | 记忆详情展示 Claim→Evidence→Source |

**验收**：任一 verified 记忆可查来源与支持证据；缺失证据降级；冲突可追踪；不伪造 Evidence。

### P1-04 跨 Thread 召回（依赖 P1-03）

| 步骤 | 文件 | 内容 |
|---|---|---|
| 1 | `research-context.js` | 召回器（权限→检索→过滤→排序→去重→预算→审计） |
| 2 | `control.js` / `orchestrator.js` | 将 contextBundle 注入执行 |
| 3 | `app.js` | 切换课题/Thread 时触发召回 |
| 4 | `security.js` | `memory.read` 按角色校验 |

**验收**：Thread A 的 verified 结论可在 Thread B 召回；不同 Project 不混入；未审核不进入；超预算截断。

### P1-05 TaskStore 检查点与恢复（依赖 P1-01、P1-04）

| 步骤 | 文件 | 内容 |
|---|---|---|
| 1 | `task.js` | `addCheckpoint`，含 projectId/memoryIds/evidenceIds/claimIds |
| 2 | `control.js` | PLAN/critical step/PROGRESS 后写检查点；恢复前校验课题与版本 |
| 3 | `task-store.js` | `listByProject` |
| 4 | `project-ui.js` | 课题内未完成任务列表与恢复 |

**验收**：关页重开可恢复；恢复不跨 Profile/Project；已完成非幂等步骤不重复；权限变化拒绝；版本不兼容提示。

### P1-06 导入导出与迁移（依赖 P1-01~05）

| 步骤 | 文件 | 内容 |
|---|---|---|
| 1 | `research-store.js` | `exportProject/importProject`、Schema、ID 映射、回滚 |
| 2 | `project-ui.js` | 导入导出入口与结果提示 |
| 3 | 测试 | 空/旧/损坏/重复 ID/非法 JSON/关联缺失 |

**验收**：导出再导入关系完整；非法文件不破坏现有数据；导入记忆重新审核。

|---|---|

## 7. 实施顺序的关键决策

1. **先权限后功能**：`security.js` 能力变更放在 P1-01 第一步，避免先做出无门禁的 CRUD。
2. **存储先于 UI**：`research-store.js` 完成并通过单测后再接 UI，避免 UI 直接摸 IndexedDB。
3. **召回在记忆之后**：没有 verified 记忆时召回器无意义。
4. **检查点最后做**：依赖课题与召回字段稳定，避免 checkpoint 结构反复改。
5. **导入导出最后做**：需要所有实体字段定稿，否则 Schema 反复变。
