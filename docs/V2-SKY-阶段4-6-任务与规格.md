## 阶段 4 · 行星视觉增强

### 4.1 目标

让行星/月球在星图中的外观接近「小型望远镜目视 + 摄影折中」的真实观感，同时不牺牲现有性能与命中语义。

### 4.2 现状与问题

| 现状 | 位置 | 问题 |
|---|---|---|
| 球体 + 径向渐变 + 固定光照方向 | `core/sky-renderer.js` `bodyLayer()` | 光照方向取「朝太阳」但未考虑相位角，内行星恒为近满相 |
| 木星条纹为三条固定矩形 | 同上 | 不随自转/视场变化，放大后明显假 |
| 土星环为固定倾角 `-0.38` | 同上 | 与真实环倾角（B 角）无关 |
| 月球相位由独立 `miniMoon` 绘制 | 同上 | 与星图中的月球尺寸/光照不联动 |
| 视觉参数集中在 `core/planet-visuals.js` | `PLANET_VISUALS` | 只有 scale/color/glow，无相位/环倾角 |

### 4.3 范围（做）

1. **相位照明**：按 `太阳-行星-地球` 几何计算相位角，行星显示为相应亏凸/弦月形态；月球复用同一套计算。
2. **土星环倾角**：由环平面与视线夹角计算，随日期缓慢变化；不再用固定 `-0.38`。
3. **木星/火星表面细节改为程序化纹理**：离屏 canvas 生成一次（条纹/极冠），按视半径缩放绘制，不再用固定矩形。
4. **行星标注补充**：标注行可显示「相位 %」或「视直径」，默认关闭，由设置项控制。
5. `PlanetVisuals` 对外接口扩展：新增 `phaseAngle()`、`ringTilt()`、`diskTexture()`，保持旧字段兼容。

### 4.4 不做

- 不做真实贴图（不下载 NASA 行星纹理，避免体积与许可问题）
- 不做行星表面地貌还原
- 不改 `BODY_INFO` 的 scale 语义（仍非真实角直径）

### 4.5 验收标准

| 编号 | 标准 |
|---|---|
| P4-1 | 金星在「东大距」与「上合」两种几何下形态明显不同（相位角差 > 60°） |
| P4-2 | 土星环倾角在 2026 与 2032 两个日期相差 > 5° |
| P4-3 | 行星命中区半径与既有 `Math.max(r*1.35, 14*k)` 不变，点击行为一致 |
| P4-4 | 新增离屏纹理创建次数 ≤ 每行星 1 次（`PlanetVisuals.summary()` 可读） |
| P4-5 | 既有 7 套测试全绿；星图整帧 JS 耗时增幅 ≤ 15% |

### 4.6 涉及文件

`core/planet-visuals.js`（扩展）、`core/sky-renderer.js`（`bodyLayer`）、`core/astro.js`（只读调用，不改）、`tools/v2-sky-04-test.js`（新增）

### 4.7 风险

- 相位计算需除地球外的日心坐标，若 `Astro.planets()` 不提供日心距，需在 `planet-visuals` 内按轨道要素近似，必须标注「近似」
- 离屏 canvas 在 `file://` 下正常，但 Safari 旧版可能不支持 `OffscreenCanvas`，需用普通 canvas 兜底

## 阶段 5 · 地平线升级

### 5.1 目标

让地平线与地面更接近真实观测：正确处理遮挡、地形轮廓示意、方位刻度与「地平线下」提示。

### 5.2 现状与问题

| 现状 | 位置 | 问题 |
|---|---|---|
| 地平线为下方半圆填充 + 固定刻度 | `sky-renderer.js` `horizonAndGround()` | 无地形起伏；全屏视图中地面覆盖过大时可能压住低空银河 |
| 方位标注为固定 8 向 | `directionLabels()` | 无 10° 细刻度；yaw 变化时标签位置固定不跟随 |
| 地平线以下天体用虚线环标记 | `bodyLayer()` | 与地面填充叠加时对比度不足 |

### 5.3 范围（做）

1. **地平线遮挡判定统一**：所有图层（银河背景、L1 星场、DSO、星座线、行星）在 `alt < 0` 时一律不绘制；当前银河背景已按 `Rmax` 裁剪，需补「alt<0 区域填地面色」而非透明。
2. **方位刻度**：每 10° 一条细刻度、每 30° 一条主刻度并标 N/E/S/W/NE…；随 `yaw` 实时重算。
3. **地形轮廓示意**：可选的「低山轮廓」开关（默认关闭），用固定伪随机轮廓模拟 +2°~+6° 遮挡，仅视觉示意，不参与天文计算。
4. **地平线以下提示**：天体在 `alt ∈ (-6°, 0°)` 时用更明显的虚线 + 「已落下」标注。

### 5.4 不做

- 不接入真实 DEM 地形数据
- 不做大气折射修正（`alt` 仍为几何高度）
- 不改 `Astro.altAz`

### 5.5 验收标准

| 编号 | 标准 |
|---|---|
| P5-1 | 银心 `alt < 0` 时画布中不出现银河亮块（像素采样验证） |
| P5-2 | 方位刻度在 yaw=0/90/180/270 四方向与 `#vwVal` 一致，误差 ≤ 1° |
| P5-3 | 地形开关默认关闭，开启后只影响视觉，不影响任何命中坐标 |
| P5-4 | 关闭 `horizon` 图层后，地面、刻度、方位标注全部消失，其余图层不受影响 |
| P5-5 | 既有测试全绿；B4.2 亮度探针位置若落在 `alt<0`，需改为 `alt>5°` 并说明理由（不得放宽阈值） |

### 5.6 涉及文件

`core/sky-renderer.js`（`horizonAndGround` / `directionLabels`）、`core/sky-layers.js`（可选新增 `terrain` 键，需评估是否破坏 7 键默认）、`tools/v2-sky-05-test.js`（新增）

### 5.7 风险

- 新增图层键会改变 `SkyLayers.ORDER` 长度，阶段 1 的 L1.1 断言（7 键）需同步；属**增强断言**而非弱化
- 「alt<0 填地面色」会改变背景合成取样，可能影响 B4.2，需要先做只读探针评估

## 阶段 6 · 专业工作空间

### 6.1 目标

把「观测台」从信息面板升级为可保存、可复用的观测工作空间：多套观测配置、观测清单与计划单联动、可导出可分享。

### 6.2 现状与问题

| 现状 | 位置 | 问题 |
|---|---|---|
| 观测上下文（日期/时刻/地点/器材）只有一套 | `#ctxDate` / `#ctxTime` / `#ctxPlace` / `#ctxGear` | 换地点要重新输入，无法保存常用组合 |
| 观测清单只存名称与基本字段 | `plan` + `localStorage` | 不记录当时的 FOV/方向/时间，无法复现 |
| 计划单导出为文本 | `exportPlan()` | 不含坐标与时间窗口，无法直接用于望远镜 |
| 两个导出按钮（配置 / 计划单）分离 | 设置 → 数据与档案 | 概念重叠 |

### 6.3 范围（做）

1. **观测配置（Workspace）**：保存/切换/重命名/删除多套「地点 + 器材 + 日期偏移 + 默认 FOV/方向」；存 `localStorage`，与档案（Profile）解耦。
2. **清单可复现**：加入清单时记录当时的 `jd/lat/lon/fov/yaw/alt`，清单项可「回到当时视角」。
3. **计划单导出升级**：文本 + CSV 两种，字段含目标、RA/Dec、最佳时间窗、方位/高度、器材。
4. **导出入口合并**：设置中把「导出配置」「导出计划单」归入同一「导出」分类，保留原有能力。

### 6.4 不做

- 不做云端同步
- 不做多人协作
- 不改 `Profile` 的语义（档案仍管对话与语体）

### 6.5 验收标准

| 编号 | 标准 |
|---|---|
| P6-1 | 可保存 ≥3 套工作空间，切换后观测台控件与星图视角同步变化 |
| P6-2 | 刷新页面后工作空间仍存在，且不覆盖用户原有 `astrum.*` 键 |
| P6-3 | 清单项「回到当时视角」后 `#vwVal` 与记录值误差 ≤ 1° |
| P6-4 | CSV 导出可被 Excel 直接打开，字段数与表头一致 |
| P6-5 | 导出/导入配置的既有格式保持向后兼容（旧备份仍可导入） |
| P6-6 | 既有测试全绿；`selftest` 的配置往返断言不弱化 |

### 6.6 涉及文件

`core/app.js`（观测台与设置）、`index.html`（工作空间选择器）、`assets/app.css`、`tools/v2-sky-06-test.js`（新增）、`docs/CONTRACTS.md`（新增存储键约定）

### 6.7 风险

- 新增 `localStorage` 键需与既有 `astrum.*` 命名空间隔离，避免导入旧备份时冲突
- CSV 导出需处理中文与逗号转义

## 共同验收（三阶段任一完成时都必须满足）

1. `file://` 双击可打开，银河与星场正常；
2. `astrum-standalone.html` 重建成功且体积增幅 ≤ 10%；
3. `selftest` 的 CSP 违规次数为 0；
4. `v1-4-pages-test` 在 `/Astrum/` 子路径下 32/32；
5. 不新增任何网络请求；
6. 阶段 3A 的 A–G 验收项不得因新改动而退化为 `BLOCKED`。

---

## 建议实施顺序

```
阶段 5（地平线）→ 阶段 4（行星）→ 阶段 6（工作空间）
```

理由：阶段 5 涉及背景合成与 B4.2，越早做越容易发现与冻结基线的冲突；阶段 6 是纯交互与存储，风险最低但依赖前两者确定「视角」与「行星可见性」的语义。
