## 1. 启动条件判断

**具备启动条件，但有三个前置决策必须先由用户确认：**

1. **数据许可方向**：Gaia / Hipparcos / Tycho 全部为 `CC BY-NC 3.0 IGO`（非商业）。若 ASTRUM 未来可能商用，主数据集不能选它们。见《V2-SKY-阶段2-数据来源与许可.md》。
2. **是否允许新增静态数据文件与图片资源**：阶段 2 需要至少一个新数据文件；若采用银河图像方案，还需要一个图片资源，并需要扩展 `tools/build-standalone.js`（当前只内联 CSS/JS，不内联图片，见 `tools/build-standalone.js#L50-L60`）。
3. **是否允许在 `sky-viewmodel.js` 内实现 alt/az → 赤道坐标的逆变换**：银河背景按屏幕像素反投影需要该函数；`core/astro.js` 目前只有正向 `altAz()`（`core/astro.js#L234-L242`），没有逆函数。为避免修改天文核心，建议在视图模型内新增并做往返一致性测试。

阶段 1 的改动仍在工作区未提交：`core/app.js`、`index.html`、`core/sky-*.js`、`tools/v2-sky-01-*.js`。阶段 2 编码必须在其之上继续，不得回退或覆盖。

### 2.1 恒星进入星图的真实调用链

```
data/catalog.js CATALOG.stars
   └─ SkyVM.model()            core/sky-viewmodel.js#L89-L93   A.altAz 逐星算 az/alt，剔除 alt<-1
        └─ SkyVM.build()       core/sky-viewmodel.js#L272-L295 投影 + starVisual 计算 size/alpha/bucket
             ├─ vm.stars[]     { key,cn,en,bayer,con,ra,dec,az,alt,size,alpha,bucket,x,y,raw }
             └─ SkyRender.draw() core/sky-renderer.js#L609-L634
                  ├─ starField()   #L73-L100   背景程序化星场（独立于 CAT.stars）
                  ├─ stars()       #L105-L140  5 个亮度桶批量 Path2D
                  └─ labels()      #L395-L462  亮星星名与星座名
```

当前视觉映射（`core/sky-viewmodel.js#L186-L196`）：

- `size = max(1.0*k, (4.9 - (mag+1.5)*0.56) * k)`：视星等的**线性**映射。
- `alpha = (mag<1?1:mag<2?0.9:mag<3?0.68:0.42) * (alt<8 ? 0.6+alt/16 : 1)`：分段常数 + 低空衰减。
- 颜色固定为冷白 `rgba(226,234,248,α)`（`core/sky-renderer.js#L128-L134`），**无颜色信息**。
- 命中区：仅当 `alt>0 && size>1.9k` 才创建（`core/sky-renderer.js#L117-L124`）；命中数据是原始 `CAT.stars` 对象。
- 标签：detail 模式下 `mag<3.6 && alt>4` 才显示（`core/sky-renderer.js#L444-L448`）。

### 2.2 星表被其他业务模块消费的位置（改动必须兼容）

| 位置 | 用途 | 对星表的依赖 |
| --- | --- | --- |
| `core/agents.js#L314-L317` | 构建问答别名索引 | `k/en/cn/ra/dec/mag/con` |
| `core/agents.js#L542-L551` | 星座定位取最亮成员 | `lines` + `k/mag/ra/dec` |
| `core/agents.js#L1250-L1251` | 知识条目按中文名定位恒星 | `cn/ra/dec/mag` |
| `core/agents.js#L1485-L1490` | 今晚候选星座锚点 | `lines` + `mag` |
| `core/agents.js#L2646-L2655` | “附近的亮星”建议 | `mag<=2.6` + `A.sep` |
| `core/sources.js#L1463-L1466` | 中文名 → 英文名 | `cn/en` |
| `core/registry.js#L243-L250` | 星座/条目定位 | `lines` + `cn/ra/dec` |
| `core/app.js#L33` | 中英文显示名映射 | `cn/en` |
| `core/app.js#L2593-L2602` | 星表面板星座行 | `lines` + `k/mag/ra/dec` |

**结论**：`CAT.stars` 是业务身份表，不只是绘制数据。直接把它扩到数万颗会改变 `nearestBrightStar()` 的结果、别名索引规模与遍历成本。阶段 2 必须采用**独立视觉星表 + 保持 `CAT.stars` 132 条不变**的方案。

### 2.3 当前缺陷（按严重度）

1. **数据量不足**：132 颗在 30° 视场下只显示 2 颗（阶段 1 测试 L5.4 实测 `small=2`），远低于真实星空密度；缩小视场不是“看得更细”，而是“几乎空白”。
2. **无颜色**：无法表现蓝白/黄/橙/红恒星，违背“由真实数据驱动颜色”的目标。
3. **亮度映射失真**：线性星等公式与固定 alpha 桶，亮星与暗星层次不真实；无亮星光芒层。
4. **无数据溯源**：无逐星 source ID、无版本、无许可文件；`cn` 缺失 19 条。
5. **无自行/视差/光谱**：无法做长期位置修正，也无法在缺少 B-V 时用光谱型近似。
6. **无 LOD**：任何视场都绘制同一份 132 颗，缩小视场时没有更密的星场可显示。
7. **标签依赖星等阈值**：星等扩充后若沿用 `mag<3.6` 会一次性显示过多标签。

## 3. 当前银河背景审计

| 审计项目 | 当前情况 |
| --- | --- |
| 银河带 | 3 条，`b=0` 固定银纬，l 从 0 到 360 步长 2°，每条 181 个采样点（`core/sky-viewmodel.js#L65-L72`） |
| 银道→赤道转换 | `galToEq(l,b)`（`core/sky-viewmodel.js#L42-L54`），使用 IAU 1958 常数 aG=192.85948°、dG=27.12825°、lN=122.93192° |
| 背景星场 | 2400 个程序化随机点，`rnd()` 线性同余；银纬集中在 ±11°，34% 扩散到 ±77.5°；只保留 `alt>=0.5`；本次审计实测 1157 点（`core/sky-viewmodel.js#L73-L87`） |
| 时间/地点联动 | 正确：所有点都经 `A.altAz(…, jd, lat, lon)`，随 `(jd,lat,lon)` 缓存键变化 |
| 投影一致性 | 正确：使用同一 `proj(az,alt)` 鱼眼投影（`core/sky-viewmodel.js#L137-L183`） |
| 是否固定在屏幕 | 否；没有截图/贴图，全部按天球坐标投影 |
| 绘制 | 银河 3 条带用 `lighter` 描边（`core/sky-renderer.js#L50-L69`）；星场 6 个亮度桶 Path2D（`#L73-L100`） |
| 图层关闭 | 有效：`layers.milkyWay` 控制银河，`layers.stars` 同时控制星场与恒星（`core/sky-renderer.js#L621-L624`） |
| 命中影响 | 无：银河与星场不创建任何 hit；命中只来自恒星/DSO/天体（`core/sky-renderer.js#L105-L140`、`#L143-L160`、`#L238-L284`） |
| 视场裁剪 | 银河保留 `null` 断点；星场按 ±20px 视口裁剪；本次 145° 视场实测仅 299 个可见星场点 |
| 数据真实性 | **无真实数据**：3 条几何带 + 随机点，属于装饰性示意 |

### 3.1 视觉缺陷

1. 银河只有 3 条等宽光带，没有核球、旋臂、尘埃带、亮度梯度。
2. 随机星场不服从真实恒星密度，亮星附近与银心方向的密度关系是假的。
3. 星场颜色固定冷白，与恒星颜色无关。
4. 大视场下背景偏空（145° 仅 299 点），小视场下又完全依赖 132 颗恒星。
5. 无 LOD，低性能设备没有降级路径（只有 `interactive` 时把星场从全量降到 600）。

### 3.2 坐标一致性现状

- `galToEq` 与 IAU 1958 定义一致；以当前常数计算：
  - `l=0,b=0` → RA 17.76033h / Dec −28.9362°（266.4050°, −28.9362°）
  - `l=180,b=0` → RA 05.76033h / Dec +28.9362°
  - `l=0,b=+90` → RA 12.85730h / Dec +27.12825°（银北极）
  - `l=0,b=−90` → RA 00.85730h / Dec −27.12825°
  - `l=90,b=0` → RA 21.20029h / Dec +48.3296°
- 注意：`l=0,b=0` 是 IAU 银心方向，**不是 Sgr A\***（相差约 0.07°）。测试容差必须按 IAU 定义设定，不能拿 Sgr A* 当精确等号。

## 4. 阶段 1 架构是否足以支撑阶段 2

| 能力 | 结论 | 依据 |
| --- | --- | --- |
| 数据与绘制分离 | 足够 | 视图模型产出 `vm.stars/vm.dust/vm.milky`，渲染器只消费（`core/sky-viewmodel.js#L204-L399`、`core/sky-renderer.js#L609-L634`） |
| 图层开关 | 足够，无需新增键 | `stars/milkyWay` 已覆盖本阶段两个对象（`core/sky-layers.js#L13-L20`） |
| 缓存 | 需扩展 | 现有单条 `(jd,lat,lon)` 缓存（`sky-viewmodel.js#L57-L61`）可继续用；银河图像需要新增屏幕栅格缓存 |
| 命中测试 | 足够，但需明确额外恒星是否可点 | 命中由渲染器唯一生产；建议新增视觉恒星不进入 `_hits`，保持旧语义 |
| 逆投影 | **缺** | `core/astro.js` 无 alt/az→ra/dec；银河像素采样需要新增（不改 astro.js） |

## 5. 性能现状与规模估算

阶段 1 实测（同机 Node，1600×900）：

- 冷启动 `model()`：9.94 ms；`build()` 平均 0.43 ms、p95 0.70 ms（132 星 + 1157 星场点）。
- 浏览器 headless 的 `perf().sky.avg` 受虚拟时钟冻结影响，不能作为可靠基线。

阶段 2 规模估算（Node，预热后 5 次中位数，`tools` 临时脚本实测后已删除）：

| 操作 | 9,000 颗 | 40,000 颗 |
| --- | --- | --- |
| 鱼眼投影 `proj()` | 1.49 ms | 6.26 ms |
| `A.altAz()`（时刻/地点变化时） | 1.85 ms | 8.35 ms |

含义：

- 9k（BSC5 规模）每帧投影约 +1.5 ms，可接受。
- 40k（Hipparcos/Tycho 子集）每帧投影约 +6.3 ms，接近 60fps 预算上限；必须做视场锥裁剪、按像素密度截断或相机桶缓存，否则拖动会掉帧。
- alt/az 只在时间/地点变化时算，8.35 ms 可接受，但会放大“改时间”的卡顿，需要放到 `requestIdleCallback` 或做增量。

## 6. 兼容性与回归风险

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 扩大 `CAT.stars` 改变业务结果 | `nearestBrightStar`、别名索引、星座锚点都会变 | 视觉星表独立文件，`CAT.stars` 保持 132 |
| 新恒星进入 `_hits` | 详情卡字段不足（无中文名、无 con），会显示空白 | 额外恒星不创建 hit；仅 L0 可点 |
| 颜色分桶增加绘制调用 | 原 5 桶变成 5×7 桶 | 上限 35 次 fill，实测后再调 |
| 银河图片加载失败 | `file://` / 单文件版 / 资源缺失 | 三级降级：图片 → 数据点场 → 现有程序化 |
| 图片破坏 standalone | 构建脚本不内联图片 | 单独任务扩展 `build-standalone.js`，并更新产物 |
| 新增脚本顺序 | 数据文件必须在 `sky-viewmodel.js` 前 | 固定加载顺序并写测试 |
| 逆变换精度 | alt/az→ra/dec 若写错，银河整体错位 | 与 `A.altAz` 做 1e-9 往返测试 + 参考点测试 |
| 新增数据文件体积 | 直接 JSON 会到 MB 级 | 打包为 base64 量化数组，控制在 ≤ 400 KB |
| 许可 | Gaia/Hipparcos/Tycho 均 NC | 编码前确认商用与否，见数据来源文档 |
