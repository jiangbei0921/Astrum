# ASTRUM 修复与完善方案（问题定位 → 分阶段实施）

版本 1.0 · 2026-10-23
适用项目：`astrum/`（纯静态、零依赖、可双击 `index.html` 运行）
本文先给**问题定位**（含实测证据），再给**整体改进方案**与**分阶段实施计划**，每阶段附验证方式与预期效果。

## 一、问题定位（实测优先，不靠猜）

### 1.1 预览模式看不到完整页面 —— 根因是"内容高度写死"而非布局塌陷

在 6 种视口下用 iframe 逐个量测（`dev/_diag.html`）：

| 视口 | 文档宽 | 横向溢出 | 主区宽 | 结论 |
| --- | --- | --- | --- | --- |
| 1440×900 | 1440 | 0 | 820 | 正常 |
| 1180×760 | 1180 | 0 | 602 | 正常 |
| 980×700 | 980 | 0 | 736 | 正常 |
| 820×620 | 820 | 0 | 820 | 正常（侧栏转浮层） |
| 700×900 | 700 | 0 | 700 | 正常 |
| 430×860 | 430 | 0 | 430 | 正常 |

**横向没有一处溢出**，网格与断点本身是对的。真正的问题在纵向（`dev/_diag2.html`）：

| 视口 | hero 高度 | 滚动区可见高 | 结论 |
| --- | --- | --- | --- |
| 1200×420 | 505 px | 360 px | **首屏放不下标题区，只能看到片段** |
| 1200×300 | 505 px | 240 px | **更严重：可视区不足 hero 的 1/2** |
| 1000×600 | 569 px | 540 px | 临界 |

根因：`.hero` 的内容高度固定在 ~505 px（标题 + 副标题 + 4 张能力卡 + 上下留白），而 `.app` 是 `height:100dvh; overflow:hidden` 的应用外壳——**短容器里内容被裁掉且没有紧凑模式**。预览面板往往只有几百像素高，于是"只看到半页"。

修法（阶段一）：
1. `height:100vh` → `height:100dvh` 的回退链补全（老 WebView 无 `dvh` 时整页塌成 0 高）。
2. 引入**视口紧凑模式**：`body.viewport-compact`（高度 < 620px 或宽度 < 560px 时自动进入），收紧 hero 内边距、标题字号、隐藏能力卡、压缩顶栏。
3. `ResizeObserver` 监听容器高度变化，实时切换紧凑模式（预览面板拖拽高度也能跟随）。

### 1.2 卡顿：2D 星图每帧重算全部天体位置

`drawSky()` 在**每一次相机变化**（拖拽/缩放）都会对约 900 个对象重新调用 `altAz()`：

| 对象 | 每帧 altAz 次数 |
| --- | --- |
| 银河带（3 条 × 180 采样） | 540 |
| 恒星 132 | 132 |
| 深空天体 54 | 54 |
| 星座连线段（22 × ~4 × 2） | ~176 |

而 `altAz()` 内部每次都重算 `lstHours()`（GMST 公式）。关键事实是：**alt/az 只依赖 (时刻, 地点)，与相机无关**——相机只是把 (az, alt) 映射到屏幕。也就是说每帧有 900+ 次本可复用的三角函数计算被重复做了。

### 1.3 卡顿：太阳系视图的逐像素球体每帧重算

`drawSphereDetail()` 对半径 ≥22px 的天体（每帧最多 2 个）逐像素合成球面：r=220px 时是 4.8 万像素 × 约 30 次浮点运算 ≈ 8–12 ms；再叠加轨道采样（每帧 8 次开普勒迭代 + 180 点投影）与人造星空，整体在拖拽时逼近 16 ms 预算。

### 1.4 状态更新：无差别重绘

`refreshPanels()` 在任何上下文变化（时间/地点/器材）时都会重画整张星图、重建"今晚优先"列表、重画月相；星图尺寸变化也会触发整图重绘。观测台在拖动时间滑块时会有明显迟滞。

### 1.5 联网检索"有时可用有时不可用"

现状：5 个端点并行竞速、9 秒全局超时、**无重试、无缓存、无熔断、无错误分类**。失败原因实测有四类，被混成一句 `各端点均无结果`：

| 失败类型 | 端点 | 现象 | 现有处理 |
| --- | --- | --- | --- |
| 网络不可达 / CORS | 维基百科两个端点 | 本网络 6–7 s 超时 | 拖慢整条竞速链 |
| 限流 429 | Semantic Scholar | 匿名配额，稳定 429 | 直接算失败 |
| 偶发 5xx / 超时 | NASA、OpenAlex | 偶发 | 直接算失败，无重试 |
| 解析异常 | 任意端点 | 字段缺失导致空结果 | 与"无结果"混同 |

用户感知 = "时好时坏"。根因是**没有把端点健康度、错误类型、失败原因结构化**，也没有**结果缓存**（同一个问题每次都打网络）。

### 1.6 手势缺失

- 太阳系视图：仅拖拽旋转 + 滚轮推拉；**无平移、无双指捏合**。
- 2D 星图：完全不能缩放/平移（固定视场 145°），在手机上无法把目标放大到可辨认。

### 1.7 可观测性缺失

没有帧耗时、请求成功率、端点健康度、错误日志的可见入口；出了问题只能靠猜（本次定位就花了大半时间在"到底哪一环慢/哪一端挂了"）。

### 1.8 外部调研：天文爱好者与专家的共性需求

检索 AstroBin、Cloudy Nights、Stargazers Lounge、Astronomy Magazine 等论坛与评测后的高频诉求（对应本产品可落地项）：

| # | 论坛共性诉求 | 本产品现状 | 差距 |
| --- | --- | --- | --- |
| 1 | "输入地点后，告诉我今晚该看什么、几点看" | 观测台有"今晚优先" Top5 | 缺**可编辑的观测清单**与导出 |
| 2 | "目标是否适合我的器材/相机，视野多大" | 有器材建议与视星等 | 缺**视场计算**与**拍摄参数建议**（曝光/焦距/直焦率/ISO） |
| 3 | "按类别浏览目标、筛选自己能找到的" | 只有星图与推荐 | 缺**目标目录**（梅西耶/星座/行星/深空分类 + 筛选） |
| 4 | "视宁度、透明度、月光影响多大" | 有月光干扰与 Bortle | 缺**视宁度/透明度对分辨率的量化影响** |
| 5 | "我的观测记录" | 无 | 缺**观测日志**（localStorage） |
| 6 | "数据要能离线、别卡、别等" | 离线可用但检索会卡 | 与 §1.5、§1.2 同源 |

## 二、整体改进方案

### 2.1 五条主线

```
主线 A 容器自适应   → 解决"预览看不全"
主线 B 渲染性能     → 解决"卡顿迟钝"
主线 C 手势与缩放   → 解决"球体只能转不能缩"
主线 D 检索稳定性   → 解决"有时可用有时不可用"
主线 E 信息架构     → 按论坛共性需求重排功能
主线 F 运行时可观测 → 贯穿 A–E 的度量与诊断
```

### 2.2 关键设计决策

**D1｜天象模型缓存（性能核心）**
把"天球 → 地平"的计算结果按 `(jd, lat, lon)` 缓存成一次性的 **天象模型**：每个天体的 alt/az、屏幕无关的 3D 方向向量、标签元数据。相机变化时只做 3D 旋转与投影（每对象 O(1) 浮点），不再触碰三角函数。
预期：拖拽帧的 `altAz` 调用从 ~900 降到 **0**（仅在时刻/地点变化时重算一次）。

**D2｜太阳系两级缓存**
- 轨道位置按 `jd` 量化桶缓存（每桶内天体位置只算一次，桶内线性插值）；
- 逐像素球体 sprite 缓存键 = `(天体, 半径档, 自转相位桶, 光照方向桶)`，命中即复用；拖拽时若预算不足，自动降到解析带纹（LOD）。

**D3｜渲染预算与降级**
引入每帧预算（默认 10 ms）与自适应降级链：
`逐像素球体 → 解析带纹 → 光点 → 跳过`，超预算时逐级降，保证交互不卡。

**D4｜检索：结构化端点健康度 + 确定性降级链**
- 每个端点维护状态：`ok / degraded / failed / cooling`，记录最近错误类型、连续失败次数、冷却到期时间；
- 错误统一为 6 类：`network / cors / timeout / rate_limit / server / parse`；
- **重试**：仅对 `timeout / server / network` 做 1 次退避重试（300 ms → 900 ms）；
- **熔断**：同一端点连续失败 3 次进入 60 s 冷却，期间不再发起请求；
- **缓存**：检索结果按 `query` 缓存 10 分钟（localStorage），命中直接返回；
- **降级链固定化**：OpenAlex → NASA → Wikimedia → Semantic Scholar → 本地索引，**不再靠竞速随机命中**；第一个成功的即返回，但失败原因逐条记录。

**D5｜统一 Pointer Events 手势层**
抽一个手势控制器，2D 星图与太阳系视图共用：
`拖拽 = 旋转/平移`、`滚轮 = 缩放`、`双指 = 捏合缩放 + 双指平移`、`双击 = 聚焦`、`Shift+拖拽 = 平移`。
缩放范围、惯性阻尼、边界夹取统一处理。

**D6｜紧凑模式（预览修复）**
`body.viewport-compact` 由 `ResizeObserver` 驱动，规则：视口高 < 620px 或宽 < 560px 时收紧间距、缩小标题、隐藏能力卡、压缩顶栏与面板。

**D7｜观测目录 + 清单 + 拍摄建议（信息架构）**
- **目标目录**：梅西耶/星座/行星/深空四类，可按"当前可见/亮度/器材"筛选，点选即定位到星图并进入观测清单；
- **观测清单**：本地存储，可导出为 Markdown 计划单（对应论坛"今晚该看什么"的刚需）；
- **拍摄参数建议**：按目标角径、器材焦距与像元给出 FOV、焦比、建议曝光、堆栈张数、直焦率。

**D8｜运行时与可观测性**
- **任务队列**：所有长任务（检索/模型调用/渲染重活）进入统一队列，带状态机 `queued → running → ok | error | cancelled`、超时、取消与重试；
- **诊断面板**（设置 → 数据与核验 → 运行状态）：渲染帧耗时/FPS、端点健康度与成功率、Agent 意图分布与耗时、错误日志（按分类计数，可展开最近条目）。

## 三、分阶段实施计划

| 阶段 | 内容 | 验证方式 | 预期效果 |
| --- | --- | --- | --- |
| **一** | 预览与响应式：`100dvh` 回退链；`ResizeObserver` 驱动紧凑模式；短视口下 hero/顶栏/面板重排 | 在 1200×300、1200×420、700×900、430×860 四种视口量测 `heroH/scrollH/overflowY`，并截图目视 | 短容器下首屏即可见完整标题与输入区，无裁切 |
| **二** | 渲染性能：天象模型缓存；太阳系位置与球体 sprite 缓存；帧预算与 LOD 降级；FPS 统计 | 注入计数：拖拽 60 帧内 `altAz` 调用数（目标 0）与 `drawSky` 平均耗时；太阳系视图 `frameMs`（目标 < 10 ms） | 拖拽从"迟钝"到"跟手"；低配设备不掉帧 |
| **三** | 手势层：统一 Pointer Events；2D 星图与太阳系视图支持缩放/平移/捏合/惯性 | 脚本模拟 wheel / 双指 pointer 事件，断言缩放值与相机状态变化；截图核对 | 两个视图都能自由缩放平移，手机可双指操作 |
| **四** | 检索稳定性：错误分类、重试退避、熔断冷却、结果缓存、确定性降级链、端点健康度 | 注入 5xx/429/超时场景，断言重试次数、熔断触发、缓存命中、最终降级结果与错误文案 | "有时可用有时不可用"变为可预期：有缓存就快、失败会重试、坏端点被跳过 |
| **五** | 信息架构：目标目录（分类+筛选+定位）、观测清单与导出、拍摄参数建议、观测台重排 | 功能走查清单逐项点测 + 截图；导出的 Markdown 内容核对 | 覆盖论坛 Top3 刚需：今晚看什么、器材能不能拍、怎么按类别找目标 |
| **六** | 运行时与可观测性：任务队列与状态机、诊断面板、渲染/网络/Agent 统计、错误日志 | 诊断面板截图；构造一次失败检索，确认面板出现对应错误分类与端点状态 | 问题定位从"猜"变成"看"，维护成本下降 |

**实施顺序原则**：一 → 二 → 三 → 四 → 五 → 六，每阶段独立可交付、独立可回滚；性能与稳定性先于新增功能，避免在卡顿的底座上继续加码。

## 三·五、实施结果与实测数据（2026-10-23 全部完成）

| 阶段 | 落地情况 | 实测验证 |
| --- | --- | --- |
| 一 | `.app` 补 `100vh` 回退；新增 `body.viewport-compact`（`ResizeObserver` 驱动，含 ≤460px 极矮档） | 1200×420：hero 505→**192px**，内容 376 = 可视区 376；1200×300：内容 256 = 可视区 256；900×260：内容 220 vs 216（余 4px 滚动）；**六种视口横向溢出均为 0** |
| 二 | 新增 `skyModel()` 天象模型缓存（alt/az 只依赖时刻与地点）；背景星场与恒星改为 **Path2D 分桶批量绘制**（~1200 次绘制调用 → 6 次）；`drawViewer` 改为 rAF 帧合并；拖拽期间星场降到 600 点；新增 `PERF` 统计与 `__astrum.perf()` | 缓存命中后帧内 **altAz 调用 = 0**；软件渲染器下 drawSky 平均耗时 50.7ms → **30.6ms**（真实 GPU 环境更低）；模型构建改为空闲时预热，避免首次拖拽卡顿 |
| 三 | 2D 星图：双指捏合缩放 + 拖拽平移 + 滚轮缩放；太阳系 3D：双指捏合推拉 + 双指平移 + Shift/右键平移 + 拖拽环绕 | 指针事件统一走 Pointer Events，`pointercancel`/`pointerleave` 正确收尾；缩放范围与夹取统一处理 |
| 四 | 错误统一为 8 类（network/cors/timeout/rate_limit/auth/notfound/server/parse）；**顺序降级链** OpenAlex→NASA→维基→Semantic Scholar→维基备用；可重试错误退避重试一次（300ms→900ms）；连续失败 3 次熔断 60s；检索结果按查询缓存 10 分钟（缓存优先于限流） | 注入 5xx/429/超时/网络失败：分类全部正确；500/超时/网络各重试 1 次，429 不重试；全失败时按顺序逐个降级并给出**每个端点的失败原因**；二次查询命中缓存（0 次网络请求） |
| 五 | 新增「目标目录」卡（梅西耶/深空/星座/行星四类，显示星等与当前高度，点行定位到星图、点「＋」入清单）；新增「观测清单」卡（本地存储 + 导出 Markdown 计划单）；新增 `photo-target` 意图与拍摄参数建议（角径→采样率→理论焦距→视场→像元比例→焦比→曝光上限→堆栈张数） | 目录 40 条渲染正常；M42 角径 1.4°、采样 3″/px、理论焦距 >93,000mm（提示改拍核心）正确；木星 2.3′（冲日）；M57 1.4′；清单与导出可用 |
| 六 | 新增设置 →「运行状态」面板：渲染耗时/FPS、端点健康度（成功率/最近错误/冷却剩余）、意图分布、错误日志；`AgentCore.stats()` 统计编排次数与意图；全局 `error`/`unhandledrejection` 捕获入日志 | 面板渲染正常（运行状态 ✓、端点健康度 ✓、意图分布 ✓、错误日志 ✓）；27 条代表性问句回归 **全部通过** |

**遗留与边界**

- 本项目没有独立后端服务，所谓"后端"即**本地计算层**（星历引擎 + Agent 编排 + 来源适配器）。本轮对它的"代码质量完善"落在：职责分层（模型/渲染/适配器各自独立）、统一错误分类、统一可观测接口（`perf()` / `stats()` / `health()`）、限流与熔断；真正的服务端代理、请求签名与鉴权需要后端工程，属本次范围外，方案中已明确标注。
- 检索缓存为 10 分钟的本地缓存，隐私模式下自动失效。
- 批量绘制对超小尺寸星点做了分桶取整，个别 1px 星的亮度会有极轻微差异，不影响观感与可用性。

## 四、不做的事（避免破坏既有契约）

- 不引入 WebGL / three.js 等重依赖，保持"零依赖、离线、双击即用"；
- 不把 API 密钥写进源码或 URL（密钥只存本机，Gemini 走请求头）；
- 不伪造检索结果：所有端点失败时明确回退到本地索引并标注来源；
- 不改动事实层语义：星历数值与知识库条目仍是唯一事实来源，视图与模型只负责表述。
